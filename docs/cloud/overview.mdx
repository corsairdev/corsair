Corsair Cloud runs the integration layer for you. Instead of building and
hosting a server that talks to Notion, Slack, GitHub, and the rest, you get a
project with its own hosted runtime and call any plugin operation over HTTP.

Nothing to deploy, no OAuth server to write, no tokens to store. You connect
your users' accounts once, then make calls.

## Before you start

Open your project's **Overview** page in the dashboard. You need two values from
it, and that is all:

| Value | Looks like | What it is |
| --- | --- | --- |
| **API key** | `ck_cloud_…` | A secret. Sent as a bearer token. Keep it on your server. |
| **URL** | `https://<vm>.corsair.cloud/<project>/api/corsair` | Your runtime's address. |

<Warning>
The API key is a server secret. Never put it in browser code or a mobile app you
ship. See [Server vs. browser](#server-vs-browser) for the safe browser path.
</Warning>

## Your first call

Install the client for your language and make one call. Every language uses the
same two values and the same request shape.

<CodeGroup>

```ts TypeScript
import { createCorsairCloud } from "corsair";

const corsair = createCorsairCloud({
  apiKey: process.env.CORSAIR_CLOUD_KEY!,
  url: process.env.CORSAIR_CLOUD_URL!,
});

const pages = await corsair.withTenant("acme").notion.api.pages.searchPage({});
```

```python Python
from corsair_cloud import CorsairCloud

corsair = CorsairCloud(api_key="ck_cloud_…", url="https://<vm>.corsair.cloud/<env>/api/corsair")

pages = corsair.with_tenant("acme").call("notion", "pages.searchPage", {})
```

```go Go
corsair := corsaircloud.New("ck_cloud_…", "https://<vm>.corsair.cloud/<env>/api/corsair")

raw, err := corsair.Tenant("acme").Call(ctx, "notion", "pages.searchPage", map[string]any{})
```

```swift Swift
let corsair = CorsairCloud(apiKey: "ck_cloud_…", url: URL(string: "https://<vm>.corsair.cloud/<env>/api/corsair")!)

let pages = try await corsair.tenant("acme").call("notion", "pages.searchPage", args: [:])
```

```bash curl
curl -X POST "$CORSAIR_CLOUD_URL/acme/notion/call/pages.searchPage" \
  -H "authorization: Bearer $CORSAIR_CLOUD_KEY" \
  -H "content-type: application/json" \
  -d '{"args":{}}'
```

</CodeGroup>

That call runs Notion's `pages.searchPage` operation as your user "acme" and
returns the result. Under the hood it is always one request:
`POST {url}/{tenant}/{plugin}/call/{op}` with a `{ "args": {...} }` body. The
language clients are thin wrappers over that one shape, so once you have seen the
curl you have seen all of them.

## What is a tenant?

A tenant is one of your users. `withTenant("acme")` (or `with_tenant`, `Tenant`,
`tenant`) picks which user a call acts as, so the call uses that user's connected
account. One runtime serves all your tenants at once. If you are building for a
single user, use one tenant id and forget about it.

## Connect a user's account

Before a tenant can call Notion, that tenant has to connect their Notion
account. Corsair Cloud runs the OAuth for you. Create a connect link and send
your user to it:

<CodeGroup>

```ts TypeScript
const link = await corsair.manage.connect.createLink({
  plugin: "notion",
  tenantId: "acme",
});
// send the user to link.connectUrl
```

```python Python
link = corsair.manage.create_connect_link("notion", "acme")
# send the user to link["connectUrl"]
```

</CodeGroup>

When the user finishes authorizing, the runtime stores their token (encrypted at
rest with a key Corsair holds, so raw provider tokens never sit in your
runtime's store). Check who is connected any time:

<CodeGroup>

```ts TypeScript
const status = await corsair.manage.connectionStatus.get({ tenantId: "acme" });
// { notion: "connected" }
```

```python Python
status = corsair.manage.connection_status("acme")
# {"notion": "connected"}
```

</CodeGroup>

## Server vs. browser

The runtime has one contract and two ways to reach it:

- **From a server or agent.** Use the client directly. It holds the API key and
  makes calls straight to the runtime. This is the path in every example above.
- **From a browser (React).** Browser code must never see the key. `CorsairProvider`
  runs in the browser and talks to a route in *your own* app that adds the bearer
  server-side. `corsair/cloud-proxy` builds that route for you:

<CloudProxyNext />

Then wrap your app in `CorsairProvider` and use `useCorsair()` to render the
connect flow and read connection state. The key stays on your server the whole
time.

## Get type hints for your calls (TypeScript)

`createCorsairCloud` takes no plugin list, because the plugins live on the
runtime. By default your calls are dynamic, so `corsair.withTenant(t).notion.api…`
is typed as `any`. To get autocomplete, run the CLI once:

```bash
pnpm corsair cloud pull
```

It reads the exact plugins and operations your runtime has, down to the scopes
you allowed, and writes a local `corsair-env.d.ts`. TypeScript picks those types
up automatically, so your calls autocomplete with no plugin import to maintain.
Coding agents can skip this and list operations with `pnpm corsair cloud list`.

## Where calls go

Your call goes straight to the runtime, not through the dashboard. The dashboard
creates and configures the runtime, then steps out of the request path. So a
plugin call is one hop out (your code to the runtime) and one hop on (the runtime
to the provider).
