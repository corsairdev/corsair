Corsair MCP lets an AI agent use the apps you've connected to Corsair. It can read your inbox, post in Slack, open a GitHub issue, search data Corsair has synced, or set up an automation that runs when something happens in one of your apps.

Every client uses the same address:

```
https://mcp.corsair.dev/mcp
```

You add it once, sign in to Corsair, and choose which of your links the client uses.

## Before you start

- A Corsair account. Sign up at [hub.corsair.dev](https://hub.corsair.dev) with Google, GitHub or an emailed sign-in link.
- Apps to use. You can connect them in Corsair first, or ask the agent to connect one later. It hands you a sign-in link for that app.

## How sign-in works

<Steps>
  <Step title="Add the address to your client">
    See [Add it to your client](#add-it-to-your-client) below.
  </Step>
  <Step title="Sign in to Corsair">
    The client opens Corsair in your browser.
  </Step>
  <Step title="Pick a link">
    A link is a set of your connected apps plus a [mode](#modes-and-approvals) that decides what the agent may do without asking. Pick an existing link or make a new one for this client. If you have no link yet, Corsair asks you to make one first.
  </Step>
  <Step title="Allow">
    The client gets the apps on that link and your email address. Nothing else on your account is shared.
  </Step>
</Steps>

One connection uses one link. To switch links, remove Corsair from the client, add it again and pick the other link. You can sign a client out of a link at any time from [hub.corsair.dev/me](https://hub.corsair.dev/me).

## Add it to your client

<Tabs>
  <Tab title="Claude">
    1. In Claude, open **Customize → Connectors → Add custom connector**.
    2. Name it Corsair, paste `https://mcp.corsair.dev/mcp` and add it.
    3. Select **Connect** and sign in to Corsair.

    On a Team or Enterprise plan, an owner adds connectors under Organization settings.
  </Tab>
  <Tab title="ChatGPT">
    1. In ChatGPT, add a custom MCP server and paste `https://mcp.corsair.dev/mcp`.
    2. Choose OAuth, then sign in to Corsair.

    On personal plans, ChatGPT currently uses only the read tools from a custom server, so Corsair can look things up but not make changes. Write tools such as `run_script` need a Business or Enterprise/Edu workspace, where an admin adds the server or gives you permission to. OpenAI's [guide to custom MCP servers](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) has the current rules.
  </Tab>
  <Tab title="Cursor">
    [Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=corsair&config=eyJ1cmwiOiJodHRwczovL21jcC5jb3JzYWlyLmRldi9tY3AifQ==), or add this to `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "corsair": { "url": "https://mcp.corsair.dev/mcp" }
      }
    }
    ```

    Cursor opens Corsair to sign in the first time it connects.
  </Tab>
  <Tab title="VS Code">

    ```json
      }
    }
    ```

    VS Code signs you in when it first connects.
  </Tab>
  <Tab title="Claude Code">

  </Tab>
  <Tab title="Codex">
    ```bash

    ```

    Codex usually opens Corsair to sign in as soon as you add it. If it says the server may or may not require login instead, or you need to sign in again later, run `codex mcp login corsair`.
  </Tab>
  <Tab title="Gemini CLI">
    ```bash

    ```

    Then run `/mcp auth corsair` to sign in.
  </Tab>
  <Tab title="Zed">

Any other client that supports remote MCP servers with OAuth sign-in works the same way.

<Note>
Some clients can't sign in to an MCP server, such as GitHub Copilot's coding agent. For those, use a link's own address with an API key. Open the link at [hub.corsair.dev/me](https://hub.corsair.dev/me) and follow the steps for your client there.
</Note>

## What the agent can do

| Tool | What it does | Type |
| --- | --- | --- |
| `list_integrations` | Lists the apps on this link, whether each is ready and which account it's signed in as, with the Corsair credits left and spent this month. Also checks whether Corsair can connect an app that isn't here yet | Read |
| `get_connect_link` | Returns the sign-in link for an app, adding the app first if it isn't here. Apps that run on Corsair's own account come back ready, with no link. Shows a [connect card](#cards) where the chat supports it | Write |
| `list_operations` | Shows what connected apps can do, with each action's risk and price. Searched by what you want to do, it returns the matching actions with the arguments they require | Read |
| `get_schema` | Shows the full arguments and return shape of one or more actions | Read |
| `search` | Searches everything Corsair has synced from your apps in one call, such as email, chat, issues, docs and calendar, and opens results in full | Read |
| `read_data` | Reads your apps live with a short script, for what `search` doesn't have or what must be current. It stops before any action that would change something | Read |
| `run_script` | Makes changes in your apps with a short script: send, create, update or delete | Sensitive write |
| `get_job` | Waits for a [long job](#long-jobs) a script started, such as a crawl or a document parse, and returns its result. Shows a [job card](#cards) where the chat supports it | Read |
| `view_routines` | Lists the routines on this link and their recent runs, or shows one run step by step with its error | Read |
| `update_routine` | Creates, changes, pauses or removes a routine, an automation that runs on an app event or a schedule. Describe it in plain words and Corsair writes and tests it | Sensitive write |
| `use_skill` | Loads one of your saved [skills](#skills) by name: its `SKILL.md`, then any file that comes with it | Read |
| `find_skill` | Searches the public [skills.sh](https://skills.sh) directory for skills you haven't saved yet. Shows a [skills card](#cards) where the chat supports it | Read |
| `save_skill` | Saves a skill for every agent on your link, from text, a GitHub URL or a skills.sh id. For a folder on your computer, such as `~/.claude/skills`, it gives you one command that uploads it | Write |
| `submit_feedback` | Sends the Corsair team a short note about Corsair itself. The agent sends one on its own when Corsair lacks an app or action you asked for, or when a reply says the fault is on Corsair's side, and tells you it did. For a wrong or confusing answer it asks you first. A note never includes your app data | Write |

Read tools never change anything in your apps. A read can still use [credits](#corsair-credits): `read_data` on an app that runs on Corsair's account is billed like any other call there. Write tools change only your Corsair setup, which you can undo, or send Corsair a note. Sensitive writes act in your apps, or set up a routine that will act later without asking, so a client should ask you before every call.

Scripts run in a sandbox that can only call your connected apps' actions. They have no network, filesystem or other system access, and the agent never sees your app credentials.

Not every link shows every tool. A link that isn't allowed to add apps has no `get_connect_link`, and a link that can't change routines has no `update_routine`. The skill tools come on the links you make at [hub.corsair.dev/me](https://hub.corsair.dev/me), and a link in Read mode has no `save_skill`.

`list_integrations`, `list_operations`, `get_schema`, `search`, `read_data`, `get_job`, `view_routines`, `use_skill` and `find_skill` are marked read-only, so most clients run them without asking. Clients usually ask you before running the others.

## Long jobs

Some actions start work that takes longer than one call: a site crawl, an async document parse, an agent run, an image or video prediction. Corsair notices when a script starts one and waits a few seconds. If the job finishes in that time, the result comes back with the script's. If not, the reply names the job, and the agent calls `get_job` to wait for it and get the result. The reply also gives a line to stop the job, where the app has one.

This works whether the app is connected with your own account or runs on Corsair's.

## Skills

A skill is a set of instructions an agent loads when a task calls for it: a `SKILL.md`, sometimes with files it refers to. Save a skill to Corsair once and every agent on the same link can use it, in whichever client it runs. Corsair keeps your skills in your own Corsair instance.

- **Use one.** Each agent sees the list of your skills when it connects, and loads one with `use_skill` when a task matches it. Clients that show MCP prompts also list each skill as a prompt.
- **Find one.** Ask the agent for a skill, such as "find me a skill for writing PR descriptions". It searches skills.sh with `find_skill`, and you pick the one to add.
- **Save one.** Ask the agent to save a skill you wrote together in the chat, or one from GitHub or skills.sh. Saving your own skill again under the same name adds a new version.
- **Upload your own.** To add the skills you keep on your computer, such as `~/.claude/skills`, ask the agent to upload the folder. It gives you one command to run in your terminal, and an agent with a shell, such as Claude Code, can run it for you. The files go straight to Corsair without passing through the chat. The command works for 10 minutes.

Corsair keeps only text files and removes any keys or tokens it finds when it saves a skill. A library holds up to 100 skills, and one skill up to 200 files and 8 MB.

See, switch off or roll back your skills at [hub.corsair.dev/me/skills](https://hub.corsair.dev/me/skills).

## Cards

In chats that show MCP Apps, such as Claude, three tools add a small card to the conversation:

- **Connect card** (`get_connect_link`): the app's logo, its name and one button. **Connect** opens the sign-in. The card shows when the sign-in has landed and offers **Continue** so the agent carries on. If the link runs out (after 10 minutes) it shows **New link** and gets a fresh one itself.
- **Job card** (`get_job`): a job that is still running, which keeps checking until the job finishes, fails or is cancelled, then offers **Continue**.
- **Skills card** (`find_skill`): the skills it found, each with an **Add** button that saves it to your library. It shows only on links that can save skills.

Clients without cards get the same information as text, so nothing is lost.

## Apps on Corsair's account

Some apps, such as Firecrawl, Exa, Reducto and TinyFish, can run on Corsair's own account with nothing to sign in to. Each call is billed to your organization's Corsair credits. `list_operations` and `get_schema` give each action's price.

## Corsair credits

Each organization gets free credits. To add more, open **Upgrade** in your Corsair account at [hub.corsair.dev/upgrade](https://hub.corsair.dev/upgrade). The agent doesn't link you there itself.

`list_integrations` gives the credits left, when the free ones come back and what this project spent this month. When credits run low, the agent says so in its next reply. When they run out or a spend limit is reached, the call doesn't run, nothing is charged and the agent tells you.

When a call fails at the app, Corsair gives its credits back. That refund is best effort: if it can't be recorded, the charge stays, so email [primary@corsair.dev](mailto:primary@corsair.dev) about a failed call you were charged for.

## Modes and approvals

Each link has a mode. Corsair checks every action against it, whatever the client allows.

| Mode | What it allows |
| --- | --- |
| Read | Reads only. Writes are refused. |
| Cautious (default) | Writes go through. A destructive action, such as a delete, needs your approval. |
| Strict | Every write needs your approval. Destructive actions are refused. |
| Open | Everything, without asking. |

When an action needs approval, the agent gives you a link. It shows exactly what will run and with which arguments. Approve or deny it there, then tell the agent to carry on. An approval covers that one action once.

Change a link's mode at [hub.corsair.dev/me](https://hub.corsair.dev/me).

## Troubleshooting

<AccordionGroup>
  <Accordion title="The agent says an app isn't connected">
    Ask it to connect the app. It calls `get_connect_link` and gives you a sign-in link, or in Claude a card with a **Connect** button. Open it, sign in to the app, then tell the agent you're done or press **Continue** on the card. A few apps Corsair provides directly come back ready with no link, and the agent can use them right away.
  </Accordion>
  <Accordion title="The sign-in link stopped working">
    Links last 10 minutes. On the card, press **New link**. Without a card, ask the agent for a new link.
  </Accordion>
  <Accordion title="I want to tell Corsair something went wrong">
    Ask the agent to send Corsair feedback. It calls `submit_feedback` with a short note in its own words, plus the error's reference code when the note is about an error, without anything from your apps. When Corsair can't do what you asked, or an error is on Corsair's side, the agent sends the note on its own and tells you. Or email [primary@corsair.dev](mailto:primary@corsair.dev).
  </Accordion>
  <Accordion title="An app needs setting up before it can be connected">
    The project behind your link has to finish setting the app up first, for example by adding its OAuth credentials. Whoever manages the project does this in Corsair.
  </Accordion>
  <Accordion title="An action is blocked by the permission mode">
    The link's mode doesn't allow that kind of action. Change the mode at [hub.corsair.dev/me](https://hub.corsair.dev/me), or use a link with a different mode.
  </Accordion>
  <Accordion title="I want this client to use a different link">
    Remove Corsair from the client, add it again and pick the other link when you sign in.
  </Accordion>
  <Accordion title="I added https://mcp.corsair.cloud/mcp earlier">
    That address still works and reaches the same server, so nothing needs to change. New setups use `https://mcp.corsair.dev/mcp`.
  </Accordion>
</AccordionGroup>
