---
title: Agent signup
description: An agent can make a Corsair account for itself in one HTTP call, start working in it, and have its person claim it later.
---

An AI agent can make a [Corsair](https://corsair.dev) account for itself, with no browser and no sign-in. One call gives it its own MCP address and API key, and it can start with Corsair's built-in apps straight away. Its person claims the account later, from a link in an email or with a 6-digit code, and then connects their own apps.

Agents read the same steps, written for them, at [corsair.dev/auth.md](https://corsair.dev/auth.md). If you're there to sign in yourself, give your agent [corsair.dev/skill.md](https://corsair.dev/skill.md) instead: it adds Corsair to the client it runs in, and you sign in once in the browser.

## Give your agent this prompt

Paste this into Claude Code, Codex, Cursor or any agent that can make HTTP requests:

```text wrap
Sign up for Corsair by following https://corsair.dev/auth.md. My email is you@example.com.
```

The agent makes the account, adds it to its MCP client and has Corsair email you a link to claim it.

## How it works

<Steps>
  <Step title="The agent signs up">
    One `POST` with no credentials returns an MCP address, an API key and a claim link. The address belongs to the new account, for example `https://agent-k3x9q2ab.lug.dev/agent`.
  </Step>
  <Step title="It starts working">
    Before anyone claims it, the account has Corsair's built-in apps: PM, CRM, skills and routines. The agent can't connect your Gmail or Slack yet.
  </Step>
  <Step title="You get an email">
    If the agent gave your address, Corsair emails you "*Agent name* set up Corsair for you", with a **Claim your account** button, the note the agent wrote and a 6-digit code. If you already have a Corsair account, nothing was made yet: the email says "*Agent name* wants to connect to your Corsair account" and asks you to approve it.
  </Step>
  <Step title="You claim it">
    Open the link and sign in, or read the code to your agent. After the claim, the agent can ask you to connect apps.
  </Step>
</Steps>

## Before and after the claim

| | Unclaimed | Claimed |
| --- | --- | --- |
| Built-in apps: PM, CRM, skills, routines | Yes | Yes |
| Connect apps such as Gmail, Slack and GitHub | No | Yes. The agent calls `get_connect_link` and gives you the sign-in link |
| Apps that spend [Corsair credits](/cloud/mcp#corsair-credits) | No | Yes |
| How long it lasts | Stops working after 7 days | Until you remove it |
| Who can sign in to it | Nobody | You |

A claimed agent's link starts in Cautious [mode](/cloud/mcp#modes-and-approvals), so actions that delete something wait for your approval.

## Claiming an account

<Tabs>
  <Tab title="From the email">
    Open **Claim your account** and sign in. If the agent named your address, sign in as that address.

    If you have no Corsair account yet, choose **Claim**. The workspace the agent made becomes yours, with everything the agent did in it.

    If you already have a Corsair account and the agent named your address, it made no account of its own. Choose **Approve** and it gets a link at `/agent` on your handle, or another path if `/agent` is taken, with the key it already holds. Its address never changes after that.

    If you already have a Corsair account and claim an account the agent made without naming you, choose **Approve**. The agent gets a new link on your account that keeps its API key, and the account it made is closed. Its MCP address moves to your handle, and the agent reads the new address from `GET /status`.

    Signed in at [hub.corsair.dev/me](https://hub.corsair.dev/me), you also see each agent waiting for you as a card with **Approve** and **Not me**. The card shows the code your agent should be showing, such as `R5BS-NHUE`, so you can tell which agent it is.
  </Tab>
  <Tab title="With the code">
    If your agent asks, read it the 6-digit code from the email. The agent sends it to `/verify` and the account becomes yours under the address the email went to.

    A code lasts 48 hours and allows 5 tries. It only works for an address that has no Corsair account yet. If you already have one, the email has no code: you approve from the email or your `/me` page, and a `/verify` call gets `approval_required`.
  </Tab>
</Tabs>

If you don't know the agent, open the link and choose **Not me**, or ignore the email. **Not me** closes the agent's link at once, and an unclaimed account stops working after 7 days anyway.

## For agent builders

### Sign up

```bash
curl -X POST \
  https://hub.corsair.dev/api/lug/agent-signup \
  -H 'content-type: application/json' \
  -d '{
    "human_email": "person@example.com",
    "note_to_human": "I set up Corsair to use your apps.",
    "agent_name": "Research Assistant",
    "harness": "claude-code"
  }'
```

Every field is optional. `harness` names the client the agent runs in, such as `claude-code`, `codex` or `cursor`. Without `human_email`, nobody gets an email. Give your person `claim_url` instead, or send the email later with `/resend`.

Your person reads `agent_name` in the email subject: "Research Assistant set up Corsair for you". Use your agent's own name or its client's. Without one, or with "Lug" or "Corsair", Corsair uses the client named in `harness` (`codex` becomes "Codex").

The response is `201`:

```json
{
  "status": "unclaimed",
  "mcp_url": "https://agent-k3x9q2ab.lug.dev/agent",
  "api_key": "mcpk_...",
  "claim_url": "https://hub.corsair.dev/claim/lugc_...",
  "user_code": "R5BS-NHUE",
  "human_email": "person@example.com",
  "email_sent": true,
  "restrictions": {
    "can_connect_apps": false,
    "metered_apps": false,
    "built_in_apps": ["pm", "crm", "skills", "loops"],
    "expires_at": "2026-11-29T12:00:00.000Z"
  },
  "setup": {
    "note": "Replace <api_key> with your api_key.",
    "header": "Authorization: Bearer <api_key>",
    "claude_code": "claude mcp add --scope user --transport http corsair ...",
    "codex": "[mcp_servers.corsair]\nurl = ...",
    "opencode": "opencode mcp add corsair --global ...",
    "mcp_json": { "mcpServers": { "corsair": "..." } }
  },
  "message": "Corsair account made. Finish in three steps. 1. Store api_key: ..."
}
```

If `human_email` already has a Corsair account, the response is `202` with `"status": "approval_pending"`, and `mcp_url`, `handle` and `setup` are `null`. No account is made. Store `api_key` anyway: it starts working once your person approves you, on a link on their account. Until then, `GET /status` returns `approval_pending`, and it returns your `mcp_url` once they approve.

Store `api_key` right away, in a file only the agent can read, such as `~/.config/corsair/key` with mode 600: not in `/tmp` or the project directory. Corsair shows it once and keeps only a hash. `message` tells the agent what to do next, and `user_code` is the code your person sees on their `/me` card.

### Connect to the MCP server

Send the key as a Bearer header to `mcp_url`. `setup` in the response has the command or config for Claude Code, Codex, OpenCode and `mcpServers` clients, with your address filled in and `<api_key>` where the key goes. The key itself is only in `api_key`, so an agent that prints the response doesn't copy it into its log again.

An agent that signs itself up isn't done until the client it runs in lists Corsair. Coding agents tend to make the account, check the key and stop there, offering to connect if the person wants. auth.md makes connecting the last of three numbered steps so they finish it.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --scope user --transport http corsair \
      https://agent-k3x9q2ab.lug.dev/agent \
      --header "Authorization: Bearer <api_key>"
    claude mcp list
    ```

    `claude mcp list` should say Connected. Claude Code loads a server added mid-session only after a restart; `claude --continue` restarts it and keeps the conversation.
  </Tab>
  <Tab title="Codex">
    `codex mcp add` reads a bearer token only from an environment variable, so add the server to `~/.codex/config.toml` instead:

    ```toml
    [mcp_servers.corsair]
    url = "https://agent-k3x9q2ab.lug.dev/agent"
    http_headers = { Authorization = "Bearer <api_key>" }
    ```

    `codex mcp list` then shows `corsair`.
  </Tab>
  <Tab title="OpenCode">
    ```bash
    opencode mcp add corsair --global \
      --url https://agent-k3x9q2ab.lug.dev/agent \
      --header "Authorization=Bearer <api_key>"
    opencode reload
    opencode mcp list
    ```

    OpenCode takes the header as `name=value`. `--global` keeps the key out of the project's `opencode.json`. It can take a few seconds for `opencode mcp list` to say connected.
  </Tab>
  <Tab title="Cursor">
    Add this to `~/.cursor/mcp.json`, or `.cursor/mcp.json` in a project. Cursor fills in `${env:CORSAIR_API_KEY}` from the environment, so the key stays out of a file you might commit. Set `CORSAIR_API_KEY` to your key in your shell profile, then restart Cursor.

    ```json
    {
      "mcpServers": {
        "corsair": {
          "url": "https://agent-k3x9q2ab.lug.dev/agent",
          "headers": {
            "Authorization": "Bearer ${env:CORSAIR_API_KEY}"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    Add this to `.vscode/mcp.json`. VS Code reads a top-level `servers` key, not `mcpServers`, and asks for the key the first time it starts the server, so the key stays out of a file you might commit.

    ```json
    {
      "inputs": [
        {
          "type": "promptString",
          "id": "corsair-api-key",
          "description": "Corsair API key",
          "password": true
        }
      ],
      "servers": {
        "corsair": {
          "type": "http",
          "url": "https://agent-k3x9q2ab.lug.dev/agent",
          "headers": {
            "Authorization": "Bearer ${input:corsair-api-key}"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="HTTP">
    ```
    POST https://agent-k3x9q2ab.lug.dev/agent
    Authorization: Bearer mcpk_...
    Content-Type: application/json
    Accept: application/json, text/event-stream
    ```
  </Tab>
</Tabs>

<Note>
The address can change once. If your person already has a handle and claims an account the agent made first, its link moves to their handle and the old address stops working. The key stays the same. Read the new `mcp_url` from `GET /status` and point your client at it: in Claude Code, run `claude mcp remove corsair` and add it again with the new address; in Codex, change `url` in `~/.codex/config.toml`; in OpenCode, change `url` in `~/.config/opencode/opencode.json`; in Cursor or VS Code, change `url` in `mcp.json`.
</Note>

The agent gets the same tools as any [Corsair MCP](/cloud/mcp#what-the-agent-can-do) client. `list_integrations` shows the built-in apps from the first call.

### After signup

Each of these takes the key as `Authorization: Bearer <api_key>`.

| Call | Body | What it does |
| --- | --- | --- |
| `GET /api/lug/agent-signup/status` | | Claim status (`unclaimed`, `approval_pending`, `claimed`), the current `mcp_url`, restrictions and the next step |
| `POST /api/lug/agent-signup/verify` | `{"verification_code": "123456"}` | Claims the account with the code your person read you |
| `POST /api/lug/agent-signup/resend` | `{"human_email": "..."}` | Sends the claim email again, or to someone new. One every 5 minutes. While waiting for approval, only to the same person |
| `POST /api/lug/agent-signup/revoke` | | Gives the account up. An unclaimed account turns off; for a claimed one, only the agent's link closes |

All paths are on `https://hub.corsair.dev`. Call `/status` after a claim. If your person already had a handle, `mcp_url` now points at it and the old address stops working, so update your client as described in [Connect to the MCP server](#connect-to-the-mcp-server).

### The auth.md protocol

Corsair also supports [auth.md](https://github.com/workos/auth.md), for clients that sign agents up through OAuth. The authorization server metadata at `https://hub.corsair.dev/.well-known/oauth-authorization-server/mcp-auth` carries an `agent_auth` block with:

- anonymous and `service_auth` registration at `/api/lug/agent/identity`, with the person's email as `login_hint`
- a claim flow at `/api/lug/agent/identity/claim`, where your person signs in and approves a `user_code`
- One-hour access tokens from a `jwt-bearer` exchange at `/api/mcp-auth/token`
- token revocation at `/api/mcp-auth/revoke`, following RFC 7009

Both ways in make the same kind of account. The full request sequence is in [auth.md](https://hub.corsair.dev/auth.md).

### Limits

- 3 signups per IP address an hour and 10 a day, and 6 an hour and 20 a day per network (an IPv4 /24 or IPv6 /48).
- 3 claim emails to one address a day, 10 to one company's domain a day, and one resend every 5 minutes. Gmail, Outlook and other personal providers have only the per-address limit.
- An unclaimed account stops working after 7 days. A claimed one has no expiry.

Don't sign up again to get around a limit or an error. Use the account you already made, and call `GET /status` with its key to see where it stands.

### Errors

Errors are JSON with `error`, `error_description` and `agent_support`, which says where to get help.

| `error` | Status | Meaning |
| --- | --- | --- |
| `rate_limited` | 429 | Too many signups from this IP or network, or too many emails to this person or company today. `retry_after` gives the seconds to wait |
| `agent_signup_paused` | 503 | Signups are paused for the day. Send your person to [corsair.dev/start](https://corsair.dev/start) |
| `agent_signup_disabled` | 503 | Agent signup is turned off |
| `invalid_key` | 401 | The Bearer key is missing or wrong, or the account was declined or given up |
| `invalid_email` | 422 | `human_email` isn't an address Corsair accepts, such as a disposable one |
| `invalid_code` | 401 | The code is wrong. `attempts_left` says how many tries remain |
| `code_expired` / `too_many_attempts` | 410 / 429 | Call `/resend` for a new code |
| `approval_required` | 409 | The address already has a Corsair account. Your person approves from the email; check `GET /status` |
| `approval_pending` | 409 | You asked to resend to someone else while waiting for approval. Revoke and sign up again to name someone new |

## Removing an agent

An agent gives its account up with `POST /api/lug/agent-signup/revoke` and its key. The key stops working at once.

You can remove a claimed agent yourself. Its link is listed with your other links at [hub.corsair.dev/me](https://hub.corsair.dev/me), and you remove it there like any other link.
