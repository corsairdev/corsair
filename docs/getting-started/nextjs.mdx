Add Corsair to a Next.js App Router app and deploy it to Vercel. Hub hosts the OAuth and webhook surfaces. Postgres is the database that survives serverless.

The [Quick start](/getting-started/quick-start) is the same flow with SQLite on your laptop. A coding agent can do this from [Set up with your agent](/getting-started/set-up-with-your-agent). Vercel AI SDK setup is a [separate guide](/mcp-adapters/vercel-ai).

You will add these files:

```text
src/
├── app/api/corsair/[[...path]]/route.ts
├── app/api/repositories/route.ts
└── server/
    ├── corsair.ts
    └── database.ts
```

<Steps>

<Step>

## Create the app

Start with a TypeScript App Router project. Skip this step if you already have one.

`--src-dir` puts the app under `src/` so the paths below match. `--yes` accepts the rest of the recommended defaults (TypeScript, ESLint, Tailwind, App Router).

<CodeGroup>
```bash npm
npx create-next-app@latest corsair-next --src-dir --yes
cd corsair-next
```
```bash yarn
yarn create next-app corsair-next --src-dir --yes
cd corsair-next
```
```bash pnpm
pnpm create next-app corsair-next --src-dir --yes
cd corsair-next
```
```bash bun
bunx create-next-app corsair-next --src-dir --yes
cd corsair-next
```
</CodeGroup>

<Note>
Pages Router is supported. Mount a catch-all at `pages/api/corsair/[...path].ts` instead. See [Frameworks](/adapters/handlers).
</Note>

</Step>

<Step>

## Install Corsair

Install Corsair, the GitHub plugin, and the Postgres driver. Swap GitHub for any other plugin from the [catalog](/guides/plugins).

<CodeGroup>
```bash npm
npm install corsair @corsair-dev/github pg
npm install --save-dev @types/pg
```
```bash yarn
yarn add corsair @corsair-dev/github pg
yarn add --dev @types/pg
```
```bash pnpm
pnpm add corsair @corsair-dev/github pg
pnpm add --save-dev @types/pg
```
```bash bun
bun add corsair @corsair-dev/github pg
bun add --dev @types/pg
```
</CodeGroup>

<Warning>
Use Postgres when you deploy to Vercel. A SQLite file is not durable across serverless instances.
</Warning>

</Step>

<Step>

## Configure the environment

Create `.env.local` in the project root. Next.js loads it automatically. Do not use `dotenv` here.

Create a project in the [Hub dashboard](https://hub.corsair.dev/dashboard) and copy the **development** API key and signing secret. Then generate a KEK. Corsair encrypts every stored credential with it:

<GenerateKEK />

```bash .env.local
DATABASE_URL=postgresql://user:password@host:5432/database
CORSAIR_KEK=your-generated-kek
CORSAIR_DEV_API_KEY=ck_dev_...
CORSAIR_DEV_SIGNING_SECRET=...
```

If your provider offers a pooled connection string (Neon `-pooler`, Supabase port `6543`), use that for `DATABASE_URL`. Run the Postgres migration from [Database](/concepts/database) before continuing.

<Warning>
Keep `DATABASE_URL`, `CORSAIR_KEK`, and Hub keys server-only. Never prefix them with `NEXT_PUBLIC_` or commit `.env.local`.
</Warning>

</Step>

<Step>

## Connect Postgres

Keep one pool across Next.js module reloads. Create `src/server/database.ts`:

```ts src/server/database.ts
import 'server-only';
import { Pool } from 'pg';

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
    throw new Error('DATABASE_URL is not set');
}

const globalForDatabase = globalThis as unknown as {
    corsairPool: Pool | undefined;
};

export const database = globalForDatabase.corsairPool ?? new Pool({
    connectionString,
    max: 1,
});

globalForDatabase.corsairPool = database;
```

`max: 1` keeps each serverless function instance from opening a large pool. Increase it only if your database connection limit allows it. `import 'server-only'` fails the build if this file is imported from a Client Component.

</Step>

<Step>

## Create the Corsair instance

```ts src/server/corsair.ts
import 'server-only';
import { github } from '@corsair-dev/github';
import { createCorsair } from 'corsair';

import { database } from '@/server/database';

const kek = process.env.CORSAIR_KEK;
const isProd = process.env.VERCEL_ENV === 'production';
const projectApiKey = isProd
    ? process.env.CORSAIR_PROD_API_KEY
    : process.env.CORSAIR_DEV_API_KEY;
const signingSecret = isProd
    ? process.env.CORSAIR_PROD_SIGNING_SECRET
    : process.env.CORSAIR_DEV_SIGNING_SECRET;

if (!kek) {
    throw new Error('CORSAIR_KEK is not set');
}

if (!projectApiKey || !signingSecret) {
    throw new Error(
        isProd
            ? 'CORSAIR_PROD_API_KEY and CORSAIR_PROD_SIGNING_SECRET must be set'
            : 'CORSAIR_DEV_API_KEY and CORSAIR_DEV_SIGNING_SECRET must be set',
    );
}

export const corsair = createCorsair({
    plugins: [github({ authType: 'managed' })],
    database,
    kek,
    hub: {
        projectApiKey,
        signingSecret,
    },
});
```

`authType: 'managed'` is the Hub OAuth path. Add more plugins later by installing the package and appending it to `plugins`.

</Step>

<Step>

## Mount the handler

This one route serves Hub delivery (OAuth callbacks, connect pages) and the management API. If you used `--src-dir`, the file lives at `src/app/api/corsair/[[...path]]/route.ts`.

<MountHandlerNextjs />

Leave the default Node.js runtime. `pg` does not run on Edge, so do not set `export const runtime = 'edge'`.

Start the app and hit the health check:

<CodeGroup>
```bash npm
npm run dev
```
```bash yarn
yarn dev
```
```bash pnpm
pnpm dev
```
```bash bun
bun dev
```
</CodeGroup>

```bash
curl http://localhost:3000/api/corsair/ok
```

You should get `{ "ok": true }`. The first request also registers this app's delivery URL with Hub. The dashboard header dot turns green when that succeeds. See [Delivery URLs](/hub/delivery-urls) if it stays grey.

</Step>

<Step>

## Connect GitHub and call it

Mint a connect link and send the user to it. Hub hosts the connect page:

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
    plugin: 'github',
    tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

After GitHub is connected, call it from a Route Handler or a Server Component. Both import the same server singleton:

```ts src/app/api/repositories/route.ts
import { corsair } from '@/server/corsair';

export async function GET() {
    try {
        const repositories = await corsair.github.api.repositories.list({
            perPage: 20,
        });

        return Response.json({ repositories });
    } catch (error) {
        console.error('Failed to list GitHub repositories', error);
        return Response.json(
            { error: 'Failed to list repositories' },
            { status: 500 },
        );
    }
}
```

<Note>
Add your app's authentication before exposing this route in production.
</Note>

```bash
curl http://localhost:3000/api/repositories
```

Hub delivers provider webhooks to `/api/corsair`. You do not add a separate `processWebhook` route. Hosting those surfaces yourself is [manual mode](/hub/manual-vs-hub).

</Step>

<Step>

## Deploy to Vercel

1. Push the project and import it into Vercel.
2. Add `DATABASE_URL` and `CORSAIR_KEK` for all environments. Add `CORSAIR_DEV_API_KEY` and `CORSAIR_DEV_SIGNING_SECRET` to Development and Preview. Add `CORSAIR_PROD_API_KEY` and `CORSAIR_PROD_SIGNING_SECRET` to Production. The `corsair.ts` snippet reads `VERCEL_ENV` to pick the pair.
3. If production uses a separate database, run the [Postgres migration](/concepts/database) against it before deploying.
4. In the Hub dashboard, switch to **Production** and register `https://your-project.vercel.app/api/corsair` as the delivery URL.
5. Deploy, then send a test connect.

See [Environments](/hub/environments) for why preview deploys keep development keys.

<Warning>
Keep the same `CORSAIR_KEK` after credentials have been stored. Changing or losing it makes the encrypted credentials unreadable.
</Warning>

</Step>
