This guide walks you through obtaining credentials for the Cloudinary plugin.

## Authentication Method

The Cloudinary plugin uses API key authentication (API Key + API Secret + Cloud Name via HTTP Basic Auth).

- **[`api_key`](/concepts/api-key)** (default) — Cloudinary API key paired with `api_secret` and `cloud_name`

## API Key Setup

### Step 1: Open API Keys

1. Sign in to the [Cloudinary Console](https://console.cloudinary.com).
2. Open **Settings** → **API Keys** (or **Product Environment Settings** → **API Keys**).
3. Note your **Cloud name**, **API Key**, and **API Secret**.

Copy the API secret immediately if it is only shown once for a newly created key.

### Step 2: Store credentials

```bash
pnpm corsair setup --plugin=cloudinary \
  api_key=your-api-key \
  api_secret=your-api-secret \
  cloud_name=your-cloud-name
```

Or pass credentials in plugin options:

```ts corsair.ts
cloudinary({
	key: process.env.CLOUDINARY_API_KEY,
	apiSecret: process.env.CLOUDINARY_API_SECRET,
	cloudName: process.env.CLOUDINARY_CLOUD_NAME,
})
```

Verify:

```bash
pnpm corsair auth --plugin=cloudinary --credentials
```

## Webhook notifications

Cloudinary signs notification webhooks with your **API secret** (`x-cld-signature` + `x-cld-timestamp`).

Corsair verifies signatures with:

1. `webhookSecret` plugin option (if set), else
2. account field `webhook_signature`, else
3. account `api_secret`

Use the same API secret Cloudinary uses to sign notifications unless you intentionally configure a dedicated secret for local testing.

## Required Credentials Summary

| Credential | Required for | Where to find |
|------------|----------------|---------------|
| API Key | [`api_key`](/concepts/api-key) auth | Console → Settings → API Keys |
| API Secret | Auth + webhook signature verification | Console → Settings → API Keys |
| Cloud Name | Product environment routing | Console → Settings → Product Environment |

For general information about how Corsair handles authentication, see [Authentication](/concepts/auth).
