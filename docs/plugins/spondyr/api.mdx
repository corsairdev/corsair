## Batch

### send

`batch.send`

Generate correspondence for a list of data objects in one request, optionally merging shared data into each

**Risk:** `write`

```ts
await corsair.spondyr.api.batch.send({ event_type: 'OrderPlaced', data: [{ Recipient: 'a@acme.com' }, { Recipient: 'b@acme.com' }], shared_data: { Message: 'Hello World!' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `event_type` | `string` | Yes | — |
| `data` | `Record<string, string \| number \| boolean \| null>[]` | Yes | One entry per correspondence to generate |
| `shared_data` | `Record<string, string \| number \| boolean \| null>` | No | Merged into every entry of `data` before processing |
| `is_generate_only` | `boolean` | No | — |

`shared_data` is merged into every entry of `data`. The response ReferenceID is for `batch.status`.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `APIStatus` | `string` | Yes | `OK` or `ERROR`; a 200 can still be `ERROR` |
| `ErrorMessage` | `string \| null` | No | — |
| `ReferenceID` | `string \| null` | No | — |

## Correspondence

### deliver

`correspondence.deliver`

Deliver correspondence that was generated with `is_generate_only`, optionally to extra recipients

**Risk:** `write`

```ts
await corsair.spondyr.api.correspondence.deliver({ reference_id: 'c1a2b3-reference', original_recipients: 'All' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `reference_id` | `string` | Yes | The ReferenceID returned by `correspondence.send` |
| `template` | `string` | No | Template names to deliver, comma separated; default "All" |
| `original_recipients` | `string` | No | "All", "None", or Recipient names; default "All" |
| `new_recipients` | `object[]` | No | Extra recipients beyond the ones the correspondence resolved |

Set `original_recipients` to "None" to deliver only to `new_recipients`. A targeted delivery method needs the matching address, which the input schema checks.

### send

`correspondence.send`

Generate correspondence from a Transaction Type and either deliver it or hold it for `correspondence.deliver`

**Risk:** `write`

```ts
await corsair.spondyr.api.correspondence.send({ event_type: 'OrderPlaced', data: { OrderNumber: 12345 }, is_generate_only: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `event_type` | `string` | Yes | Event Type name; Spondyr resolves the Transaction Type from it |
| `data` | `Record<string, string \| number \| boolean \| null>` | Yes | The document data, in the shape of the Transaction Type JSON sample |
| `is_generate_only` | `boolean` | No | When true the correspondence is generated but not delivered until `correspondence.deliver` is called |

Pass `is_generate_only: true` to generate without delivering. The returned `ReferenceID` is what the status and deliver calls take.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `APIStatus` | `string` | Yes | `OK` or `ERROR`; a 200 can still be `ERROR` |
| `ErrorMessage` | `string \| null` | No | — |
| `ReferenceID` | `string \| null` | No | — |
