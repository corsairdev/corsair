The Eventbrite plugin handles incoming webhooks. Point your provider’s subscription URL at your Corsair HTTP handler (see [Overview](/plugins/eventbrite/overview) for setup context and the exact URL shape).

<Info>
**New to Corsair?** See [webhooks](/concepts/webhooks) and [hooks](/concepts/hooks).
</Info>

## Webhook map

- `notifications`
  - `delivery` (`notifications.delivery`)

## HTTP handler setup

```ts app/api/webhook/route.ts
import { processWebhook } from "corsair";
import { corsair } from "@/server/corsair";

export async function POST(request: Request) {
    const headers = Object.fromEntries(request.headers);
    const body = await request.json();
    const result = await processWebhook(corsair, headers, body);
    return result.response;
}
```

## Notifications

### Delivery

`notifications.delivery`

An Eventbrite webhook delivery: the notification naming the changed object’s `api_url` and the `config.action` that fired, not the object itself

**Payload**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `api_url` | `string` | Yes | Absolute v3 API URL of the object that changed, always on eventbriteapi.com. |
| `config` | `object \| null` | No | — |

<Accordion title="config full type">

{
  action?: string | null,

```
</Accordion>

  } | null
}
```
</Accordion>
</AccordionGroup>

**`webhookHooks` example**

```ts
eventbrite({
    webhookHooks: {
        notifications: {
            delivery: {
                before(ctx, args) {
                    return { ctx, args };
                },
                after(ctx, response) {
                },
            },
        },
    },
})
```
