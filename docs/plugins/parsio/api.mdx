## Data

### getParsed

`data.getParsed`

Read the parsed data records of a mailbox, paged by date

**Risk:** `read`

```ts
await corsair.parsio.api.data.getParsed({ mailboxId: "65d1c0e4b8f2b3c4d5e6f7a8", from: "2026-04-01" });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `mailboxId` | `string` | Yes | Mailbox id |
| `page` | `number` | No | Page number |
| `from` | `string` | No | Start date in YYYY-MM-DD format |
| `to` | `string` | No | End date in YYYY-MM-DD format |

Paged parsed data for the mailbox documents.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `docs` | `object[]` | Yes | The parsed data records on this page |
| `docIds` | `string[] \| null` | No | Ids of the documents on this page |
| `totalDocs` | `number \| null` | No | Documents in total |
| `limit` | `number \| null` | No | Page size |
| `page` | `number \| null` | No | Current page |
| `totalPages` | `number \| null` | No | Pages in total |
| `hasNextPage` | `boolean \| null` | No | Whether another page follows |
| `nextPage` | `number \| null` | No | Next page number |

<AccordionGroup>
<Accordion title="docs full type">

```ts
{
  doc_id?: string | null
}[]
```
</Accordion>
</AccordionGroup>

## Documents

### createAsync

`documents.createAsync`

Parse HTML or text content asynchronously; poll documents.get for the result

**Risk:** `write`

```ts
await corsair.parsio.api.documents.createAsync({ mailboxId: "65d1c0e4b8f2b3c4d5e6f7a8", text: "Order 42" });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `mailboxId` | `string` | Yes | Mailbox id that parses the document |
| `html` | `string` | No | HTML content to parse; wins when both html and text are sent |
| `text` | `string` | No | Plain text content to parse |
| `__meta__` | `Record<string, any>` | No | Custom payload included in the parsed JSON as __meta__ |

Returns parsing_in_progress true with status parsing; the job wrapper follows it with documents.get until status is parsed.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `doc_id` | `string` | Yes | Document id |
| `parsing_in_progress` | `boolean \| null` | No | Whether parsing is still running |
| `status` | `string \| null` | No | Document status, e.g. parsing, parsed |
| `name` | `string \| null` | No | Document name; null while parsing |
| `content_type` | `string \| null` | No | Media type of the source document |
| `created_at` | `string \| null` | No | Creation timestamp |
| `processed_at` | `string \| null` | No | When parsing finished |
| `json` | `Record<string, any> \| null` | No | The parsed data |

### createSync

`documents.createSync`

Parse HTML or text content and wait for the result; template and GPT parsers only, each parse consumes credits

**Risk:** `write`

```ts
await corsair.parsio.api.documents.createSync({ mailboxId: "65d1c0e4b8f2b3c4d5e6f7a8", html: "<p>Order 42</p>", __meta__: { source: "api" } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `mailboxId` | `string` | Yes | Mailbox id that parses the document |
| `html` | `string` | No | HTML content to parse; wins when both html and text are sent |
| `text` | `string` | No | Plain text content to parse |
| `__meta__` | `Record<string, any>` | No | Custom payload included in the parsed JSON as __meta__ |

Supported only by the template-based and GPT-powered parsers; when parsing_in_progress is true, poll documents.get.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `doc_id` | `string` | Yes | Document id |
| `parsing_in_progress` | `boolean \| null` | No | Whether parsing is still running |
| `status` | `string \| null` | No | Document status, e.g. parsing, parsed |
| `name` | `string \| null` | No | Document name; null while parsing |
| `content_type` | `string \| null` | No | Media type of the source document |
| `created_at` | `string \| null` | No | Creation timestamp |
| `processed_at` | `string \| null` | No | When parsing finished |
| `json` | `Record<string, any> \| null` | No | The parsed data |

## Webhooks

### create

`webhooks.create`

Create a webhook subscription for doc.parsed, doc.fail, doc.received or table.parsed events

**Risk:** `write`

```ts
await corsair.parsio.api.webhooks.create({ mailboxId: "65d1c0e4b8f2b3c4d5e6f7a8", url: "https://example.com/webhooks/parsio", event: "doc.parsed", enabled: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `mailboxId` | `string` | Yes | Mailbox the webhook belongs to |
| `name` | `string` | No | Webhook name |
| `url` | `string` | Yes | Endpoint deliveries are posted to |
| `event` | `doc.parsed \| doc.parsed.flat \| doc.fail \| doc.received \| table.parsed` | Yes | Event the webhook delivers |
| `enabled` | `boolean` | No | Whether deliveries are active |
| `table_id` | `string` | No | Required only when the event is table.parsed |

Events: doc.parsed, doc.parsed.flat, doc.fail, doc.received, table.parsed. table_id is required only for table.parsed. The answer includes the webhook signing secret: store it with keys.set_webhook_signature. table_id is sent empty when unset (the API refuses it missing).



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `_id` | `string` | Yes | Webhook id |
| `name` | `string \| null` | No | Webhook name |
| `url` | `string \| null` | No | Endpoint deliveries are posted to |
| `event` | `string \| null` | No | Event the webhook delivers |
| `enabled` | `boolean \| null` | No | Whether deliveries are active |
