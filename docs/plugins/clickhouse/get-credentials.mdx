---
title: Get Credentials
description: Step-by-step instructions for obtaining ClickHouse credentials and pointing the Corsair plugin at a ClickHouse HTTP endpoint.
---

This guide walks you through obtaining everything the ClickHouse plugin
needs: a ClickHouse HTTP endpoint and a Basic-auth credential.

## What you need

The plugin talks to the ClickHouse **HTTP interface** (default port
`8123`, TLS port `8443`). You will need:

- The HTTP endpoint URL of your ClickHouse server, including the port
- A ClickHouse user with permission to read from the relevant databases

## Auth model

The plugin uses HTTP Basic authentication. The credential is stored in the
Corsair account as the `api_key` and is the `base64(user:password)` value
(or the full `Authorization: Basic …` header value — the plugin handles
both shapes).

The per-tenant HTTP endpoint URL is stored either:

- as the `baseUrl` plugin option (solo mode, single tenant), or
- as the account's `tenant_external_id` (multi-tenant mode, one cluster
  per tenant).

## Step 1 — Find or create a ClickHouse user

If you are using ClickHouse Cloud, the connection details are in the
service overview:

1. Open your ClickHouse Cloud service.
2. Click **Connect** → **HTTPS** (or **Native** — not what the plugin
   uses).
3. Copy the endpoint URL (e.g. `https://<id>.<region>.aws.clickhouse.cloud:8443`).
4. Use the service's default password, or create a dedicated user with
   read-only permissions in SQL:

   ```sql
   CREATE USER corsair IDENTIFIED BY '<password>';
   GRANT SHOW TABLES, SELECT ON *.* TO corsair;
   ```

If you are running a self-hosted ClickHouse, the HTTP endpoint is
`http://<host>:8123` (or `https://<host>:8443` if TLS is enabled). Create
a user the same way.

## Step 2 — Base64-encode the credential

The plugin stores the credential in the standard Basic-auth format.

```bash
echo -n "corsair:<password>" | base64
# → Y29yc2Fpcjo8cGFzc3dvcmQ+
```

If you prefer, you can also pass the full header value with the
`Basic ` prefix; the plugin strips-or-adds it transparently.

## Step 3 — Store the credential

Solo mode (one cluster, the credential is shared):

```bash
pnpm corsair setup --plugin=clickhouse api_key=Basic Y29yc2Fpcjo8cGFzc3dvcmQ+
```

Multi-tenant mode (each tenant supplies its own URL and credential through
the connect flow; the `tenant_external_id` slot stores the URL):

```bash
pnpm corsair connect --plugin=clickhouse \
    tenant_external_id=https://tenant-ch.example.com:8443 \
    api_key=Basic Y29yc2Fpcjo8cGFzc3dvcmQ+
```

Verify the stored credential:

```bash
pnpm corsair auth --plugin=clickhouse --credentials
```

You should see the plugin's auth status as `ready` and the `api_key`
field as configured.

## What the plugin sends

For every query, the plugin issues one request:

```
POST <baseUrl>/?database=<db>&<param>=<value> HTTP/1.1
Authorization: Basic <base64(user:password)>
Content-Type: text/plain; charset=utf-8

<sql>
FORMAT JSONEachRow
```

The response is `Content-Type: text/plain` and contains one JSON object
per line. Errors come back with the ClickHouse error message as the
response body and the appropriate HTTP status (401, 403, 404, …).
