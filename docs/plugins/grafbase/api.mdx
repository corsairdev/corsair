## Access Tokens

### create

`accessTokens.create`

Create a USER or ACCOUNT access token; the jwt value is returned only in this response, so store it right away

**Risk:** `write`

```ts
await corsair.grafbase.api.accessTokens.create({ name: 'ci-token', kind: 'USER' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | A name to recognize the token by. |
| `kind` | `'USER' \| 'ACCOUNT'` | Yes | USER acts as you. ACCOUNT acts as an organization and needs accountId. |
| `accountId` | `string` | No | The organization ID; required for ACCOUNT tokens. |
| `expiresAt` | `string` | No | When the token expires, as ISO 8601 such as 2026-12-31T23:59:59Z. Omit for no expiry. |
| `graphScopes` | `string[]` | No | Organization graph IDs the token may use; omit to allow all of them. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `__typename` | `string` | Yes | — |
| `jwt` | `string \| null` | No | — |
| `token` | `object \| null` | No | — |

<AccordionGroup>
<Accordion title="token full type">

```ts
{
  id: string,
  name: string,
  accountId?: string | null,
  createdAt?: string | null,
  expiresAt?: string | null,
  graphScopes?: {
    id: string,
    slug?: string | null
  }[] | null
} | null
```
</Accordion>
</AccordionGroup>

### publish

`subgraphs.publish`

Publish a subgraph SDL to a graph branch, which runs composition and can trigger a gateway deployment; the outcome names the result, and composition failures carry their messages

**Risk:** `write`

```ts
await corsair.grafbase.api.subgraphs.publish({ accountSlug: 'fieldkit', graphSlug: 'analytics-api', subgraph: 'products', schema: 'type Product { id: ID! name: String }', url: 'https://products.fieldkit.example/graphql', message: 'Add Product.name' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `accountSlug` | `string` | Yes | The organization slug. |
| `graphSlug` | `string` | Yes | The graph slug. |
| `subgraph` | `string` | Yes | The subgraph name. |
| `schema` | `string` | Yes | The subgraph SDL to publish. |
| `url` | `string` | No | The subgraph routing URL. Omit it for an existing subgraph or a virtual one. |
| `branch` | `string` | No | The branch to publish to; defaults to the production branch. |
| `message` | `string` | No | A note kept in the deploy history. |
| `virtual` | `boolean` | No | True publishes a virtual subgraph with no routing URL. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `__typename` | `string` | Yes | — |
| `messages` | `string[] \| null` | No | — |
| `deploymentError` | `string \| null` | No | — |
