## Bookings

### create

`bookings.create`

Book an appointment; SuperSaaS may email the customer a confirmation, depending on the schedule settings. A resource schedule needs start and finish, a capacity schedule needs a slot id

**Risk:** `destructive`

```ts
await corsair.supersaas.api.bookings.create({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `schedule_id` | `number` | Yes | The schedule id, the number at the end of the Configure Overview URL. |
| `start` | `string` | No | A local wall-clock value, as YYYY-MM-DD or YYYY-MM-DD HH:MM:SS. SuperSaaS applies the schedule timezone. |
| `finish` | `string` | No | A local wall-clock value, as YYYY-MM-DD or YYYY-MM-DD HH:MM:SS. SuperSaaS applies the schedule timezone. |
| `slot_id` | `number \| string` | No | — |
| `resource_id` | `number \| string` | No | — |
| `full_name` | `string \| null` | No | — |
| `email` | `string \| null` | No | — |
| `address` | `string \| null` | No | — |
| `mobile` | `string \| null` | No | — |
| `phone` | `string \| null` | No | — |
| `country` | `string \| null` | No | — |
| `field_1` | `string \| null` | No | — |
| `field_2` | `string \| null` | No | — |
| `field_1_r` | `string \| null` | No | — |
| `field_2_r` | `string \| null` | No | — |
| `super_field` | `string \| null` | No | — |
| `form_id` | `string \| null` | No | — |
| `user_id` | `number \| string` | No | Create the booking on behalf of this user (id or your own key). |
| `webhook` | `boolean` | No | Trigger the schedule's webhooks for this booking. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `created` | `true` | Yes | — |
| `id` | `string` | Yes | The new record id, from the Location header. |
| `location` | `string` | Yes | The new record URL SuperSaaS returned. |

### delete

`bookings.delete`

Delete a booking, which frees its time for someone else and cannot be undone

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.supersaas.api.bookings.delete({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `schedule_id` | `number` | Yes | The schedule id, the number at the end of the Configure Overview URL. |
| `booking_id` | `number \| string` | Yes | — |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | Yes | — |
| `deleted` | `true` | Yes | — |

### changes

`schedules.changes`

Read the changes to a schedule since a time, which is how a sync catches up; omitting the time gives the ten most recent

**Risk:** `read`

```ts
await corsair.supersaas.api.schedules.changes({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `schedule_id` | `number` | Yes | The schedule id, the number at the end of the Configure Overview URL. |
| `from` | `string` | No | Only changes after this UTC time (YYYY-MM-DD HH:MM:SS), not the schedule timezone. Omitted shows the ten most recent. |
| `to` | `string` | No | Only changes before this UTC time (YYYY-MM-DD HH:MM:SS). |
| `limit` | `number` | No | Records to return. |
| `offset` | `number` | No | Records to skip, to read past a full page. |
| `slot` | `boolean` | No | Group the answer by slot (capacity schedules). |

`slots.delete`

**Risk:** `destructive` · **Irreversible**

