## Customers

### list

`customers.list`

List the account customers, with field selection, sorting and paging

**Risk:** `read`

```ts
await corsair.hotspotsystem.api.customers.list({ limit: 25, offset: 0 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `fields` | `string[]` | No | Response properties to return, such as `["id", "name"]`. Omitted returns every property. |
| `sort` | `string` | No | A response property to sort by. Prefix it with `-` for descending order, such as `-registered_at`. |
| `limit` | `number` | No | How many items to return per page. |
| `offset` | `number` | No | Zero-based index of the first item to return. Take the next value from `next_offset` on the previous page. |

A customer and a subscriber have the same documented properties, so both are the same shape here.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `items` | `object[]` | Yes | — |
| `metadata` | `object \| null` | No | — |
| `next_offset` | `number` | No | — |

## Ping

### check

`ping.check`

Confirm the API answers: returns `pong`. Needs a key, because Corsair resolves one before every call

**Risk:** `read`

```ts
await corsair.hotspotsystem.api.ping.check({});
```

**Input:** _empty object_

Answers `{ ping: "pong" }`. The endpoint needs no key, but Corsair resolves one before every call, so a connected account is still required.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ping` | `string \| null` | No | — |
