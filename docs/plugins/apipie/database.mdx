---
title: APIpie Database
description: Cached APIpie model and generated-image entities.
---

APIpie caches selected read results when Corsair is configured with a database. Cache writes happen after a successful API response and are scoped by the active tenant.

## Synced entities

- `models` mirrors entries from `models.list`.
- `modelDetails` mirrors entries from `models.listDetailed`.
- `images` mirrors generated image URLs from `images.generate`.

The image entity stores URLs, not `b64_json` response data. Generated images are assigned a request-level generation id and an item index because APIpie does not return image identifiers.

## Query examples

Use the plugin's bound database API:

```typescript
const models = await corsair.apipie.db.models.findMany({ limit: 20 });
const images = await corsair.apipie.db.images.findMany({ limit: 20 });
```

## Entity shapes

### `models`

Contains `id` plus optional model identity, provider, type, route, availability, pricing, latency, token-limit, and query-count fields.

### `modelDetails`

Contains `id` plus optional modality, capability, capacity, pricing, and supported-parameter fields. This is stored separately from `models` because the detailed API response has a different shape.

### `images`

```typescript
type ApipieImage = {
  id: string;
  prompt?: string | null;
  model?: string | null;
  url?: string | null;
  revised_prompt?: string | null;
  created?: number | null;
};
```

For the complete generated response, use `images.generate`; the database contains only the cacheable URL metadata.
