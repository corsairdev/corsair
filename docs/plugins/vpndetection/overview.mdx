Use **VPNDetection** through Corsair: one client, typed API calls, local DB sync, and incoming webhooks.

The API answers lookups without a key, so the plugin works with none stored: leave the key unset and each lookup goes out keyless. A key from vpndetection.io (free, made in the console under API &gt; Keys) adds the fields its plan includes, which pass through unchanged, and is needed for everything else. Keyless use is covered by the API's [terms](https://vpndetection.io/terms) and [privacy policy](https://vpndetection.io/privacy).

- **Scopes.** A key carries `ip.lookup` (the lookups) and `db.download` (the `databases.*` routes). The account, organization and `apiKeys.*` routes need an OAuth scope (`account.read`, `org.read`, `apikeys.read`, `apikeys.manage`, `apikeys.reveal`) that an API key cannot hold: with a key they answer 403 `FORBIDDEN`. Store an OAuth access token from VPNDetection's authorization server as the key to use them.
- **Plans.** `ip.batch` needs a paid plan; on the free plan a batch of one is answered and anything larger is a 402. A field the plan does not include is absent rather than `false`, so test for presence.
- **Webhooks.** In the console under Database &gt; Delivery, add a webhook destination pointing at your Corsair webhook URL, tick the databases to announce, and give the plugin the destination's signing secret (`whsec_...`) as `webhookSecret` (or store it as the account's webhook signature). Deliveries are checked to the Standard Webhooks spec and refused when older than five minutes.

**What you get:**

- 16 typed API operations
- 1 synced entity (`lookups`) for fast `.search()` / `.list()`
- 4 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/vpndetection better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/vpndetection better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/vpndetection better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/vpndetection better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { vpndetection } from '@corsair-dev/vpndetection';

export const corsair = createCorsair({
	plugins: [
		vpndetection(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the VPNDetection API key before the first call: `pnpm corsair setup --plugin=vpndetection --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
vpndetection()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'vpndetection',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Check whether an IP is a VPN**

```ts
const tenant = corsair.withTenant('acme');
await tenant.vpndetection.api.ip.lookup({ ip: '185.65.135.230' });
```


**`apiKeys.create`**

```ts
const tenant = corsair.withTenant('acme');
await tenant.vpndetection.api.apiKeys.create({});
```


See the full list on the [API](/plugins/vpndetection/api) page.

## Query synced data

Synced entities support `tenant.vpndetection.db.<entity>.search()` and `.list()`: `lookups`.

See [Database](/plugins/vpndetection/database) for filters and operators.

## Webhooks

This plugin registers **4** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/vpndetection/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
