Use **FreshBooks** through Corsair: one client, typed API calls.

FreshBooks has no static API key. The key this plugin uses is an OAuth 2 access token from your own FreshBooks app:

1. Sign in at my.freshbooks.com, open the developer portal (my.freshbooks.com/#/developer), create an app and register an HTTPS redirect URI. Scopes are per resource, `user:<resource>:read|write`.
2. Authorize the app through the OAuth flow (freshbooks.com/api/authentication shows the steps) and exchange the code for a token.
3. Paste the access token into Corsair as the FreshBooks key.

Access tokens last 12 hours. Refresh tokens are single-use and rotate on every refresh, so a stored refresh token goes stale as soon as a newer one is issued. When the access token expires, run the OAuth flow again and paste the new token.

Two ids run the API, both from `users.me`: the `accountId` (such as LJArJ4) for the accounting family (clients, invoices, estimates, expenses, tasks) and the numeric `businessId` for projects and timeEntries. `users.me` surfaces both.

Deliberate non-goals for v1: payments, webhook registrations, and `systems.get` (research scoped them in, this plugin ships the core resources only).

- **Two response families.** The accounting family wraps every answer in `{response: {result}}` and reports errors as `{response: {errors}}`; the projects and timetracking families answer bare with a `meta` paging object. The plugin unwraps both and reports envelope errors as failed calls.
- **Paging.** Accounting lists page from 1; projects pages from 0. `per_page` defaults to 15, and the API silently caps every page at 100 rows.
- **Deletes.** Accounting deletes are soft: the plugin sends `vis_state: 1`, the record stays, and no documented call restores it. `projects.delete` and `timeEntries.delete` remove the data outright. All deletes are marked destructive and irreversible.
- **invoices.sendEmail cannot be unsent.** It emails the client immediately. `invoices.markSent` only flips the status without emailing anyone.
- **Invoice number collisions.** Creating invoices concurrently without `invoice_number` can answer 409; the docs say retrying succeeds, and the plugin retries that case automatically.
- **Webhooks.** FreshBooks can POST event callbacks to your own endpoint (freshbooks.com/api/webhooks), but this plugin does not handle inbound deliveries, so none are registered through it.
- **Unverified accounting surface.** The accounting routes could not be verified against a live account before this build: the API resolves the account id before auth, so every probe with a bogus id hits the same "Account not found" wall. The projects and timetracking routes were proven to exist by probe, and request and response shapes come from the docs examples throughout. File an issue if a live call disagrees with a schema.

**What you get:**

- 38 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/freshbooks better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/freshbooks better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/freshbooks better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/freshbooks better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { freshbooks } from '@corsair-dev/freshbooks';

export const corsair = createCorsair({
	plugins: [
		freshbooks(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the FreshBooks API key before the first call: `pnpm corsair setup --plugin=freshbooks --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
freshbooks()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'freshbooks',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Read the authenticated identity with its ids**

```ts
const tenant = corsair.withTenant('acme');
await tenant.freshbooks.api.users.me({});
```


**Create a client**

```ts
const tenant = corsair.withTenant('acme');
await tenant.freshbooks.api.clients.create({
	accountId: 'LJArJ4',
	client: {
		fname: 'Melville',
		lname: 'DMello',
		email: 'melville@example.com',
		organization: 'Example Ltd',
	},
});
```


See the full list on the [API](/plugins/freshbooks/api) page.
