## Geo

### boundaries

`geo.boundaries`

Read the administrative boundaries a place belongs to, such as its city, county and country

**Risk:** `read`

```ts
await corsair.geoapify.api.geo.boundaries({ lat: 52.5, lon: 13.4, boundaries: ['city', 'country'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | No | A place ID, such as the one a geocode result returned |
| `lat` | `number` | No | Latitude of a point |
| `lon` | `number` | No | Longitude of a point |
| `osm_id` | `number` | No | An OpenStreetMap ID |
| `osm_type` | `N \| W \| R` | No | The OSM type that goes with `osm_id`: node, way or relation |
| `boundaries` | `string[]` | No | Which levels to return, such as `postal_code`, `city` or `country` |
| `lang` | `string` | No | An IETF language tag such as `en` or `de`, which localizes names |
| `region` | `global \| eu` | No | `eu` sends the request to api-eu.geoapify.com, where processing stays in the European Union |

Identify the place by `id`, by `lat`/`lon`, or by `osm_id` with `osm_type`.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `type` | `string` | No | — |
| `features` | `object[]` | Yes | — |

<AccordionGroup>
<Accordion title="features full type">

```ts
{
  type?: string,
  properties?: Record<string, any>,
  geometry?: Record<string, any>,
  bbox?: number[]
}[]
```
</Accordion>
</AccordionGroup>

### matrix

`routing.matrix`

Calculate the time and distance between every source and target, one row per source. A pair with no route carries an error instead

**Risk:** `read`

```ts
await corsair.geoapify.api.routing.matrix({ mode: 'drive', sources: ['52.5,13.4'], targets: ['52.6,13.5'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `mode` | `drive \| truck \| light_truck \| bicycle \| mountain_bike \| road_bike \| scooter \| walk \| hike \| motorcycle \| bus` | Yes | How to travel, which decides every cell of the matrix |
| `sources` | `string[]` | Yes | Starting points as `lat,lon` pairs, one row each |
| `targets` | `string[]` | Yes | Destination points as `lat,lon` pairs, one column each |
| `type` | `balanced \| short \| less_maneuvers` | No | What to optimize for |
| `units` | `metric \| imperial` | No | Units of the answer |
| `avoid` | `string[]` | No | Features to avoid |
| `traffic` | `free_flow \| approximated` | No | How to account for traffic |
| `max_speed` | `number` | No | A speed cap |

A pair with no route carries an `error` and no distance, and the rest of the matrix is still valid.

### route

`routing.route`

Calculate a route between waypoints, with distance, time and optional turn-by-turn steps and geometry

**Risk:** `read`

```ts
await corsair.geoapify.api.routing.route({ waypoints: ['52.5,13.4', '52.6,13.5'], mode: 'drive' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `waypoints` | `string[]` | Yes | The points to route through, as `lat,lon` pairs, such as `52.5,13.4\|52.6,13.5` |
| `mode` | `drive \| truck \| light_truck \| bicycle \| mountain_bike \| road_bike \| scooter \| walk \| hike \| motorcycle \| bus \| approx_transit \| transit` | Yes | How to travel, which decides the roads and paths used |
