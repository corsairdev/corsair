## Files

### download

`files.download`

Download a message attachment stored on the server (/file/&#123;id&#125;) and return the file

**Risk:** `read`

```ts
await corsair.ntfy.api.files.download({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | Yes | Attachment id from a message `attachment.url` (/file/&lt;id&gt;, an extension is allowed) |

Takes the id at the end of `attachment.url` (/file/&lt;id&gt;) and returns the file: text as `text`, other files as base64.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `contentBase64` | `string` | No | The file, base64-encoded. Missing when the file came back as text or contentOmitted is set. |
| `text` | `string` | No | The file as text, in place of contentBase64, when it is a text file (CSV, JSON, Markdown, XML and the like) in UTF-8. |
| `contentType` | `string` | Yes | Media type of the file, for example application/pdf. |
| `byteLength` | `number` | Yes | Size of the file in bytes. |
| `filename` | `string` | No | The file name, when known. |
| `contentOmitted` | `not_requested \| over_limit` | No | Set when the content was left out: the caller did not ask for it, or the file was over the limit. |
| `fileId` | `string` | No | Where the host saved the file. Over the limit it comes in place of the content; a host that keeps every file sets it beside the content too. On Corsair it is a Files id (fil_…): pass it to another app wherever that app takes a file URL, or read a text file or PDF with files.read_text. |

### delete

`messages.delete`

Delete a message by sequence id, sending a delete event to subscribers; the cache entry is removed

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.ntfy.api.messages.delete({ topic: 'mytopic', sequenceId: 'disk-alert' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `topic` | `string` | Yes | Topic name |
| `sequenceId` | `string` | Yes | Sequence id of the message to delete |

Sends a `message_delete` event. A scheduled message that has not gone out is cancelled and removed from the server; a delivered one stays cached with the delete event after it, and clients that support it remove the notification. Republishing the same `sequenceId` revives the sequence.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | Yes | — |
| `time` | `number` | Yes | Unix seconds |
| `expires` | `number \| null` | No | Unix seconds the cache entry expires |
| `event` | `message_delete` | Yes | — |
| `topic` | `string` | Yes | — |
| `sequence_id` | `string \| null` | No | — |

### poll

`messages.poll`

Read cached messages from one or more topics, optionally including scheduled ones, with since/filters

**Risk:** `read`

```ts
await corsair.ntfy.api.messages.poll({ topic: 'mytopic', since: '10min' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `topic` | `string` | Yes | Topic name, or a comma-separated list of up to 150 topics, [-_A-Za-z0-9]&#123;1,64&#125; each |
| `since` | `string \| number` | No | Read messages since: a duration ("10min"), unix seconds, a message id, "all" (default), or "latest" |
| `scheduled` | `boolean` | No | Include scheduled (undelivered) messages |
| `id` | `string` | No | Only the message with this id |
| `message` | `string` | No | Filter by message text |
| `title` | `string` | No | Filter by title |
| `priority` | `(number \| min \| low \| default \| high \| urgent)[]` | No | Only these priorities (OR filter) |
| `tags` | `string[]` | No | Only messages with all of these tags (AND filter) |

Reads the server-side cache (12h on ntfy.sh, 10 MB replay cap per topic). Poll filters: `message`, `title`, `id` match text; `priority` is an OR list, `tags` an AND list. A multi-topic comma list (up to 150 topics) interleaves by time.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `messages` | `object[]` | Yes | — |

### send

`messages.send`

Publish a notification to a topic; every subscriber gets a push, so the send cannot be undone

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.ntfy.api.messages.send({ topic: 'mytopic', message: 'Disk space is low at 5.1 GB', title: 'Low disk space alert', priority: 4, tags: ['warning', 'cd'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `topic` | `string` | Yes | Topic name, [-_A-Za-z0-9]&#123;1,64&#125; |
| `message` | `string` | No | Notification body; the server default is "triggered" |
| `title` | `string` | No | Notification title |
| `priority` | `number \| min \| low \| default \| high \| urgent` | No | Priority as 1-5 or min\|low\|default\|high\|urgent |
| `tags` | `string[]` | No | Emoji tags, e.g. ["warning","skull"] |
| `click` | `string` | No | URL opened when the notification is clicked |
| `markdown` | `boolean` | No | Render the message as markdown |
| `actions` | `object[]` | No | Up to 3 action buttons |
| `delay` | `string` | No | Delayed delivery, e.g. "30min" or "9am"; ntfy.sh accepts 10s to 3d. Cancel before delivery with messages.delete |
| `icon` | `string` | No | URL of a JPEG or PNG shown as the notification icon |
| `attach` | `string` | No | URL of a file to attach (the server does not download it) |
| `filename` | `string` | No | File name for the `attach` URL |
| `email` | `string` | No | Also email the notification to this address (the server must have email sending configured; counts against the daily email limit) |
| `call` | `string` | No | Also phone this verified number (or "yes" for the first one) and read the message out; needs a tier with calls |
| `cache` | `boolean` | No | false: deliver to current subscribers only, do not cache |
| `firebase` | `boolean` | No | false: do not forward to Firebase (Android app without instant delivery) |
| `sequenceId` | `string` | No | Optional sequence id, [-_A-Za-z0-9]&#123;1,64&#125;; publishing again with the same id updates (replaces) the message on subscribers |

Publishes as JSON to the server root. `email` and `call` also email or phone someone (servers with those features). `message` defaults to 'triggered' server-side. `delay` accepts 10s to 3d on ntfy.sh; self-hosted servers may differ.
