Use **ntfy** through Corsair: one client, typed API calls.

Create an access token at https://ntfy.sh/account under Manage access tokens, then Create access token. The token starts with `tk_` and is shown once. Corsair authenticates every call, and ntfy.sh rejects any bad Authorization header with 401 even on public topics, so a token is required even to read public ones. Things to know before you send:

- **Real pushes.** `messages.send` delivers a real push notification to every subscriber of the topic. On ntfy.sh a visitor can send 250 messages per rolling 24 hours and has a 60-request burst limit; the plugin retries 429s with backoff, honoring Retry-After.
- **Sends cannot be undone.** `messages.send` and `messages.update` both notify subscribers; neither can be recalled. Failed sends are never replayed automatically, because a retry after a timeout can duplicate a notification.
- **Sequences.** Publishing with `sequenceId` gives the message a stable id: publishing again with the same id updates it (the server keeps both versions), `messages.clear` marks it read and dismissed, and `messages.delete` deletes it and cancels a scheduled delivery before it goes out.
- **Polling, not webhooks.** ntfy has no inbound webhooks here: `messages.poll` reads the topic cache as NDJSON and returns the messages with `event: "message"`. An unknown topic polls to an empty list, not an error. Use `since` (a duration like `10min`, unix seconds, a message id, `all` or `latest`) as the cursor, and `scheduled: true` to list undelivered scheduled messages.
- **Priorities and actions.** `priority` takes 1-5 or min|low|default|high|urgent; responses always use ints and omit the field at default. `actions` takes up to 3 buttons of type view, http, broadcast or copy; the server assigns each an id. http actions default to POST.
- **Delays.** `delay` takes a duration or time like `30min` or `9am`; ntfy.sh accepts 10 seconds to 3 days. The message sits undelivered until its time; its `time` field is the future delivery time.
- **Account view.** `account.usage` reads your tier limits and used/remaining counters with the daily reset time. `server.health` and `server.stats` read server-wide values and need no special rights.

- 8 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/ntfy better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/ntfy better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/ntfy better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/ntfy better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { ntfy } from '@corsair-dev/ntfy';

export const corsair = createCorsair({
	plugins: [
		ntfy(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the ntfy API key before the first call: `pnpm corsair setup --plugin=ntfy --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
ntfy()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'ntfy',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Poll a topic**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ntfy.api.messages.poll({ topic: 'mytopic', since: '10min' });
```


**Send a notification**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ntfy.api.messages.send({
	topic: 'mytopic',
	message: 'Disk space is low at 5.1 GB',
	title: 'Low disk space alert',
	priority: 4,
	tags: ['warning', 'cd'],
});
```


See the full list on the [API](/plugins/ntfy/api) page.
