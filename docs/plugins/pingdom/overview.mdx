Use **Pingdom** through Corsair: one client, typed API calls.

Authenticate with an API token generated inside My Pingdom; the plugin sends it as an Authorization Bearer token. Every call goes against https://api.pingdom.com/api/3.1. Answers are bare objects keyed by resource (&#123;checks: […], check: &#123;…&#125;, message: …&#125;); errors carry &#123;error: &#123;statuscode, statusdesc, errormessage&#125;&#125;. Timestamps are UNIX seconds everywhere (from/to filters, lasttesttime, maintenance windows).
checks.create takes name, host and type plus type-specific settings in typeSettings as flat body fields (url/encryption/port for http, stringtoexpect for tcp, nameserver/expectedip for dns, …) — the docs list them per type. resolution is one of 1, 5, 15, 30 or 60 minutes. checks.updateMulti pauses or re-times every check at once. tools.runSingle performs a one-off test without creating a check.
Maintenance windows silence alerts for chosen checks, teams or contacts; recurrence is none, daily, weekly or monthly, and only future from/to values are allowed (use 1 for the current timestamp). Deleting checks, teams, contacts or maintenance windows cannot be undone.
The transaction-check (/tms) group and traceroute are documented by Pingdom but not part of this plugin. Every operation is described in the official reference: https://docs.pingdom.com/api/

**What you get:**

- 40 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/pingdom better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/pingdom better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/pingdom better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/pingdom better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { pingdom } from '@corsair-dev/pingdom';

export const corsair = createCorsair({
	plugins: [
		pingdom(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Pingdom API key before the first call: `pnpm corsair setup --plugin=pingdom --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
pingdom()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'pingdom',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List checks**

```ts
const tenant = corsair.withTenant('acme');
await tenant.pingdom.api.checks.list({ includeTags: true });
```


**Create an HTTP check**

```ts
const tenant = corsair.withTenant('acme');
await tenant.pingdom.api.checks.create({ name: 'api', host: 'example.com', type: 'http' });
```


See the full list on the [API](/plugins/pingdom/api) page.
