## Branches

### list

`branches.list`

List a repository's branches with their latest commit and protection status

**Risk:** `read`

```ts
await corsair.gitea.api.branches.list({ owner: 'gitea', repo: 'tea' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `owner` | `string` | Yes | The owner (user or org) of the repository. |
| `repo` | `string` | Yes | The repository name. |
| `q` | `string` | No | Only branches whose name contains this string. |
| `page` | `number` | No | Page number of results to return (1-based). Defaults to 1. |
| `limit` | `number` | No | Page size of results, at most 50 (the server-side cap). Defaults to 50. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `branches` | `object[]` | Yes | — |
| `page` | `number` | Yes | — |
| `limit` | `number` | Yes | — |

## Commits

### list

`commits.list`

List a repository's commits, newest first, optionally from a ref, path or time window; a repository with no commits answers an error rather than an empty list

**Risk:** `read`

```ts
await corsair.gitea.api.commits.list({ owner: 'gitea', repo: 'tea', sha: 'main', limit: 10 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `owner` | `string` | Yes | The owner (user or org) of the repository. |
| `repo` | `string` | Yes | The repository name. |
| `sha` | `string` | No | Branch or tag name, or a commit SHA, to start listing from. |
| `path` | `string` | No | Only commits touching this file path. |
| `since` | `string` | No | Only commits made at or after this time. |
| `until` | `string` | No | Only commits made at or before this time. |
| `stat` | `boolean` | No | Include add and delete counts per commit. |
| `verification` | `boolean` | No | Include signature verification per commit. |
| `files` | `boolean` | No | Include the list of affected files per commit. |
| `page` | `number` | No | Page number of results to return (1-based). Defaults to 1. |
| `limit` | `number` | No | Page size of results, at most 50 (the server-side cap). Defaults to 50. |
| `not` | `string` | No | Exclude commits reachable from this ref (the API names the parameter `not`). |

Answers 409 with the provider message when the repository has no commits; the plugin leaves it an error rather than an empty page. `since` and `until` are RFC3339; the `not` field maps to the query parameter of that name and excludes commits reachable from the given ref.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `commits` | `object[]` | Yes | — |
| `page` | `number` | Yes | — |
| `limit` | `number` | Yes | — |

**Risk:** `write`

### get

`issues.get`

Get one issue or pull request by its number, including labels, assignees and the comment count

**Risk:** `read`

```ts
await corsair.gitea.api.issues.get({ owner: 'gitea', repo: 'tea', index: 1 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `owner` | `string` | Yes | The owner (user or org) of the repository. |
| `repo` | `string` | Yes | The repository name. |
| `index` | `number` | Yes | The issue's `number` (shown in the issue URL), not its global `id`. |

`index` is the issue NUMBER shown in the URL, never the global `Issue.id` (number 1 and id 31370 on the probe differ). Unset fields arrive as JSON `null`, including `assignees`, `closed_at`, `milestone` and `pull_request`; `pull_request` is non-null when the row is a pull request. `content_version` is the optimistic-lock token to send back on `issues.update`.

## Webhooks

### create

`webhooks.create`

Register a webhook on a repository: a target URL and payload type, the events to subscribe, and an optional signing secret. Deliveries are sent by Gitea to that URL; this plugin does not receive them

**Risk:** `write`

```ts
await corsair.gitea.api.webhooks.create({ owner: 'gitea', repo: 'tea', type: 'gitea', config: { url: 'https://receiver.example.com/gitea', content_type: 'json' }, events: ['push'], active: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `owner` | `string` | Yes | The owner (user or org) of the repository. |
| `repo` | `string` | Yes | The repository name. |
| `type` | `dingtalk \| discord \| gitea \| gogs \| msteams \| slack \| telegram \| feishu \| wechatwork \| packagist` | Yes | Which payload format the target expects, e.g. gitea, slack or discord. |
| `config` | `Record<string, string>` | Yes | Target settings. `url` (delivery target) and `content_type` (json or form) are required; a `secret` key sets the HMAC signing secret and is never echoed back. |
| `active` | `boolean` | No | Whether the hook triggers on events. Gitea creates hooks inactive when this is omitted. |
| `events` | `string[]` | No | Event names to subscribe, as named in the repository's webhook settings (for example push, issue_events, pull_request_events). Empty subscribes push only. |
| `name` | `string` | No | Display name of the hook. |
| `authorization_header` | `string` | No | Sent as the Authorization header on every delivery. |
| `branch_filter` | `string` | No | Glob pattern restricting which branches trigger push events. |

`type` accepts dingtalk, discord, gitea, gogs, msteams, slack, telegram, feishu, wechatwork or packagist, and `config` must carry `url` and `content_type` (json or form); a `secret` key sets the HMAC signing secret and is never echoed back on reads. Gitea creates hooks inactive unless `active` is true, and an omitted `events` subscribes push only.
