This plugin manages repositories, branches, commits, issues, comments, releases and webhook registrations through each account's own instance. Use **Gitea** through Corsair: one client, typed API calls.

Gitea is self-hosted, so each connected account stores two things: the API token and the `instance_url` of the Gitea site it belongs to (for example `https://gitea.com` or a self-hosted `https://git.example.com`, with or without `/api/v1`). Tokens are created in the instance UI under `user/settings/applications` with `read:` and `write:` scopes over repository and issue, and are sent as `Authorization: token <api_key>`, the literal word `token` rather than Bearer. SDK users can pass `instanceUrl` in the plugin options instead of storing it. Calls fail with a connect prompt until both are set.
Lists are paged with `page` (1-based) and `limit`; the server caps pages at 50 items, and the plugin sends 50 when `limit` is omitted, so each list result echoes the `page` and `limit` it fetched and callers page by stepping `page` until a page comes back short. `comments.list` is the one unpaged route and returns every comment on an issue. `commits.list` answers an error rather than an empty list on a repository with no commits. The issues list returns pull requests too; pass `type: 'issues'` to exclude them and read `pull_request` on each row to tell them apart.

**What you get:**

- 18 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/gitea better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/gitea better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/gitea better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/gitea better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { gitea } from '@corsair-dev/gitea';

export const corsair = createCorsair({
	plugins: [
		gitea(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Gitea API key before the first call: `pnpm corsair setup --plugin=gitea --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
gitea()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'gitea',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Get a repository**

```ts
const tenant = corsair.withTenant('acme');
await tenant.gitea.api.repos.get({ owner: 'gitea', repo: 'tea' });
```


**Create an issue**

```ts
const tenant = corsair.withTenant('acme');
await tenant.gitea.api.issues.create({
	owner: 'gitea',
	repo: 'tea',
	title: 'Release notes cover the breaking change',
	body: 'The 2.0 migration guide does not mention the renamed config keys.',
});
```


See the full list on the [API](/plugins/gitea/api) page.
