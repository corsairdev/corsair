Use **Gitea** through Corsair: one client, typed API calls, and incoming webhooks.

Gitea is self-hosted, so each account stores two things: an access token
and the `instance_url` of the site it belongs to (`https://gitea.com`,
`https://codeberg.org` or your own `https://git.example.com`, with or
without `/api/v1`). Forgejo and Codeberg serve the same API v1, so the
plugin works there too; a route an older or forked server lacks answers
404 `page not found`. Create the token at
`<instance>/user/settings/applications` with the scopes you need
(read:/write: repository, issue, organization, user, notification,
package, misc, and admin for the site-admin routes); it is sent as
`Authorization: token <token>`. SDK users can pass `instanceUrl` in the
plugin options instead of storing it.

- **Repository routes** take `owner` and `repo`. Branches, refs, tags and
file paths keep their slashes (`feature/login`, `docs/README.md`).
- **Lists** page with `page` (1-based) and `limit`; Gitea caps a page at
50 and the plugin sends 50 when `limit` is left out. Paged lists return
`{ items, next_page }`, with `next_page` set while a page comes back full.
- **Files.** `contents.get` returns a file's metadata and base64 content;
`contents.raw`, `contents.media`, `repos.downloadArchive` and the Actions
log and artifact downloads return the bytes as a file. Diffs, patches,
signing keys and rendered markdown come back as `{ text }`.
- **Risk.** Every delete is `destructive`, as are site-admin changes to
users and organizations, merging a pull request, moving a branch to another
commit (`branches.setCommit`), applying a patch, transfers, renaming an
organization and overwriting Actions secrets. `admin.*` needs a site-admin
token.
- **Webhooks.** Register one with `webhooks.create` (or `orgs.hooks.create`,
`user.hooks.create`, `admin.hooks.create`) using `type: gitea` and a
`config.secret`, point it at your Corsair webhook URL, and give the plugin
the same secret as `webhookSecret` (or store it as the account's webhook
signature). Deliveries are checked against `X-Gitea-Signature` (HMAC-SHA256
of the body) and routed by `X-Gitea-Event-Type` to `push`, `refCreated`,
`refDeleted`, `fork`, `issues`, `issueComment`, `pullRequest`,
`pullRequestReview`, `release`, `wiki`, `repository`, `status`,
`workflowRun`, `workflowJob` and `package`.
- Not wrapped: four routes the swagger marks deprecated (each has a
replacement), and `users.tokens` list, create and delete, which Gitea only
accepts with the account password (BasicAuth), not a token.

**What you get:**

- 530 typed API operations
- 15 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/gitea better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/gitea better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/gitea better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/gitea better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { gitea } from '@corsair-dev/gitea';

export const corsair = createCorsair({
	plugins: [
		gitea(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Gitea API key before the first call: `pnpm corsair setup --plugin=gitea --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
gitea()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'gitea',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Get a repository**

```ts
const tenant = corsair.withTenant('acme');
await tenant.gitea.api.repos.get({ owner: 'gitea', repo: 'tea' });
```


**Create an issue**

```ts
const tenant = corsair.withTenant('acme');
await tenant.gitea.api.issues.create({
	owner: 'gitea',
	repo: 'tea',
	title: 'Release notes cover the breaking change',
	body: 'The 2.0 migration guide does not mention the renamed config keys.',
});
```


See the full list on the [API](/plugins/gitea/api) page.

## Webhooks

This plugin registers **15** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/gitea/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
