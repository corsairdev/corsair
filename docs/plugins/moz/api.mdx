## Anchor Text

### list

`anchorText.list`

Use this endpoint to get data about anchor text used to link to a specified site. Costs rows per result returned.

**Risk:** `read`

```ts
await corsair.moz.api.anchorText.list({ site_query: { query: 'moz.com', scope: 'domain' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `site_query` | `object` | Yes | A SiteQuery provides a target URL along with a scope to define how the query is parsed. |
| `offset` | `object` | No | Defines the input parameters used to retrieve anchor text data for a given target. It allows controlling the pagination, and number of results returned. |

## Competitors

### fetch

`competitors.fetch`

Get the top ranking competitors for a given target site, sorted by rivalry descending. Asynchronous: answers with an async_call to poll with jobs.lookup. Draws on the mozscape rows quota.

**Risk:** `read`

```ts
await corsair.moz.api.competitors.fetch({ target_query: { query: 'moz.com', scope: 'domain', locale: 'en-US' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `target_query` | `object` | Yes | The target site to fetch competitors for. |

`data.site.competitor.fetch` is asynchronous: the answer is an
async_call receipt, and the competitors arrive through jobs.lookup once
the status is complete. It spends the mozscape quota bucket.

<AccordionGroup>
<Accordion title="target_query full type">

```ts
{
  query: string,
  scope: domain | subdomain | subfolder,
  locale: en-US | en-GB | en-CA | en-AU
```

</AccordionGroup>

## Jobs

### lookup

`jobs.lookup`

Fetch an `async_call` by ID to retrieve the result or error. Free (no quota).

**Risk:** `read`

```ts
await corsair.moz.api.jobs.lookup({ id: (await corsair.moz.api.test.pingAsync({ message: 'hi' })).async_call?.id ?? '' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | Yes | The ID of the `async_call` to lookup. This is the `async_call.id` returned by the asynchronous action that started the request. |

`async.call.lookup` is free and safe to poll every five seconds. Pass
the `async_call.id` from the async method's response (above, a
test.pingAsync call). A
completed call carries exactly one of async_call.result and
async_call.error. Poll within the current `ttl`: once a completed call
is first retrieved, Moz keeps it for twenty more seconds, so use the
result or error from that first completed response.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `async_call` | `object \| null` | No | — |

<AccordionGroup>
<Accordion title="async_call full type">

```ts
{
  id?: string | null,
  action?: string | null,
  status?: string | null,
  ttl?: number | null,
  result?: Record<string, any> | null,
  error?: {
    message?: string | null,
    code?: number | null,
    status?: number | null,
    data?: {
      explanation?: string | null,
      issue?: string | null,
      key?: string | null,
      value?: Record<string, any> | null
    } | null
  } | null
} | null
```
</Accordion>
</AccordionGroup>
