Use **Moz** through Corsair: one client, typed API calls.

Generate an API token on the Moz API dashboard
(https://api.moz.com) and Corsair sends it in the x-moz-token header on
every call. The Moz API is JSON-RPC 2.0: one endpoint
(https://api.moz.com/jsonrpc), one POST per operation, with the method
name in the request body.

- **Quota is per row.** Every method reports the rows it consumed in the
response body, and quota.lookup reads the remaining balance for free.
Metrics and link methods charge api.limits.data.rows (one row per call or
per returned result); the competitor fetch draws on the separate
api.limits.mozscape.rows bucket.
- **Errors are JSON-RPC envelopes** with a stable `code`: -32651 is a bad
token (401), -32670 is exhausted quota (403), -32658 and -32650 are the
two 429 rate limits (a per-method one with Retry-After and an edge one
without). The plugin retries the 429s and 5xx on reads and never retries
auth or quota errors.
- **The competitor lookup is asynchronous.** competitors.fetch answers
with an async_call receipt; follow it with jobs.lookup until the status
is complete, then read async_call.result (or .error). Poll no more than
once every five seconds; lookups are free.
- **Paging is token-based.** List methods take offset.limit (1-50) and an
optional offset.token; the response's offset.token is null when there is
no next page.
- **Nothing writes.** The Moz data API is read-only, so every operation
here is a read.

**What you get:**

- 11 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/moz better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/moz better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/moz better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/moz better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { moz } from '@corsair-dev/moz';

export const corsair = createCorsair({
	plugins: [
		moz(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Moz API key before the first call: `pnpm corsair setup --plugin=moz --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
moz()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'moz',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Read site metrics for moz.com**

```ts
const tenant = corsair.withTenant('acme');
await tenant.moz.api.metrics.fetch({
	site_query: { query: 'moz.com', scope: 'domain' },
});
```
