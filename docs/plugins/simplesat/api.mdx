### search

`answers.search`

Search answers by date range and filters such as sentiment, across every survey

**Risk:** `read`

```ts
await corsair.simplesat.api.answers.search({ start_date: '2024-01-01T00:00:00Z', filters: [{ key: 'sentiment', values: ['positive'], comparison: 'is' }] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `page` | `number` | No | Page number, from 1. |
| `page_size` | `number` | No | Results per page, up to 250. Defaults to 50. |
| `next` | `string` | No | The `next` path from the previous page. It replaces the other filters, because Simplesat already encoded them into it. |
| `start_date` | `string` | No | ISO 8601. |
| `end_date` | `string` | No | ISO 8601. |
| `filters` | `object[]` | No | — |

A POST because it takes a filter list and date range, but its next links are followed with a GET.

<AccordionGroup>
<Accordion title="filters full type">

```ts
{
  key: string,
  values: string[],
  attribute?: string,
  comparison: string
}[]
```
</Accordion>
</AccordionGroup>



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `next` | `string \| null` | No | Path of the next page, or null on the last one. Pass it back as `next`. |
| `previous` | `string \| null` | No | — |
| `count` | `number \| null` | No | Total matching records. |
| `results` | `object[]` | Yes | — |

<AccordionGroup>
<Accordion title="results full type">

```ts
{
  id?: number | null,
  question?: {
    id?: number | null,
    text?: string | null,
    metric?: string | null
  } | null,
  choice?: string | null,
  choice_label?: string | null,

  comment?: string | null,
  follow_up_answer?: string | null,
  follow_up_answer_choice?: string | null,
  follow_up_answer_choices?: string[] | null,

    id?: number | null,
    name?: string | null
  } | null
}[]
```
</Accordion>
</AccordionGroup>

## Customers

### bulk

`customers.bulk`

Queue many customer upserts in one request. The answer carries a request_id rather than the stored records, because the write is queued

**Risk:** `write`

```ts
await corsair.simplesat.api.customers.bulk({ customers: [{ external_id: '1', email: 'a@example.com' }, { external_id: '2', email: 'b@example.com' }] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `customers` | `object[]` | Yes | The customers to create or update. |

Queued rather than applied: the answer carries a request_id and a message, not the stored records.

**Risk:** `write`

```ts
await corsair.simplesat.api.customers.create({ external_id: '12345', email: 'tester@simplesat.io', name: 'Tester McTestFace' });
```

| `language` | `string \| null` | No | — |
| `tags` | `string[] \| null` | No | — |
| `custom_attributes` | `Record<string, any> \| null` | No | — |

**Risk:** `read`

```ts
await corsair.simplesat.api.customers.list({ page_size: 50, subscribed: true });
```

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `page` | `number` | No | Page number, from 1. |
| `page_size` | `number` | No | Results per page, up to 250. Defaults to 50. |
| `next` | `string` | No | The `next` path from the previous page. It replaces the other filters, because Simplesat already encoded them into it. |

| `created_before` | `string` | No | ISO 8601. |
| `modified_after` | `string` | No | ISO 8601. |
| `modified_before` | `string` | No | ISO 8601. |
| `subscribed` | `boolean` | No | — |

Pass the path from a previous page as `next`. Every list answers `{ next, previous, count, results }`, and `next` is a same-host path the plugin checks before use.
