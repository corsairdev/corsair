## Account

### status

`account.status`

The plan, whether the account is active, and the quota total, used and remaining, all in bytes

**Risk:** `read`

```ts
await corsair.krakenio.api.account.status({});
```

**Input:** _empty object_

Quota figures are in bytes.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `boolean` | Yes | — |
| `active` | `boolean \| null` | No | Whether the account may optimize. |
| `plan_name` | `string \| null` | No | — |
| `quota_total` | `number \| null` | No | Bytes. |
| `quota_used` | `number \| null` | No | Bytes. |
| `quota_remaining` | `number \| null` | No | Bytes. |

## Upload

### optimize

`upload.optimize`

Optimize a file sent as base64 in the request body, with the same resize and conversion options. Spends quota

**Risk:** `write`

```ts
await corsair.krakenio.api.upload.optimize({ data: 'aGVsbG8=', filename: 'header.jpg', wait: true, convert: { format: 'webp' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `wait` | `boolean` | No | Hold the connection open and answer with the result. Without it a `callback_url` is required. |
| `callback_url` | `string` | No | Kraken posts the result here instead of answering in-line. |
| `lossy` | `boolean` | No | `true` for lossy, `false` for lossless. Kraken’s default is lossy. |
| `resize` | `object` | No | — |
| `quality` | `number` | No | JPEG quality for a lossy run. Ignored on a lossless one. |
| `auto_orient` | `boolean` | No | Rotate the image according to its EXIF orientation. |
| `preserve_meta` | `(profile \| date \| copyright \| geotag \| orientation)[]` | No | Metadata categories to keep. Anything left out is stripped. |
| `convert` | `object` | No | — |
| `data` | `string` | Yes | The file as a base64 string. Kraken also accepts a multipart upload, which this plugin does not wrap because it sends a JSON body. |
| `filename` | `string` | No | A name for the upload, such as `header.jpg`. |

Sends the file as base64 in the JSON body, because Kraken’s multipart form is not wrapped here.

<Accordion title="resize full type">

```ts

  height?: number,

```
</Accordion>

<Accordion title="convert full type">

```ts
}
```
</Accordion>
</AccordionGroup>



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `boolean` | Yes | — |
| `id` | `string \| null` | No | The job ID, for a callback lookup. |
| `message` | `string \| null` | No | — |
| `original_size` | `number \| null` | No | — |
| `kraked_size` | `number \| null` | No | — |
| `saved_bytes` | `number \| null` | No | — |
| `results` | `object \| null` | No | One entry per optimized file. A `wait` call fills this; a callback delivery puts the same shape in its body. |

## Url

### optimize

`url.optimize`

Fetch an image or PDF from a URL and optimize it, optionally resizing, converting, keeping metadata or setting the quality. Spends quota

**Risk:** `write`

```ts
await corsair.krakenio.api.url.optimize({ url: 'https://acme.example/header.jpg', wait: true, lossy: true, quality: 80, resize: { width: 800, strategy: 'fit' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `wait` | `boolean` | No | Hold the connection open and answer with the result. Without it a `callback_url` is required. |
| `callback_url` | `string` | No | Kraken posts the result here instead of answering in-line. |
| `lossy` | `boolean` | No | `true` for lossy, `false` for lossless. Kraken’s default is lossy. |
| `resize` | `object` | No | — |
| `quality` | `number` | No | JPEG quality for a lossy run. Ignored on a lossless one. |
| `auto_orient` | `boolean` | No | Rotate the image according to its EXIF orientation. |
| `preserve_meta` | `(profile \| date \| copyright \| geotag \| orientation)[]` | No | Metadata categories to keep. Anything left out is stripped. |
| `convert` | `object` | No | — |
| `url` | `string` | Yes | The publicly reachable image or PDF to fetch and optimize. |

Needs `wait: true` or a `callback_url`. Spends quota. A per-file failure appears in `results`, and a whole-request refusal arrives as a 200 with `success: false`, which the plugin throws on.
