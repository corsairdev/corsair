Use **Melo** through Corsair: one client, typed API calls.

**Melo is the product, Stream Estate is the API.** melo.io is the French real-estate aggregator; its developer API is served from `https://api.stream.estate` and documented at docs.stream.estate (docs.melo.io redirects there). The plugin calls `https://api.stream.estate` and authenticates with the `X-API-KEY` header. Create the key on the API Keys page of the Stream Estate console (stream.estate/console). The API is paid: a subscription, or a trial that asks for a card.

**The live suite has not run.** `api.test.ts` needs `MELO_API_KEY` and no key was available when this plugin was built, so every response shape was written from Melo's documentation. The one route that answers without a key, `/public/location-autocomplete`, was checked against the real API, and a wrong key was confirmed to reach Melo and come back as a 401. Everything else is unverified against live traffic:

- the response shape of every operation except `indicators.locations` (the documentation's examples are used as fixtures, and the spec's own types are known to be wrong in places, for example a location `id` that is a string where the spec says integer, which is why output schemas are loose)
- what `searches.update` replaces (it is a PUT, and the plugin sends the whole search)
- the exact answer of `webhooks.simulate`, which the spec leaves undocumented, so the plugin reports `{ sent: true }` on any 2xx
- the rate limit: Melo documents a 429 but no limit and no `Retry-After` header, so the plugin retries a 429 up to three times with a 1s, 2s, 4s backoff and uses a `Retry-After` if one ever arrives
- the update example in the documentation sets a webhook without `notificationEnabled`, which the notification rules in the same spec forbid, so the plugin follows the rules, not the example

**The OpenAPI spec was the source of truth over earlier notes.** The locations route is `/public/location-autocomplete`, the cities route is `/cities`, and the webhook test route is `GET /webhook-tester`. There are 13 operations, exactly the ones in the spec.

Things to know before you call:

- **Filters are IRIs.** `includedCities`, `includedDepartments` and the other place filters take IRIs such as `/departments/77` (Paris; department ids are Melo's own, not INSEE codes), not names. Get them from `indicators.locations` (which needs a key here even though Melo serves the route publicly) or `indicators.cities`.
- **Numbers stand for words.** `transactionType` is 0 for sale and 1 for rent. `propertyTypes` is 0 apartment, 1 house, 2 building, 3 parking, 4 office, 5 land, 6 shop. Inputs are strict, so a misspelled filter throws instead of silently returning unfiltered data.
- **Paging.** `properties.list` and the other collections return the Hydra fields untouched plus a `nextPage` number, or `null` on the last page. Pass it back as `page`. `itemsPerPage` is capped at 30.
- **Saved searches.** `searches.create` and `searches.update` need `title`, `transactionType` and `propertyTypes`. A webhook endpoint needs `notificationEnabled: true`, and an event endpoint also needs at least one `subscribedEvents`. `searches.delete` is irreversible.
- **Webhook deliveries are not handled.** The plugin does not receive webhooks. `webhooks.simulate` is an API call: it asks Melo to send a test `match` (or the event in `eventType`) to an endpoint you give it, so it is a write with a side effect and is never repeated automatically.
- **Content type.** Melo answers `application/ld+json` only when asked for it, so the plugin sends `Accept: application/ld+json` and decodes the body itself. A wrong key answers 401 with the plain text `Authentication failed`.

**What you get:**

- 13 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/melo better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/melo better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/melo better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/melo better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { melo } from '@corsair-dev/melo';

export const corsair = createCorsair({
	plugins: [
		melo(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the API key for each tenant before its first call. A call made with no stored key throws `AuthMissingError`, which may carry a `connectUrl` where the tenant can supply one.

```ts
await corsair.withTenant('acme').melo.keys.set_api_key(process.env.MELO_API_KEY!);
```

Or from the CLI: `pnpm corsair setup --plugin=melo api_key=<key> --tenant=acme`. The key is sent as the `X-API-KEY` header.

```ts
melo()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'melo',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Find the place IRIs for a name**

```ts
const tenant = corsair.withTenant('acme');
await tenant.melo.api.indicators.locations({ query: 'paris' });
```


**Send a test match to a webhook endpoint**

```ts
const tenant = corsair.withTenant('acme');
await tenant.melo.api.webhooks.simulate({ endpoint: 'https://hooks.example.com/melo' });
```
