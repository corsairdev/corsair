Use **Piloterr** through Corsair: one client, typed API calls.

Authenticate with the API key from your Piloterr dashboard; the plugin sends it in the x-api-key header. Every operation is a GET against https://api.piloterr.com and each call costs the credits listed on the endpoint page (account.usage and account.getJob are free). Errors answer &#123;"error": "&lt;message&gt;"&#125;; Piloterr signals rate limits as 401 with a "Rate limit exceeded" message rather than 429, and the plugin retries those with backoff (2s, then 4s). The docs prescribe exponential backoff for 500s only; 400/402/403 are never retried.
The fields global parameter filters the response by comma-separated field names with dot notation. soft_fail and is_async are not part of this plugin (a failed call surfaces as an error with Piloterr's message); poll jobs started elsewhere with account.getJob.
web.crawler and web.webunlocker answer a JSON-encoded HTML string, web.rendering the rendered HTML, and web.screenshot a base64-encoded file. web.webunlocker only works for domains on Piloterr's whitelist. Every operation is described in the official reference: https://docs.piloterr.com/reference

**What you get:**

- 19 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/piloterr better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/piloterr better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/piloterr better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/piloterr better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { piloterr } from '@corsair-dev/piloterr';

export const corsair = createCorsair({
	plugins: [
		piloterr(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Piloterr API key before the first call: `pnpm corsair setup --plugin=piloterr --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
piloterr()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'piloterr',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Enrich a company by domain**

```ts
const tenant = corsair.withTenant('acme');
await tenant.piloterr.api.linkedin.companyInfo({ domain: 'guideflow.com' });
```


**Scrape a Google search**

```ts
const tenant = corsair.withTenant('acme');
await tenant.piloterr.api.google.search({ query: 'best electric cars 2024' });
```
