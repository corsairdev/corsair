Use **WooCommerce** through Corsair: one client, typed API calls, and incoming webhooks.

Each account stores the store's `site_url` (the WordPress address of the
shop, with or without `/wp-json`) and a REST API key pair: the consumer key
as `consumer_key` and the consumer secret as the key. Create one in
WooCommerce → Settings → Advanced → REST API with Read/Write permission
(Read for reports only). Over HTTPS the pair goes as HTTP Basic auth; over
plain HTTP (a local store) the plugin signs each call with OAuth 1.0a, as
WooCommerce requires. A WordPress application password also works: put the
WordPress username in `consumer_key` and the application password as the
key (HTTPS only, except on localhost and `.local`/`.test` hosts, since
Basic auth would cross the network in the clear). SDK users can pass
`siteUrl` and `consumerKey` as options.

- **Lists** page with `page` and `per_page` (up to 100) and return
`{ items, next_page }`: `next_page` is set while a page comes back full
(a full last page is followed by an empty one). With `offset`, `next_page`
is null: page by `offset`.
- **Money** amounts are strings (`"19.99"`), as WooCommerce sends them.
- **Batch** routes take `{ create, update, delete }` with up to 100 records
in all.
- **Risk.** Every delete is `destructive`, as are refunds (the gateway
returns the money unless `api_refund: false`), sending order emails, batch
calls, running system status tools, replacing a zone's locations and
changing a payment gateway. Creating an order takes no payment.
- **Webhooks.** Create one with `webhooks.create` (topic `order.created`,
`product.updated`, `customer.deleted`, `coupon.restored`, or
`action.<hook>`), the Corsair webhook URL as `delivery_url` and a `secret`,
and give the plugin the same secret as `webhookSecret` (or store it as the
account's webhook signature). Deliveries are checked against
`X-WC-Webhook-Signature` (base64 HMAC-SHA256 of the body) and routed by
`X-WC-Webhook-Resource` to `order`, `product`, `customer`, `coupon` and
`action`. The `webhook_id=<id>` ping WooCommerce sends when a webhook is
created is not a store event and isn't routed.
- Not wrapped: the WooCommerce.com marketplace and PayPal Payments callback
routes under wc/v3, the legacy wc/v1 and wc/v2 APIs, the Store API
(wc/store, for storefront carts) and wc-analytics (the admin dashboards).
WordPress content (posts, pages, users) is in the `wordpress` plugin.

**What you get:**

- 155 typed API operations
- 5 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/woocommerce better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/woocommerce better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/woocommerce better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/woocommerce better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { woocommerce } from '@corsair-dev/woocommerce';

export const corsair = createCorsair({
	plugins: [
		woocommerce(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the WooCommerce API key before the first call: `pnpm corsair setup --plugin=woocommerce --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
woocommerce()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'woocommerce',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List processing orders**

```ts
const tenant = corsair.withTenant('acme');
await tenant.woocommerce.api.orders.list({
	status: ['processing'],
	per_page: 20,
});
```


**Create a product**

```ts
const tenant = corsair.withTenant('acme');
await tenant.woocommerce.api.products.create({
	name: 'Corsair Hoodie',
	type: 'simple',
	regular_price: '49.00',
	sku: 'CORSAIR-HOODIE',
	status: 'draft',
});
```


See the full list on the [API](/plugins/woocommerce/api) page.

## Webhooks

This plugin registers **5** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/woocommerce/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
