The Shotstack plugin handles incoming webhooks. Point your provider’s subscription URL at your Corsair HTTP handler (see [Overview](/plugins/shotstack/overview) for setup context and the exact URL shape).

<Info>
**New to Corsair?** See [webhooks](/concepts/webhooks) and [hooks](/concepts/hooks).
</Info>

## Webhook map

- `render` (`render`)
- `serve` (`serve`)
- `source` (`source`)

## HTTP handler setup

```ts app/api/webhook/route.ts
import { processWebhook } from "corsair";
import { corsair } from "@/server/corsair";

export async function POST(request: Request) {
    const headers = Object.fromEntries(request.headers);
    // With multiTenancy, give each tenant its own URL (/api/webhook?tenantId=acme):
    // the query says whose account, secret and hooks handle the delivery.
    const query = Object.fromEntries(new URL(request.url).searchParams);
    // The raw text, not request.json(): signatures are checked over the exact bytes sent.
    const body = await request.text();
    const result = await processWebhook(corsair, headers, body, query);
    if (!result.plugin) {
        return Response.json({ success: false }, { status: 404 });
    }
    // A refusal (bad signature) carries no status and answers 400; a handler
    // that threw comes back with 500, so the sender retries it.
    const status =
        result.response?.success === false ? (result.response.statusCode ?? 400) : 200;
    return Response.json(result.response ?? { success: true }, {
        status,
        headers: result.responseHeaders,
    });
}
```

## Events

## Render

### Render

`render`

A render (renders.create or templates.render with a callback URL) finished: status done or failed, with the output URL. Checked against the API, since Shotstack does not sign callbacks.

**Payload**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `type` | `edit` | Yes | — |
| `action` | `render` | Yes | — |
| `id` | `string` | Yes | The render, source or hosted asset id. |
| `owner` | `string` | Yes | The Shotstack account (owner) id. |
| `status` | `string` | Yes | The job status: done or failed for a render, ready or failed for a source or hosted copy. |
| `url` | `string \| null` | No | Where the output or ingested file is, read back from the API. |
| `error` | `string \| null` | No | Why the job failed, when it did. |
| `completed` | `string \| null` | No | When the job ended (ISO 8601). |
| `poster` | `string \| null` | No | — |
| `thumbnail` | `string \| null` | No | — |



<AccordionGroup>
<Accordion title="Response data full type">

```ts
{
  type: edit,
  action: render,
  id: string,
  owner: string,
  status: string,
  url?: string | null,
  error?: string | null,
  completed?: string | null,
  poster?: string | null,
  thumbnail?: string | null
}
```
</Accordion>
</AccordionGroup>

**`webhookHooks` example**

```ts
shotstack({
    webhookHooks: {
        render: {
            before(ctx, args) {
                return { ctx, args };
            },
            after(ctx, response) {
            },
        },
    },
})
```

## Serve

### Serve

`serve`

The hosting copy of a render output is ready on the Shotstack CDN (sent with render callbacks): the durable CDN URL and the render id. Checked against the API.

**Payload**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `type` | `serve` | Yes | — |
| `action` | `string` | Yes | copy: the hosting copy of an output. |
| `id` | `string` | Yes | The render, source or hosted asset id. |
| `owner` | `string` | Yes | The Shotstack account (owner) id. |
| `status` | `string` | Yes | The job status: done or failed for a render, ready or failed for a source or hosted copy. |
| `url` | `string \| null` | No | Where the output or ingested file is, read back from the API. |
| `error` | `string \| null` | No | Why the job failed, when it did. |
| `completed` | `string \| null` | No | When the job ended (ISO 8601). |
| `render` | `string \| null` | No | The render id the hosted asset came from. |
