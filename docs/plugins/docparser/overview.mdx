Use **Docparser** through Corsair: one client, typed API calls, local DB sync.

Get the secret API key under Account &gt; API in Docparser. It is sent as HTTP Basic with the key as the username and an empty password.
The usual flow: `parsers.list` to find the parser, `documents.fetch` (public URL) or `documents.upload` (base64) to send a document, `documents.status` until `done` is true (parsing takes a minute or more), then `results.get` for the extracted fields. Parsing rules are set up in the Docparser app; the API runs them.
Importing a document uses parsing credits, one per 5 pages, charged only the first time it is parsed (the free trial has 50), so `documents.fetch` and `documents.upload` are destructive. `documents.reparse` costs nothing but replaces the parsed data with a run of the current rules, and `documents.reintegrate` sends the parsed data to the parser's integrations and webhooks again; both are destructive too.
Results come back whole, with every field the parser extracted. Only parser, layout and result metadata (ids, file name, page count, dates) is stored locally; parsed values, media links and document URLs are not stored and stay out of events.

**What you get:**

- 10 typed API operations
- 4 synced entities (`models`, `parsers`, `pings`, `results`) for fast `.search()` / `.list()`

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/docparser better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/docparser better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/docparser better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/docparser better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { docparser } from '@corsair-dev/docparser';

export const corsair = createCorsair({
	plugins: [
		docparser(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Docparser API key before the first call: `pnpm corsair setup --plugin=docparser --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
docparser()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'docparser',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**Get the newest parsed documents**

```ts
const tenant = corsair.withTenant('acme');
await tenant.docparser.api.results.list({ parserId: 'balhnyuzdezt', limit: 20 });
```


**Send an invoice PDF to a parser**

```ts
const tenant = corsair.withTenant('acme');
await tenant.docparser.api.documents.fetch({ parserId: 'balhnyuzdezt', url: 'https://example.com/invoices/inv-1001.pdf', remoteId: 'inv-1001' });
```


See the full list on the [API](/plugins/docparser/api) page.

## Query synced data

Synced entities support `tenant.docparser.db.<entity>.search()` and `.list()`: `models`, `parsers`, `pings`, `results`.

See [Database](/plugins/docparser/database) for filters and operators.
