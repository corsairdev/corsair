## Monitors

### create

`monitors.create`

Create a monitor of any type; the body is checked against the type, so a PORT monitor needs a port and a HEARTBEAT one takes no URL

**Risk:** `write`

```ts
await corsair.uptimerobot.api.monitors.create({ friendlyName: 'Acme storefront', type: 'HTTP', interval: 300, url: 'https://shop.acme.example' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `friendlyName` | `string` | Yes | — |
| `type` | `HTTP \| KEYWORD \| PING \| PORT \| HEARTBEAT \| DNS \| API \| UDP \| VISUAL_COMPARISON \| THIRD_PARTY_SERVICE` | Yes | — |
| `interval` | `number` | Yes | Seconds between checks. The free plan allows no less than 300. |
| `url` | `string` | No | The URL, hostname or IP to check; for DNS the resolver. Omitted only for HEARTBEAT. |
| `port` | `number` | No | Required for PORT and UDP monitors, rejected otherwise. |
| `portAlertCondition` | `CLOSED \| OPEN` | No | PORT only. Whether a closed port or an open one is the alert. |
| `keywordType` | `ALERT_EXISTS \| ALERT_NOT_EXISTS` | No | KEYWORD only. Alert when the keyword is present or absent. |
| `keywordCaseType` | `CaseSensitive \| CaseInsensitive` | No | KEYWORD only. |
| `keywordValue` | `string` | No | KEYWORD only. Text to look for in the response body. |
| `timeout` | `number` | No | Seconds to wait. Required for KEYWORD monitors. |
| `gracePeriod` | `number` | No | HEARTBEAT only. Seconds of lateness allowed before alerting. |
| `groupId` | `number` | No | — |
| `tagNames` | `string[]` | No | — |
| `maintenanceWindowsIds` | `number[]` | No | — |
| `assignedAlertContacts` | `object[]` | No | Who is alerted. Threshold and recurrence are paid-plan only. |
| `customFields` | `Record<string, string>` | No | Up to 20 key/value pairs. Paid plans only. |
| `responseTimeThreshold` | `number` | No | — |
