## Departments

### create

`departments.create`

Create a department with a name that is unique in the company

**Risk:** `write`

```ts
await corsair.talenthr.api.departments.create({ name: 'Engineering' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | The name, up to 255 characters. TalentHR requires it to be unique in its collection. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `number` | Yes | — |
| `name` | `string \| null` | No | — |
| `object_type` | `string \| null` | No | — |
| `field_data` | `object \| null` | No | — |

<AccordionGroup>
<Accordion title="field_data full type">

```ts
{
  address?: string | null,
  is_remote?: boolean | null
} | null
```
</Accordion>
</AccordionGroup>

### directory

`employees.directory`

List employees with their job, contact and org details, filtered and paged; the response carries the total match count

**Risk:** `read`

```ts
await corsair.talenthr.api.employees.directory({ limit: 50, offset: 0, filter: 'department_id:6' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `limit` | `number` | No | Rows per page. Defaults to 10; TalentHR caps it at 100. |
| `offset` | `number` | No | Rows to skip. Defaults to 0. |
| `filter` | `string` | No | Filter IDs joined by commas, in the form `field:id` (for example `department_id:6,division_id:13`). TalentHR lists the filter IDs at `GET /directory/filters`, which this plugin does not wrap; the IDs come from the division, department, location and job title lists. |
| `customFields` | `string` | No | Custom field slugs joined by commas, as set up in TalentHR (its `GET /custom-fields`, which this plugin does not wrap). TalentHR returns them under each row. |

limit defaults to 10 and caps at 100; filter takes field:id pairs separated by commas, with IDs from the directory filters endpoint.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `total` | `number` | Yes | — |
| `rows` | `object[]` | Yes | — |

### hire

`employees.hire`

Create an employee with a hire date, employment status and optional job, pay and emergency contact records; TalentHR emails the new employee unless prevent_email is set

**Risk:** `destructive`

```ts
await corsair.talenthr.api.employees.hire({ first_name: 'Ada', last_name: 'Lovelace', email: 'ada@example.com', hire_date: '2026-12-01', employment_status: { employment_status_id: 1 }, reports_to_employee_id: 15 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `first_name` | `string` | Yes | The employee first name. |
| `last_name` | `string` | Yes | The employee last name. |
| `email` | `string` | Yes | The work email. TalentHR requires a valid address that no other employee uses. |
| `hire_date` | `string` | Yes | The hire date. |
| `employment_status` | `object` | Yes | The starting status. Get the ID from `referenceData.employmentStatuses`. |
| `reports_to_employee_id` | `number \| null` | Yes | The manager employee ID. Send `null` to make this employee the head of the company. |
| `job_record` | `object` | No | Job title, location, division and department. Get each ID from its list route. |
| `compensation_record` | `object` | No | The initial pay record. |
| `emergency_contact` | `object` | No | The emergency contact. |
| `employee_number` | `string` | No | — |
| `prevent_email` | `boolean` | No | When true, TalentHR sends no welcome email. |

reports_to_employee_id is required and accepts null for the head of the company; prevent_email stops the welcome email.

### rehire

`employees.rehire`

Return a terminated employee to active status from a new hire date, with a manager and employment status; TalentHR sends a rehire email unless prevent_email is set

**Risk:** `destructive`


| `employeeId` | `number` | Yes | The employee ID, from `employees.directory` or `employees.hire`. |
| `hire_date` | `string` | Yes | The new hire date. It must fall after the latest termination date. |
| `reports_to_employee_id` | `number` | Yes | The manager employee ID. It must be active and not this employee. |
| `employment_status` | `object` | Yes | The status the employee returns to. |
| `job_record` | `object` | No | — |
| `prevent_email` | `boolean` | No | When true, TalentHR sends no rehire notification email. |

hire_date must fall after the latest termination date, and reports_to_employee_id must be an active employee.
