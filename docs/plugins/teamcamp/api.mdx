## Account

### verify

`account.verify`

Read the workspace the key belongs to, which also confirms the key is valid

**Risk:** `read`

```ts
await corsair.teamcamp.api.account.verify({});
```

**Input:** _empty object_

Reads the workspace the key belongs to. A bad key answers 403 here, which is the one call where that status really does mean the key.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspaceId` | `string` | Yes | — |
| `workspaceName` | `string \| null` | No | — |
| `createdBy` | `string \| null` | No | — |

## Projects

### create

`projects.create`

Create a project, optionally from a template and with a customer and dates

**Risk:** `write`

```ts
await corsair.teamcamp.api.projects.create({ projectName: 'Website Redesign', customerId: '<customer id>', startDate: '2026-11-30', dueDate: '2026-12-31' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectName` | `string` | Yes | The project name. |
| `customerId` | `string` | No | The customer to bill the project to. |
| `startDate` | `string` | No | The project start date. |
| `dueDate` | `string` | No | The project due date. |
| `templateId` | `string` | No | A project template to copy the statuses and groups from. |

Only `projectName` is required. A `templateId` copies the template's statuses and groups into the new project.

### delete

`projects.delete`

Delete a project. It is archived rather than erased: it leaves the project list, but a read by id still returns it marked archived

**Risk:** `destructive`

```ts
await corsair.teamcamp.api.projects.delete({ projectId: '<project id>' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | The project to delete. |

This archives the project rather than erasing it. It leaves the project list, but a read by id still returns it with `archived: true`, so this is destructive but the record survives.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `archived` | `boolean` | Yes | — |
| `projectId` | `string` | Yes | — |
| `message` | `string` | Yes | — |

## Tasks

### create

`tasks.create`

Create a task in a project, with a priority, due date, assignees, group, status, milestone, estimate and attachments

**Risk:** `write`

```ts
await corsair.teamcamp.api.tasks.create({ projectId: '<project id>', taskName: 'Draft the launch announcement', priority: 'high', dueDate: '2026-12-15' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | The project the task belongs to. |
| `taskName` | `string` | Yes | The task name. |
| `description` | `string` | No | The task description. |
| `priority` | `none \| urgent \| high \| medium \| low` | No | The task priority. Omit it for no priority. The project must have task priorities turned on in Teamcamp, or Teamcamp answers 400 "Not enable priority in your project." |
| `dueDate` | `string` | No | The task due date. |
| `groupId` | `string` | No | The task group to place it in. |
| `taskUsers` | `string[]` | No | User ids to assign as the task assignees. |
| `statusId` | `string` | No | The workflow status id, as a project read lists it under `status`. Teamcamp does not check it, so a wrong id is saved as given. |
| `milestoneId` | `number` | No | The milestone id, when the project has milestones. |
| `estimateTime` | `number` | No | The estimated hours for the task. The project must have estimates turned on in Teamcamp, or Teamcamp answers 400. |
| `files` | `object[]` | No | Files to attach, each with its type, url, name and a human-readable size such as "12 KB". |

The name field is sent as `taskName`, which is what the API accepts; the published spec calls it `name` and that is rejected.

<AccordionGroup>
<Accordion title="files full type">

```ts
{
  fileType: string,
  href: string,
  name: string,
  size: string
}[]
```
</Accordion>
</AccordionGroup>

### list

`tasks.list`

List the tasks of a project, optionally only the completed or only the open ones

**Risk:** `read`

```ts
await corsair.teamcamp.api.tasks.list({ projectId: '<project id>', complete: false });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | The project to list tasks from. Required by the API. |
| `complete` | `boolean` | No | True returns only completed tasks, false only open ones. Omit it for both. |

`projectId` is required; the API answers 400 "ProjectId is required" without it. `complete: true` returns only finished tasks, `false` only open ones.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `tasks` | `object[]` | Yes | — |

<AccordionGroup>
<Accordion title="tasks full type">

```ts
{
  taskId: string,
  taskName?: string | null,
  status?: boolean | null,
  statusId?: string | null,
  createdAt?: string | null,
  updatedAt?: string | null,
  id?: string | null
}[]
```
</Accordion>
