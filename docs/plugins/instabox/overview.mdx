Use **InstaBox** through Corsair: one client, typed API calls, and incoming webhooks.

The account stores one credential: an InstaBox API key (`ibk_...`, from
the dashboard's API keys page or `instabox keys create`), sent as
`Authorization: Bearer`. Its scopes decide which operations work. A key
belongs to one workspace and sees only that workspace's machines and
snapshots. A signed-in user's access token works in its place and is the
only credential the sign-in-only routes accept (keys, Vault, billing
changes, creating and deleting workspaces, sessions, support tickets);
their descriptions say so.

- **Lifecycle calls** (create, start, stop, suspend, resume, fork,
snapshot, delete) take an `Idempotency-Key`; the plugin sends a fresh one
unless you pass `idempotency_key`. They answer with an operation; read its
progress with `operations.get`.
- **Deletes** of a machine or snapshot need `X-Confirm-Delete` with its ID
or exact name. The plugin sends the id from the call unless you pass
`confirm_delete`.
- **Exec** (`machines.exec`) runs `cmd` through `bash -lc`, or `argv` with
no shell, and waits for the exit (default 60 s, at most 600). Output is
cut at 1 MiB per stream; download files with `machines.files.download`
rather than `cat`.
- **Money.** Machines are billed per second while they run (vCPU, memory,
storage, egress, GPUs). Creating, starting, resuming, waking, forking or
restoring one, running a command in it, and every plan, checkout and
top-up call are `destructive`, as are invites, key and token issuing and
every delete.
- **Webhooks.** Register an endpoint with `orgs.webhooks.create` and store
the `whsec_` secret it returns as the webhook secret. Deliveries follow
Standard Webhooks (`webhook-id`, `webhook-timestamp`, `webhook-signature`),
and the plugin checks each one.
- **Rate limits.** A 429 `rate_limited` carries `Retry-After` and core
retries it; a 429 `quota_exceeded` is a plan limit and is not retried.
- Not wrapped: sign-in and OAuth flows, the WebSocket terminal, VNC and
Orca tunnels, the desktop watch stream, the GitHub and Stripe webhook
receivers, and deprecated `/v1/images` routes (use `snapshots.*`).

**What you get:**

- 129 typed API operations
- 12 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/instabox better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/instabox better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/instabox better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/instabox better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { instabox } from '@corsair-dev/instabox';

export const corsair = createCorsair({
	plugins: [
		instabox(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the InstaBox API key before the first call: `pnpm corsair setup --plugin=instabox --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
instabox()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'instabox',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List machines**

```ts
const tenant = corsair.withTenant('acme');
await tenant.instabox.api.machines.list({ limit: 20 });
```


**Run a command in a machine**

```ts
const tenant = corsair.withTenant('acme');
await tenant.instabox.api.machines.exec({ id: 'm_k3m7q2abx5wr4hj6zpcnfa2etd', cmd: 'uname -a && nproc', timeoutSeconds: 60 });
```


See the full list on the [API](/plugins/instabox/api) page.

## Webhooks

This plugin registers **12** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/instabox/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
