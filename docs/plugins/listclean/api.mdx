## Account

### getCredits

`account.getCredits`

Read the remaining credit balance; useful before billed calls, which spend one credit per address

**Risk:** `read`

```ts
await corsair.listclean.api.account.getCredits({});
```

**Input:** _empty object_

Free. Answers the remaining balance; a verification spends one credit per address.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `credits` | `number` | Yes | The balance left. A verification spends one credit per address. |

## Lists

### delete

`lists.delete`

Permanently delete a list and its results; there is no undo and the rows cannot be fetched again afterwards

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.listclean.api.lists.delete({ list_id: 159261 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `list_id` | `number` | Yes | The list id, as `startBatchVerification` answered it or `listLists` reported it. |

Permanent. The answer carries only a message string, which the plugin requires before reporting success.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `message` | `string` | Yes | — |

### getList

`lists.getList`

Read one list, including its SUBMITTED, INPROCESS or COMPLETED status and its analytics once done; this is how a batch job is polled

**Risk:** `read`

```ts
await corsair.listclean.api.lists.getList({ list_id: 159261 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `list_id` | `number` | Yes | The list id, as `startBatchVerification` answered it or `listLists` reported it. |

Answers an array holding the one list, so the status reads as 0.status. This is the poll for a startBatchVerification job.

### getListResults

`lists.getListResults`

Download one completed list's verified rows as JSON, choosing the clean, dirty or unknown addresses

**Risk:** `read`

```ts
await corsair.listclean.api.lists.getListResults({ list_id: 159261, type: 'clean' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `list_id` | `number` | Yes | The list id, as `startBatchVerification` answered it or `listLists` reported it. |
| `type` | `clean \| dirty \| unknown` | Yes | Which verified rows to download: the clean, dirty or unknown ones. |

Download the verified rows of one type as a JSON array. This route answers a bare JSON stream, not the envelope. The list must be COMPLETED for rows to exist.



**Output:** `object[]`

<AccordionGroup>
<Accordion title="Output full type">

```ts
{
  datetime?: string | null,
  email: string,
  status: clean | dirty | unknown | error,
  remarks?: string | null,
  disposable?: boolean | null,
  role_based?: boolean | null,
  mx_found?: boolean | null,
  mx_records?: string | null,
  msp?: string | null,
  email_user?: string | null,
  email_domain?: string | null,
  free_email?: boolean | null
}[]
```
</Accordion>
</AccordionGroup>

### listLists

`lists.listLists`

List the bulk lists with their status, per-list analytics and cost, newest page first

**Risk:** `read`

```ts
await corsair.listclean.api.lists.listLists({});
```

Answers total, an opaque cursor integer and the lists. Listclean documents no way to send the cursor back, so there is no paging input here.

## Verify

### getAnalytics

`verify.getAnalytics`

Read verification totals, per-date summaries and graph data for a date range, with optional source and status filters

**Risk:** `read`

```ts
await corsair.listclean.api.verify.getAnalytics({ start_date: '2026-11-01', end_date: '2026-11-25' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `start_date` | `string` | Yes | Range start. |
| `end_date` | `string` | Yes | Range end. It cannot be in the future. |
| `source` | `api \| file_upload \| single_email` | No | Only this verification source. |
| `status` | `clean \| dirty \| unknown \| error` | No | Only this verdict. |

Listclean documents no inner fields for total_summary, datewise_summary or graph_summary, so they are passed through untyped.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `total_summary` | `Record<string, unknown> \| null` | No | — |
| `datewise_summary` | `Record<string, unknown> \| null` | No | — |
| `graph_summary` | `Record<string, unknown>[] \| null` | No | — |

### getVerificationLogs

`verify.getVerificationLogs`

Read past verifications in a date range of up to 30 days, with optional email, source and status filters and offset paging

**Risk:** `read`

```ts
await corsair.listclean.api.verify.getVerificationLogs({ start_date: '2026-11-01', end_date: '2026-11-25', status: 'dirty' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `start_date` | `string` | Yes | Range start. The maximum range is 30 days. |
| `end_date` | `string` | Yes | Range end. It cannot be in the future. |
| `email` | `string` | No | Only this address. |
| `source` | `api \| file_upload \| single_email` | No | Only this verification source. |
| `status` | `clean \| dirty \| unknown \| error` | No | Only this verdict. |
| `start` | `number` | No | Zero-based page offset. |
| `limit` | `number` | No | Page size, at most 100. Defaults to 10. |

The range spans at most 30 days and end_date cannot be in the future. Paging is a start offset with a limit of at most 100, 10 by default. error_code on a log row is a string, unlike the integer on the envelope.



**Output:** `object[]`

<AccordionGroup>
<Accordion title="Output full type">

```ts
{
  id?: number | null,
  entered?: string | null,
  email?: string | null,
  status?: clean | dirty | unknown | error | null,
  remarks?: string | null,
  credits_deducted?: number | null,
  error_code?: string | null
}[]
```
</Accordion>
</AccordionGroup>

### startBatchVerification

`verify.startBatchVerification`

Start an async bulk verification of up to 3000 addresses; each one spends a credit when the job runs. Answers the list id to poll with lists.getList and fetch with lists.getListResults. Not replayed on failure: a repeat would start a second billed job.

**Risk:** `write`

```ts
await corsair.listclean.api.verify.startBatchVerification({ emails: ['user1@example.com', 'user2@example.com'], filename: 'october-leads.csv' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `emails` | `string[]` | Yes | Up to 3000 addresses. Each one spends a credit when the job runs. |
| `filename` | `string` | No | Name shown for the list. When omitted, Listclean generates batch_upload-DD-MM-YYYY-HHMMSS-utc.csv. |

Takes up to 3000 addresses and answers the list_id of the async job. Never retried by the plugin: a repeat would start a second billed job.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `list_id` | `number` | Yes | The async job id; poll it with `lists.getList`. |

### verifyEmail

`verify.verifyEmail`

Verify one email address and read back its verdict, MX and mailbox details. Billed: this spends one credit per call even when the answer is lost, so it is never retried.

**Risk:** `read`

```ts
await corsair.listclean.api.verify.verifyEmail({ email: 'myselfi.itba@gmail.com' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `email` | `string` | Yes | The address to verify. |

Spends one credit even when the address cannot be resolved. The verdict is one of clean, dirty, unknown or error, and remarks explains it. Answers the MX records, the mail service provider and the local and domain parts.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `datetime` | `string \| null` | No | — |
| `email` | `string` | Yes | — |
| `status` | `clean \| dirty \| unknown \| error` | Yes | — |
| `remarks` | `string \| null` | No | — |
| `disposable` | `boolean \| null` | No | — |
| `role_based` | `boolean \| null` | No | — |
| `mx_found` | `boolean \| null` | No | — |
| `mx_records` | `string \| null` | No | — |
| `msp` | `string \| null` | No | — |
| `email_user` | `string \| null` | No | — |
| `email_domain` | `string \| null` | No | — |
| `free_email` | `boolean \| null` | No | — |
