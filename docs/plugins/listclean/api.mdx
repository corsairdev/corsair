## Account

### getCredits

`account.getCredits`

Read the remaining credit balance; useful before billed calls, which spend one credit per address

**Risk:** `read`

```ts
await corsair.listclean.api.account.getCredits({});
```

**Input:** _empty object_

Free. Answers the remaining balance; a verification spends one credit per address.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `credits` | `number` | Yes | The balance left. A verification spends one credit per address. |

|------|------|----------|-------------|

## Uploads

### getUpload

`uploads.getUpload`

Read one upload: its inprocess, success or error status, chunk counts and the request id of the list it became (pass it to lists.getList)

**Risk:** `read`

```ts
await corsair.listclean.api.uploads.getUpload({ upload_id: 1327 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `upload_id` | `number` | Yes | The upload id `uploads.startUpload` answered. |

Answers the upload row (file names, status inprocess, success or error in lowercase, remarks) with chunk_details and request_id, the list the upload became. Chunk counts arrive as strings, or false before any chunk; request_id is 0 or null while there is no list. total_records reads 100 whatever the file holds.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `status` | `inprocess \| success \| error \| string \| null` | No | Upload status: inprocess, success or error (lowercase, unlike the list statuses). |
| `progress` | `number \| string \| null` | No | Completion percentage. |
| `chunk_details` | `object \| null` | No | — |
| `request_id` | `number \| null` | No | The list this upload became: pass it as list_id to `lists.getList`. 0 or null while no list exists. |

<AccordionGroup>
<Accordion title="chunk_details full type">

```ts
{
  total_chunk_count?: number | string | false | null,

} | null
```

### startUpload

`uploads.startUpload`

Open a chunked CSV upload: name the file, its chunk count and chunk size, the zero-based email column, and optional CSV characters and fast mode. Answers the upload id the chunks go to. Once every chunk is in, the list is verified and spends one credit per address.

**Risk:** `write`

```ts
await corsair.listclean.api.uploads.startUpload({ filename: 'leads.csv', file_type: 'csv', total_chunk_count: 2, max_chunk_size: 64000, email_column_index: 0, separator_char: ',' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `filename` | `string` | Yes | Name of the file, shown on the list (e.g. `leads.csv`). |
| `file_type` | `string` | Yes | The file format. The spec documents `csv`. |
| `total_chunk_count` | `number` | Yes | How many chunks `uploads.uploadChunk` will send. |
| `max_chunk_size` | `number` | Yes | The largest chunk, in bytes before base64 encoding. |
| `email_column_index` | `number` | Yes | Zero-based index of the CSV column holding the email address (0 is the first column). Required by the live API, though the spec omits it. |
| `separator_char` | `string` | No | CSV field separator, e.g. `,`. |
| `enclosure_char` | `string` | No | CSV field enclosure character, one single-byte character, e.g. `"`. |
| `escape_char` | `string` | No | CSV escape character, at most one single-byte character; an empty string turns escaping off. |
| `fast_process` | `0 \| 1` | No | 1 skips slow checks such as SMTP and uses only cache, DNS and format checks. Defaults to 0 (off). |

filename, file_type, total_chunk_count, max_chunk_size and email_column_index (zero-based; 0 is the first column) are required. The spec omits email_column_index, but the live API refuses a start without it. fast_process 1 skips SMTP checks. Answers upload_id. Not retried after a 5xx or a dropped connection.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `upload_id` | `number` | Yes | Send the chunks to this id, then poll it with `uploads.getUpload`. |



---

### uploadChunk

`uploads.uploadChunk`

Send one base64-encoded chunk of an upload, with its sequence number (counted from 1) and an optional md5 checksum. Answers the chunk counters. The last chunk starts the billed verification. Not replayed after a 5xx or a lost answer.

**Risk:** `write`

```ts
await corsair.listclean.api.uploads.uploadChunk({ upload_id: 1327, chunk_sequence_number: 1, content: 'ZW1haWwKdXNlckBleGFtcGxlLmNvbQo=' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `upload_id` | `number` | Yes | The upload id `uploads.startUpload` answered. |
| `chunk_sequence_number` | `number` | Yes | Position of this chunk, counted from 1: the last chunk of a 24-chunk file is 24. |
| `content` | `string` | Yes | The chunk of the file, base64-encoded. |
| `md5_checksum` | `string` | No | md5 hash Listclean checks the file against, as hex. |

content is the base64 of one chunk of the file. Chunks are numbered from 1 (live: chunk 1 of 1 completed an upload). Answers the message and chunk_details (total and uploaded counts, as strings). The last chunk starts the billed verification. Not retried after a 5xx or a dropped connection.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `message` | `string` | Yes | — |
| `chunk_details` | `object \| null` | No | How many chunks the upload expects and how many have arrived. |

<AccordionGroup>
<Accordion title="chunk_details full type">

```ts
{
  total_chunk_count?: number | string | false | null,
  uploaded_chunk_count?: number | string | false | null
} | null
```
</Accordion>
</AccordionGroup>

### startBatchVerification

`verify.startBatchVerification`

Start an async bulk verification of up to 3000 addresses; each one spends a credit when the job runs. Answers the list id to poll with lists.getList and fetch with lists.getListResults. Not replayed after a 5xx or a lost answer, since a repeat would start a second billed job; a 429 is retried by core because Listclean refused it before running.

**Risk:** `write`

```ts
await corsair.listclean.api.verify.startBatchVerification({ emails: ['user1@example.com', 'user2@example.com'], filename: 'october-leads.csv' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `emails` | `string[]` | Yes | Up to 3000 addresses. Each one spends a credit when the job runs. |
| `filename` | `string` | No | Name shown for the list. When omitted, Listclean generates batch_upload-DD-MM-YYYY-HHMMSS-utc.csv. |

Takes up to 3000 addresses and answers the list_id of the async job. Not retried after a 5xx or a dropped connection, since a repeat would start a second billed job; a 429 is, because Listclean refused it before running.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `list_id` | `number` | Yes | The async job id; poll it with `lists.getList`. |

Verify one email address and read back its verdict, MX and mailbox details. Billed: one credit per call, spent even when the answer is lost, so it is not retried after a 5xx or a dropped connection (a 429 is, since Listclean refused it before running).

**Risk:** `read`

```ts
await corsair.listclean.api.verify.verifyEmail({ email: 'myselfi.itba@gmail.com' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `email` | `string` | Yes | The address to verify. |

Spends one credit even when the address cannot be resolved. The verdict is documented as clean, dirty, unknown or error (another value is passed through), and remarks explains it. Answers the MX records, the mail service provider and the local and domain parts. Not retried after a 5xx or a dropped connection; a 429 is.
