Use **Ko-fi** through Corsair: one client, typed API calls, and incoming webhooks.

Paste your webhook URL and copy the verification token from your Ko-fi page under Settings, Webhooks. That token is the only credential this plugin needs, and it is sent as the `key` option or stored as the account's `verification_token`.

How a delivery arrives:

- **Ko-fi POSTs form-encoded, not JSON.** The body is `application/x-www-form-urlencoded` with a single `data` field holding the payment as a JSON string. The plugin reads both that form and a body that has already been parsed, so an endpoint that hands over `request.json()` still works.
- **Every delivery carries a `verification_token`**, and it is compared in constant time before anything is handled. With no token configured the delivery is refused rather than accepted: an unverified payment notification would let whoever posted to the URL trigger a sale.
- **A refused delivery throws.** That is deliberate. `processWebhook` builds its result as `{ ...returnToSender, success: true }`, so a handler that returned `success: false` would be reported to Ko-fi as a successful delivery and the retry would never happen.

The four payment types:

- **`Donation`** is a one-off tip. `amount` is a decimal string such as `5.00`, not a number, and `message` holds the note left with it.
- **`Subscription`** is a membership payment. It fires on every payment, not only the first, so use `is_first_subscription_payment` to tell them apart, and `tier_name` for the tier.
- **`Shop Order`** carries `shop_items`, and `shipping` when the goods are physical.
- **`Commission`** is a paid commission. Ko-fi documents the type but publishes no example payload, so its fields follow the same base shape and may vary.

Things to know before you call:

- **There is no API to call.** `api.ko-fi.com` does not resolve, and Ko-fi's help page says the API is "currently limited to when a payment is made". `webhooks.listEvents` therefore returns the documented payment types from Ko-fi's reference and makes no request.
- **Ko-fi only tells you about payments.** It cannot notify you when a membership ends, so a lapse has to be inferred from the absence of a payment or read from Ko-fi itself.
- **A retry keeps its `message_id`.** Ko-fi retries when the endpoint does not answer 200, with the same `message_id` each time, so that field is what makes a delivery safe to de-duplicate.
- **Supporter details are personal data.** The plugin logs the amount, currency and message ID, and never the supporter's name, email, address or message.

**What you get:**

- 1 typed API operations
- 4 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/kofi better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/kofi better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/kofi better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/kofi better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { kofi } from '@corsair-dev/kofi';

export const corsair = createCorsair({
	plugins: [
		kofi(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

This plugin saves no credentials of its own. A call made without a stored key for the tenant throws `AuthMissingError`, which may carry a `connectUrl` to the page that collects one. For Ko-fi that key is the webhook verification token.

```ts
kofi()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'kofi',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Webhooks

This plugin registers **4** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.
