### search

`contacts.search`

Search with query text and/or filterGroups; only default properties come back unless properties is set. Up to 200 per page and 10,000 results; follow paging.next.after.

**Risk:** `read`

```ts
await corsair.hubspot.api.contacts.search({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `query` | `string` | No | Free text matched against the default searchable text properties. |
| `limit` | `number` | No | Page size, max 200. |
| `after` | `string` | No | paging.next.after from the previous page. |
| `sorts` | `object[]` | No | One sort only, e.g. [&#123;"propertyName":"createdate","direction":"DESCENDING"&#125;]. |
| `properties` | `string[]` | No | Internal property names to return, not labels. Only default properties come back if omitted. |
| `filterGroups` | `object[]` | No | Groups are ORed, filters inside a group are ANDed (max 5 groups, 6 filters each). Dates as epoch milliseconds in a string. e.g. [&#123;"filters":[&#123;"propertyName":"email","operator":"EQ","value":"a@b.com"&#125;]&#125;]. |

<AccordionGroup>
<Accordion title="sorts full type">

```ts
{
  propertyName: string,
  direction: ASCENDING | DESCENDING
}[]
```
</Accordion>

<Accordion title="filterGroups full type">

```ts
{
  filters: {
    operator: BETWEEN | CONTAINS_TOKEN | EQ | GT | GTE | HAS_PROPERTY | IN | LT | LTE | NEQ | NOT_CONTAINS_TOKEN | NOT_HAS_PROPERTY | NOT_IN,
    propertyName: string,
    highValue?: string,
    value?: string,
    values?: string[]
  }[]
}[]
```
</Accordion>
</AccordionGroup>
