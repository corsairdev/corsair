Use **Discourse** through Corsair: one client, typed API calls, and incoming webhooks.

Create an API key on the forum (Admin &gt; Advanced &gt; API keys) and connect it with the forum URL and the username to act as. Things to know before you write:

- **Which user acts.** An "All users" key acts as whatever user `Api-Username` names (use an admin, or `system`); a "Single user" key always acts as its own user. Admin routes (`/admin/...`) need an admin.
- **Hosted plans.** Discourse's hosted Free plan has no API keys; self-hosted forums and the paid hosted plans do.
- **Posting.** `posts.create` makes a topic (title + raw), a reply (topic_id + raw) or a private message (archetype `private_message` + `target_recipients`). New topics notify watchers.
- **Rate limits.** Admin keys get 60 requests a minute by default; a 429 carries Retry-After, and core retries it.
- **Webhooks.** Discourse signs each delivery with HMAC-SHA256 of the raw body in `X-Discourse-Event-Signature` (`sha256=<hex>`) using the webhook's secret. The plugin checks it before handling `topic`, `post`, `user`, `group`, `category`, `tag` and other events.

**What you get:**

- 95 typed API operations
- 38 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/discourse better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/discourse better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/discourse better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/discourse better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { discourse } from '@corsair-dev/discourse';

export const corsair = createCorsair({
	plugins: [
		discourse(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Discourse API key before the first call: `pnpm corsair setup --plugin=discourse --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
discourse()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'discourse',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List the latest topics**

```ts
const tenant = corsair.withTenant('acme');
await tenant.discourse.api.topics.listLatest({});
```


**Create a topic**

```ts
const tenant = corsair.withTenant('acme');
await tenant.discourse.api.posts.create({ title: 'Release notes for 2.4', raw: 'What changed in this release, one line per change.', category: 4 });
```


See the full list on the [API](/plugins/discourse/api) page.

## Webhooks

This plugin registers **38** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/discourse/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
