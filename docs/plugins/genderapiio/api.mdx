## Account

### capabilities

`account.capabilities`

Read the deployment version, the AI availability and the batch limit. This route is free

**Risk:** `read`

```ts
await corsair.genderapiio.api.account.capabilities({});
```

**Input:** _empty object_


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `version` | `string` | Yes | — |
| `documentation` | `string` | No | — |
| `capabilities` | `object` | No | — |
| `billing_consistency` | `string` | No | — |

<AccordionGroup>
<Accordion title="capabilities full type">

```ts
{
  ai?: boolean,
  forceToGenderize?: boolean,
  max_batch_items?: number,
  shared_v1_keys_and_credits?: boolean,

    credits: number,
    period_hours: number
  },
  default_ai_mode?: {
    single: string,
    batch: string
  }
}
```
</Accordion>
</AccordionGroup>

## Gender

### batch

`gender.batch`

Infer gender for up to 50 names, emails or usernames in one request. An item can fail on its own, and only successful items are billed

**Risk:** `read`

```ts
await corsair.genderapiio.api.gender.batch({ items: [{ type: 'name', value: 'Sophia' }, { type: 'name', value: 'Michael', country: 'US' }] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `items` | `object[]` | Yes | Items to infer, answered in the same order, each with its own charge. An item can fail without failing the batch |
| `ai_mode` | `off \| fallback \| always` | No | Applies to every item without its own `ai_mode`. A batch defaults to `off`, where a single request defaults to `fallback` |

Up to 50 items (10 on the IP trial); defaults to `ai_mode: off`, unlike a single request.

```ts
{

  type: name | email | username,

```
</Accordion>
</AccordionGroup>



**Output**

### infer

`gender.infer`

Infer gender from a name, an email address or a username, with a confidence, the source that answered (dataset or AI) and the credits it cost

**Risk:** `read`

```ts
await corsair.genderapiio.api.gender.infer({ type: 'name', value: 'Sophia', country: 'US' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `type` | `name \| email \| username` | Yes | What the value is: a first or full name, an email address, or a username or nickname |
| `value` | `string` | Yes | The name, email address or username to infer from |
| `country` | `string` | No | Scopes the lookup to one country, which changes the answer for names such as Kim |
| `ai_mode` | `off \| fallback \| always` | No | `fallback` lets AI answer when the dataset cannot (1 credit in total); `off` is dataset only; `always` forces AI (2 credits) |
| `forceToGenderize` | `boolean` | No | Resolves more names by falling back to nickname-based AI. A dataset hit costs 1 credit, an AI one 2. Cannot be combined with `ai_mode` `off` or `always` |

`ai_mode` defaults to `fallback` here (1 credit in total); `always` costs 2.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |
| `meta` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
  },
```

## Phone

### validate

`phone.validate`

Validate and format a phone number, returning its E.164 form, country and calling code

**Risk:** `read`

```ts
await corsair.genderapiio.api.phone.validate({ number: '+14155552671', country: 'US' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `number` | `string` | Yes | The phone number, with or without a country calling code |
| `country` | `string` | No | The country to parse the number in, when it has no calling code |

Returns the E.164 form, or null when the number cannot be formatted.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |
| `meta` | `object` | Yes | — |

<AccordionGroup>
