The InboxKit plugin handles incoming webhooks. Point your provider’s subscription URL at your Corsair HTTP handler (see [Overview](/plugins/inboxkit/overview) for setup context and the exact URL shape).

<Info>
**New to Corsair?** See [webhooks](/concepts/webhooks) and [hooks](/concepts/hooks).
</Info>

## Webhook map

- `clientIdRequests`
  - `statusChanged` (`clientIdRequests.statusChanged`)
- `consentRequests`
  - `statusChanged` (`consentRequests.statusChanged`)
- `domains`
  - `statusChanged` (`domains.statusChanged`)
- `mailboxes`
  - `statusChanged` (`mailboxes.statusChanged`)

## HTTP handler setup

```ts app/api/webhook/route.ts
import { processWebhook } from "corsair";
import { corsair } from "@/server/corsair";

export async function POST(request: Request) {
    const headers = Object.fromEntries(request.headers);
    // With multiTenancy, give each tenant its own URL (/api/webhook?tenantId=acme):
    // the query says whose account, secret and hooks handle the delivery.
    const query = Object.fromEntries(new URL(request.url).searchParams);
    // The raw text, not request.json(): signatures are checked over the exact bytes sent.
    const body = await request.text();
    const result = await processWebhook(corsair, headers, body, query);
    if (!result.plugin) {
        return Response.json({ success: false }, { status: 404 });
    }
    // A refusal (bad signature) carries no status and answers 400; a handler
    // that threw comes back with 500, so the sender retries it.
    const status =
        result.response?.success === false ? (result.response.statusCode ?? 400) : 200;
    return Response.json(result.response ?? { success: true }, {
        status,
        headers: result.responseHeaders,
    });
}
```

## Events

## Client Id Requests

### Status Changed

`clientIdRequests.statusChanged`

A client ID request's status changed.

**Payload**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `event` | `client_id_request.status_changed` | Yes | — |
| `timestamp` | `string \| null` | No | — |
| `team_id` | `string \| null` | No | — |
| `team_name` | `string \| null` | No | — |
| `data` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  client_id_request: {
    uid: string,
    status?: string | null,
    previous_status?: string | null,
    status_text?: string | null,
    status_reason?: string | null,
    retry_count?: number | null,
    max_retries?: number | null,
    completed_at?: string | null
  },
  metadata?: {
    updated_at?: string | null,
    workspace_id?: string | null,
    workspace_uid?: string | null,
    domain_id?: string | null,
    domain_uid?: string | null,
    domain_name?: string | null
  } | null
}
```
</Accordion>
</AccordionGroup>



<AccordionGroup>
<Accordion title="Response data full type">

```ts
{
  event: client_id_request.status_changed,
  timestamp?: string | null,
  team_id?: string | null,
  team_name?: string | null,
  data: {
    client_id_request: {
      uid: string,
      status?: string | null,
      previous_status?: string | null,
      status_text?: string | null,
      status_reason?: string | null,
      retry_count?: number | null,
      max_retries?: number | null,
      completed_at?: string | null
    },
    metadata?: {
      updated_at?: string | null,
      workspace_id?: string | null,
      workspace_uid?: string | null,
      domain_id?: string | null,
      domain_uid?: string | null,
      domain_name?: string | null
    } | null
  }
}
```
</Accordion>
</AccordionGroup>

**`webhookHooks` example**

```ts
inboxkit({
    webhookHooks: {
        clientIdRequests: {
            statusChanged: {
                before(ctx, args) {
                    return { ctx, args };
                },
                after(ctx, response) {
                },
            },
        },
    },
})
```
