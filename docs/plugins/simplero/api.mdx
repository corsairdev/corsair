## Customers

### addTag

`customers.addTag`

Add one tag or a list of tags to a contact, which can start the automations that tag is attached to

**Risk:** `write`

```ts
await corsair.simplero.api.customers.addTag({ id: 12, tag_id: 5 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `number` | Yes | A Simplero integer id. |
| `tag_id` | `number` | No | One tag to add or remove. |
| `tag_ids` | `number[]` | No | Several tags to add or remove. |

Send exactly one of tag_id or tag_ids. A tag change can start or stop the automations attached to that tag.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  success: boolean,
  message?: string | null
}
```
</Accordion>
</AccordionGroup>

| `value` | `number` | Yes | Added to the stored score, unlike customers.update which replaces it. |

### create

`customers.create`

Create a contact. Email and lead score are the required pair; a score sent here replaces rather than adds

**Risk:** `write`

```ts
await corsair.simplero.api.customers.create({ email: 'alex@example.com', lead_score: 0, first_names: 'Alex', last_name: 'Doe' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `first_names` | `string \| null` | No | — |
| `last_name` | `string \| null` | No | — |
| `email` | `string` | Yes | The address Simplero matches the contact on. |
| `alternative_emails` | `string[] \| null` | No | — |
| `phone_number` | `string \| null` | No | — |
| `do_not_contact` | `boolean` | No | — |
| `do_not_sms` | `boolean` | No | — |
| `locale` | `string \| null` | No | — |
| `gdpr_consent` | `boolean` | No | — |
| `lead_score` | `number` | Yes | Setting it replaces the score. Use customers.adjustLeadScore to add to it instead. |
| `field_value_ids` | `number[]` | No | — |

Simplero requires both email and lead_score on a contact, so a create must send a score. Sending it replaces the stored score; use customers.adjustLeadScore to add to it instead.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |

### list

`customers.list`

List contacts with filters for name, email, tag, segment, list, product and stage; page by number or continue with `after`

**Risk:** `read`

```ts
await corsair.simplero.api.customers.list({ list_id: 7, per_page: 50 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `page` | `number` | No | Page number, from 1. Ignored when `after` is set. |
| `per_page` | `number` | No | Results per page, 1 to 100. Defaults to 20. |
| `after` | `number` | No | Cursor paging: pass the last id of the previous page to get the next one. `total` and `total_pages` are null when this is used. |
| `q` | `string` | No | Search, matching the fields the route documents. |
| `created_at` | `string` | No | A date filter such as 2026-01-01..2026-01-31. |
| `updated_at` | `string` | No | — |
| `first_names` | `string` | No | Matches the first names. |
| `last_name` | `string` | No | — |
| `email` | `string` | No | — |
| `tag_id` | `number` | No | — |
| `segment_id` | `number` | No | — |
| `status` | `customers \| leads \| clients` | No | Only contacts at this stage. |
| `active` | `boolean` | No | — |
| `list_id` | `number` | No | — |
| `product_id` | `number` | No | — |

Page by number with per_page up to 100, or pass pagination.next_after as after. With after, total and total_pages are null because counting is skipped.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object[]` | Yes | — |
| `pagination` | `object \| null` | No | — |
