Use **Proofly** through Corsair: one client, typed API calls, local DB sync.

Auth is the X-Api-Key header on https://proofly.io/api; copy the key from proofly.io/developers while logged in. Free accounts get 10 requests a minute; core retries a 429. Proofly answers a failure with `{ ok: false, error }`, which the plugin throws.

Proofly's API has six routes and the plugin covers all of them:

- **Campaigns.** `campaigns.list` lists them (stored locally). `campaigns.setEnabled` turns one on or off. Proofly's own call is a flip, so the plugin reads the current state first and sends nothing when it already matches (`changed: false`).
- **Notifications.** `notifications.list` returns a campaign's notifications with their settings and impressions, hovers, clicks and leads. `notifications.getData` returns what a notification collected: what visitors typed (often an email), their IP, page and location. That data is not stored, and events log only counts.
- **Account.** `user.get` returns the user (stored without the pixel key) and `activity.list` the login activity (not stored; IPs are not logged).

**What you get:**

- 6 typed API operations
- 2 synced entities (`campaigns`, `users`) for fast `.search()` / `.list()`

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/proofly better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/proofly better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/proofly better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/proofly better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { proofly } from '@corsair-dev/proofly';

export const corsair = createCorsair({
	plugins: [
		proofly(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Proofly API key before the first call: `pnpm corsair setup --plugin=proofly --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
proofly()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'proofly',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List campaigns**

```ts
const tenant = corsair.withTenant('acme');
await tenant.proofly.api.campaigns.list({});
```


**`campaigns.setEnabled`**

```ts
const tenant = corsair.withTenant('acme');
await tenant.proofly.api.campaigns.setEnabled({});
```


See the full list on the [API](/plugins/proofly/api) page.

## Query synced data

Synced entities support `tenant.proofly.db.<entity>.search()` and `.list()`: `campaigns`, `users`.

See [Database](/plugins/proofly/database) for filters and operators.
