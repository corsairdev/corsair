## Activity

### list

`activity.list`

Read Proofly activity logs. The logs are not stored.

**Risk:** `read`

```ts
await corsair.proofly.api.activity.list({});
```

**Input:** _empty object_

Official activity fields are type, ip, and date. The call returns them and stores nothing.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `true` | Yes | — |
| `status` | `number` | No | — |
| `data` | `object[]` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  type: string,
  ip?: string,
  date?: string
}[]
```
</Accordion>
</AccordionGroup>

## Campaigns

### list

`campaigns.list`

List Proofly campaigns for the connected account.

**Risk:** `read`

```ts
await corsair.proofly.api.campaigns.list({});
```

**Input:** _empty object_

Official campaign fields are id, name, domain.domain, domain.subdomains, enabled, and created. id is stored as a decimal string.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `true` | Yes | — |
| `status` | `number` | No | — |
| `data` | `object[]` | Yes | — |

```ts
{
  id: number | string,

  domain?: {
    domain: string,

}[]
```
</Accordion>
</AccordionGroup>

### setEnabled

`campaigns.setEnabled`

Turn a campaign on or off; sends nothing when it already has that state.

**Risk:** `write`

```ts
await corsair.proofly.api.campaigns.setEnabled({ campaign_id: 464014, enabled: false });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `campaign_id` | `number \| string` | Yes | Campaign id from campaigns.list |
| `enabled` | `boolean` | Yes | true to turn the campaign on, false to turn it off |

PUT /campaign/&#123;campaign_id&#125; flips the campaign. The plugin first reads GET /campaigns and sends the PUT only when the current state differs from `enabled`.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `campaign_id` | `string` | Yes | — |
| `enabled` | `boolean` | Yes | — |
| `changed` | `boolean` | Yes | false when the campaign already had that state and nothing was sent |
| `message` | `string` | No | Proofly's reply, when a change was sent |

## Notifications

### getData

`notifications.getData`

Read the leads and conversions a notification collected. Not stored.

**Risk:** `read`

```ts
await corsair.proofly.api.notifications.getData({ notification_id: 745613007 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `notification_id` | `number \| string` | Yes | Notification id from notifications.list |

GET /data/&#123;notification_id&#125;. Leads and conversions with visitor input, IP and location. Returned, not stored.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `true` | Yes | — |
| `status` | `number` | No | — |
| `data` | `object[]` | Yes | — |

```ts
  } | null,

    country?: string | null
```

## User

### get

`user.get`

Read the signed-in Proofly user. The pixel key is removed from the result.

**Risk:** `read`

```ts
await corsair.proofly.api.user.get({});
```

**Input:** _empty object_

Official user fields are name, email, meta, impressions, and pixel. The call returns and stores email, name, meta, and impressions. pixel is removed.


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `true` | Yes | — |
| `status` | `number` | No | — |
| `data` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  name?: string,
  email: string,
  meta?: {
    logins?: number,
    registered?: string
  },
  impressions?: {
    period?: number,
    total?: number
  },
  pixel?: {
    key?: string,
    debug?: boolean
  }
}
```
</Accordion>
</AccordionGroup>
