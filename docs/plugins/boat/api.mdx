## Account

### getCallerAddress

`account.getCallerAddress`

Get the caller's address. The public address that this request comes from, as boat sees it. Use it as an entry of network.inboundAllow. Your network can use another address for the other IP version (IPv4 or IPv6): add both. Any key or session can call this route. An organization API key gets 403 api_key_org_forbidden here (live 11-28): it needs a personal account key.

**Risk:** `read`

```ts
await corsair.boat.api.account.getCallerAddress({});
```

**Input:** _empty object_


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `boolean \| null` | No | — |
| `type` | `string & string \| null` | No | — |
| `address` | `string \| null \| null` | No | The public address that this request comes from, as boat sees it. Null when boat cannot tell. Use it as an entry of `network.inboundAllow`. |

### getLimits

`account.getLimits`

Get Boat limits. Check remaining machine starts, included VM time, the wallet, overage prices, access readiness, and concurrent-sandbox capacity for the wallet a create would bill: the org / X-Boat-Org you pass (id or name), else the account's active wallet, else personal.

**Risk:** `read`

```ts
await corsair.boat.api.account.getLimits({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `org` | `string` | No | Billing wallet for this request: an organization you belong to, by id (`team_…`) or by name as `GET /orgs` lists it (case-insensitive), or `personal`. Omitted, the account's active wallet applies (`PATCH /orgs/active`; personal until set). Two organizations sharing the name answer `409 ambiguous_org` and need the id. Sandboxes and snapshots stay creator-private. On `/environments` routes, only this query parameter selects the organization's shared environments; the `X-Boat-Org` header and the active wallet do not apply there. ### updateDataRetention

`account.updateDataRetention`

Update account data-retention policy. Requires an interactive sandbox session; API keys and legacy permanent tokens are refused. Enabling requires the exact confirmation phrase delete archived sandbox data. Disabling affects future archives only and cannot cancel deletion operations already accepted. An organization API key gets 403 api_key_org_forbidden here (live 11-28): it needs a personal account key.

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.boat.api.account.updateDataRetention({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `enabled` | `boolean` | No | — |
| `snapshotsOff` | `boolean` | No | Turn snapshots off for every sandbox created from now on. Existing sandboxes keep their setting. While on, a create or fork that passes `snapshots: true` is refused with 409 `snapshots_off_for_account`. |
| `monitoringOff` | `boolean` | No | Turn monitoring off for every sandbox created from now on. Existing sandboxes keep their setting. While on, a create or fork that passes `monitoring: true` is refused with 409 `monitoring_off_for_account`. |
| `confirmation` | `delete archived sandbox data` | No | Required when enabling and must exactly equal `delete archived sandbox data`. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `ok` | `boolean \| null` | No | — |
| `type` | `string & string \| null` | No | — |
| `enabled` | `boolean \| null` | No | — |
| `enabledAt` | `string \| null \| null` | No | — |
| `queuedSandboxes` | `number \| null` | No | Archived Sandboxes newly queued for deletion by this policy update. |

## Api Keys

### createScoped

Create a scoped API key. Creates a scoped, expiring API key. Requires a dashboard/CLI session or an admin-scoped token. The secret is returned once. At least one of preset, actions, sandboxIds, or environmentIds is required. Full account access requires an explicit admin preset. Mints a new API key; its secret is returned once. An organization API key gets 403 api_key_org_forbidden here (live 11-28): it needs a personal account key.


### fork

`sandboxes.fork`

Fork sandbox. Provision a new sandbox from an existing one. Send an Idempotency-Key header to make this call safe to retry after a lost response without creating a second billable fork. Starts a new machine that bills like a create. Pass idempotencyKey to make a retry safe.

**Risk:** `destructive`

```ts
await corsair.boat.api.sandboxes.fork({ sandboxId: 'bx_23456789' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `sandboxId` | `string` | Yes | Public Sandbox id returned by create/list/get sandbox calls. |
| `idempotencyKey` | `string` | No | Optional exactly-once key for creating a sandbox. Send your own opaque, account-unique value (a UUID) to make `POST /sandboxes` safe to retry when the response is lost (network timeout, 5xx): the first request creates the sandbox and binds it to the key; every later request with the **same account, key, and request body** returns that same sandbox instead of creating a second, billable one. Behavior: keys are retained for **24 hours**; a concurrent or early retry while the first sandbox is still being minted returns `409` `idempotency_in_progress` (retry shortly, same key); reusing a key with a **different body** returns `409` `idempotency_key_reused`; timeouts and 5xx are safe to retry with the same key; a create that fails before the sandbox exists releases the key within ~2 minutes so a retry can create the sandbox. Omit the header to keep the default (non-idempotent) behavior. |
| `labels` | `Record<string, string>` | No | Labels of the fork. The fork never takes the source's labels. Same rules as `CreateSandboxRequest.labels`. |
| `failFast` | `boolean` | No | Pass `true` to fork only if a machine is ready right now. Within about 1.5 s you get the usual `202`, or `503` `no_ready_machine` with no fork created and nothing counted against your start limits. |
| `monitoring` | `boolean` | No | `false` creates the fork with monitoring off: Boat keeps no command or process output, process list or CPU/RAM samples for it. Omitted, the fork keeps the source sandbox's setting. `true` turns it on for the fork, unless the account has monitoring off by default (`409` `monitoring_off_for_account`). |
| `network` | `object` | No | What the sandbox may connect to. Send `mode`, `inbound` or both: at least one. The side that the request does not name stays as it is. `inbound` and `inboundAllow` are one side. A sandbox that sets one side has its own policy and no longer follows its environment; `mode: environment` makes it follow again. On create, omitted means the policy of its environment; with `from`, the policy that the saved snapshot's sandbox had. On fork, omitted means what the source sandbox has. An API key without the `network.write` action always gets the policy that the sandbox would have without this field, a tighter one included: any other value is refused with 403 `api_key_action_forbidden`. | `type` | `small \| default \| large \| xlarge` | No | Machine size for the fork. Omit to inherit the source sandbox's type. `xlarge` needs the $100/month plan or higher (403 `machine_class_plan_required`). The source sandbox is never modified. Shrinking is rejected with `type_too_small` when the source's data would not fit the smaller disk. |
