## Connectors

### create

`connectors.create`

Create connector. Connect an external source to this namespace. OAuth providers return an authorization url to send the user to; providers that authenticate with config start syncing right away. Needs the Pro plan (the free plan answers 403).

**Risk:** `write`

```ts
await corsair.supermemory.api.connectors.create({ namespace: 'user_ada', provider: 'notion' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `namespace` | `string` | Yes | Namespace identifier. This can be an ID for your user, a project ID, or any other identifier you wish to use to scope documents and memories. |
| `provider` | `notion \| gmail \| onedrive \| github \| google-drive \| s3 \| web-crawler \| granola` | Yes | — |
| `redirectUrl` | `string` | No | Where the user returns after authorizing with the provider |
| `documentLimit` | `number` | No | Maximum documents this connector imports |
| `config` | `object` | No | — |

### delete

`connectors.delete`

Delete connector. Disconnect a connector and stop its webhooks. Its imported documents are deleted too unless deleteDocuments is false.

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.supermemory.api.connectors.delete({ namespace: 'user_ada', id: 'doc_ada_notes' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `namespace` | `string` | Yes | Namespace identifier. This can be an ID for your user, a project ID, or any other identifier you wish to use to scope documents and memories. |
| `id` | `string` | Yes | Connector identifier returned when the connector was created |
| `deleteDocuments` | `boolean` | No | Also delete documents this connector imported. Defaults to true. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string \| null` | No | — |
| `deleted` | `boolean \| null` | No | — |

### get

`connectors.get`

Get connector. Read one connector. Add include=syncs to include its recent sync runs and the items that failed. include=picker needs an admin with write access, since the link changes what syncs.

**Risk:** `read`


| `id` | `string` | Yes | Connector identifier returned when the connector was created |
| `include` | `(syncs \| picker)[]` | No | Comma-separated extras. syncs: the 10 most recent sync runs with their failed items. picker: a one-time hosted picker URL. |

## Documents

### add

`documents.add`

Add document. Turn text or a supported URL into searchable, evolving memory. Supply a new ID to create a document, or reuse an existing ID to append new information while preserving its history.

**Risk:** `write`

```ts
await corsair.supermemory.api.documents.add({
	namespace: 'user_ada',
	content: 'Ada prefers morning meetings and works in Lisbon.',
	id: 'doc_ada_notes',
	metadata: { source: 'onboarding' },
});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `namespace` | `string` | Yes | The isolated namespace. This can be an ID for your user, a project ID, or any other identifier you wish to use to scope documents. |
| `content` | `string` | Yes | The content to process. This may be plaintext or a URL to supported rich content. |
| `id` | `string` | No | An optional caller-defined document ID |
| `supportingContext` | `string` | No | Context used to guide memory extraction within this namespace. Max 1500 characters. |
| `metadata` | `Record<string, string \| number \| boolean \| string[]>` | No | Arbitrary metadata attached to the document and derived data |
| `group` | `Record<string, string \| number \| boolean \| string[]>` | No | Metadata values that isolate related context within the namespace |
| `date` | `string` | No | When the source content is from, in ISO 8601 format |
| `taskType` | `memory \| superrag` | No | Processing pipeline. "memory" builds durable learned context; "superrag" optimizes the document for retrieval without generating memories. |
| `dreaming` | `dynamic \| instant` | No | Processing mode. "dynamic" (default) groups related documents so memories form from coherent context. "instant" processes each document independently right away and bills one extra operation per document. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string \| null` | No | Document identifier to poll or retrieve |
| `status` | `string \| null` | No | The document's processing state after this request. queued when new work was queued; otherwise its current state, e.g. done for an unchanged duplicate or failed for a metadata-only update to a failed document. |

### delete

`documents.delete`

**Risk:** `destructive` · **Irreversible**

```ts

	namespace: 'user_ada',
	ids: ['doc_ada_notes'],
});
```

| `ids` | `string[]` | Yes | Document identifiers to permanently delete from this namespace |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `count` | `number \| null` | No | Number of documents successfully deleted |

### get

`documents.get`

Get document. Retrieve a document's canonical content, metadata, and processing state by document ID or caller-defined ID. Optionally include its source chunks, derived memories, or both in the same response.

**Risk:** `read`

```ts
await corsair.supermemory.api.documents.get({
	namespace: 'user_ada',
	id: 'doc_ada_notes',
	include: ['chunks', 'memories'],
});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `namespace` | `string` | Yes | The isolated namespace. This can be an ID for your user, a project ID, or any other identifier you wish to use to scope documents. |
| `id` | `string` | Yes | The public document ID |
| `include` | `(chunks \| memories)[]` | No | Comma-separated child resources to include: chunks, memories, or both. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string \| null` | No | Stable document identifier |
| `title` | `string \| null \| null` | No | Extracted or caller-provided document title |
| `type` | `string \| null` | No | Detected source or content type |
| `summary` | `string \| null \| null` | No | Generated summary of the document, when available |
| `content` | `string \| null \| null` | No | Canonical extracted text used for processing and recall |
| `metadata` | `Record<string, any> \| null` | No | Caller metadata with internal fields removed |
| `system` | `object \| null` | No | Ingestion source, processing status, lifecycle timestamps, and storage path maintained by Supermemory |
| `chunks` | `object[] \| null` | No | Ordered document chunks; included only when requested |

## Search

### query

`search.query`

Search memories. Recall the most relevant learned context and source passages from a namespace. Hybrid search combines memories with document chunks by default, with optional query rewriting, reranking, and supporting context attachments.

**Risk:** `read`

```ts
await corsair.supermemory.api.search.query({ namespace: 'user_ada', query: 'When does Ada like to meet?', limit: 5 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `namespace` | `string` | Yes | The isolated namespace to search. This can be an ID for your user, a project ID, or any other identifier you wish to use to scope memories. |
| `query` | `string` | Yes | Natural-language question, topic, or phrase to retrieve relevant context for. Replaces the v4 `q` field. |
| `filter` | `object` | No | A type-safe metadata filter predicate or nested and/or expression. The API validates up to 5 levels of nesting. |
| `searchMode` | `hybrid \| memories \| chunks` | No | Search surface. "hybrid" combines learned memories with source chunks, "memories" returns learned context, and "chunks" returns source passages. |
| `limit` | `number` | No | Maximum number of results to return |
| `include` | `object` | No | Optional context to include alongside each matching result |
| `threshold` | `number` | No | Minimum relevance score from 0 to 1. Raise it for precision (fewer, accurate results) or lower it for broader recall (more results). |
| `rerank` | `none \| order \| aggregate` | No | Post-retrieval ranking. "order" improves result ordering; "aggregate" also combines overlapping context into cleaner answers. This is helpful if you want to ensure the most relevant results are returned. |
| `rewriteQuery` | `boolean` | No | Expand and clarify the query before retrieval to improve recall for conversational or underspecified prompts. This increases the latency by about 400ms. |
