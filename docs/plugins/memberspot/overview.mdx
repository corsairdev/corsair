Use **MemberSpot** through Corsair: one client, typed API calls.

Create the key in your school under Settings, API keys (https://app.memberspot.de/settings/apikeys). It is per school, so one key covers every member.

Things to know before you call:

- **The API is documented as OpenAPI 3.0.** The readable reference is https://api.memberspot.de/api and the machine-readable spec is https://api.memberspot.de/api-json, so the plugin's schemas were built from the spec rather than from prose.
- **Auth is an `X-API-KEY` header.** A missing key answers 400, not 401; only an invalid key answers 401. The plugin treats both as auth failures and never retries them.
- **`name` means last name.** MemberSpot splits a member into `firstname` and `name`, and this plugin keeps those names exactly. `created` and the other dates are ISO date-times.
- **Paging uses two different names.** A page request takes `lastLoadedId` and the response returns `nextPage`; the course-progress list calls the inbound cursor `lastLoadedCourseId`. Pass `nextPage` straight back as `lastLoadedId`.
- **Many operations come in email and uid pairs.** Every write that targets a member exists twice, once keyed by email and once by uid. The uid form needs no email lookup, so prefer it when you already have the uid.
- **Deletes are capped at 10 members per call.** The schema enforces the cap locally, because the API rejects an 11th rather than batching it.
- **Members are deleted, not deactivated.** `users.delete` and `users.deleteByUid` remove the account and its progress. To keep the record and remove access, use `users.setOfferState` with `active: false` instead.
- **Rate limits.** Several write routes document a 429 with no `Retry-After`. The plugin retries twice, after the header when present and after one minute otherwise. Every other 4xx is a rejected request and is not retried.
- **No webhooks.** MemberSpot sends none, so the plugin declares no webhook surface.

**What you get:**

- 32 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/memberspot better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/memberspot better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/memberspot better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/memberspot better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { memberspot } from '@corsair-dev/memberspot';

export const corsair = createCorsair({
	plugins: [
		memberspot(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

No setup needed up front. A call made with no saved key throws `AuthMissingError`, which may carry a `connectUrl` where the key can be entered. You can also supply the key yourself, either when the plugin is registered or once per tenant:

```ts
// At registration: pass the key into the factory inside the plugins array.
plugins: [memberspot({ key: process.env.MEMBERSPOT_API_KEY })],

// Or per tenant, scoped through withTenant since multiTenancy is on above.
const tenant = corsair.withTenant('acme');
await tenant.memberspot.keys.set_api_key('the-key');
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'memberspot',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List a page of members**

```ts
const tenant = corsair.withTenant('acme');
await tenant.memberspot.api.users.list({ pageLength: 25 });
```


**Revoke an offer without deleting the member**

```ts
const tenant = corsair.withTenant('acme');
await tenant.memberspot.api.users.setOfferState({ email: 'jordan@acme.example', offerId: 'offer-1', active: false });
```


See the full list on the [API](/plugins/memberspot/api) page.
