Use **MailerLite** through Corsair: one client, typed API calls.

Create an API token in MailerLite under Integrations, MailerLite API, and copy it. It goes in the `Authorization` header as a bearer token. The token is shown once at creation and stays tied to the user who made it.

Things that shape the calls:

- **Every answer wraps in `data`.** Lists add `links` and `meta` alongside, and this plugin passes the envelope through, so pagination fields keep the provider's own names: `meta.next_cursor` for subscribers and `meta.current_page`, `meta.last_page` and `meta.total` for the rest.
- **Paging is mixed.** `subscribers.list` pages by cursor: pass `meta.next_cursor` from one response as `cursor` on the next. Groups, fields, campaigns and campaign activity page by number: pass `page`. Subscribers take up to 1000 per page, campaigns 100, campaign activity 10, 25, 50 or 100.
- **Upsert and update differ on groups.** `subscribers.upsert` only adds groups and never removes on omission. `subscribers.update` takes the complete set: subscribers are removed from every group not listed, so an empty array removes them from all groups. Setting a status back to active or unconfirmed is silently ignored for unsubscribed, bounced or junk subscribers; reactivation needs `subscribers.upsert` with `resubscribe: true`.
- **`campaigns.create` makes a draft only.** Nothing sends until `campaigns.schedule`, whose `delivery: 'instant'` emails every recipient immediately and cannot be unsent. `delivery: 'scheduled'`, `'timezone_based'` or `'smart_sending'` need a future `schedule.date`, and the first two also need `schedule.hours` and `schedule.minutes`. `campaigns.cancel` returns a campaign that has not started sending back to draft, so it can be edited and rescheduled.
- **The sender must be verified.** `emails.from` and `emails.reply_to` on a campaign must already be verified on the MailerLite account, or creation fails with 422.
- **`campaigns.activity` reads a sent campaign**, listing recipients with their open and click counts. The docs specify GET for this route and that is what the plugin sends.
- **Rate limits.** MailerLite allows 120 requests per minute per account. A 429 carries `Retry-After`, which the plugin honours, and retries up to three times. Only reads and the subscriber upsert are replayed after a server error or a dropped connection; a campaign schedule is never replayed, because a repeat could send twice.
- **Webhooks.** MailerLite can deliver subscriber events to URLs it registers, but this plugin does not receive those deliveries; it exposes no webhook handling.

**What you get:**

- 16 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/mailerlite better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/mailerlite better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/mailerlite better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/mailerlite better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { mailerlite } from '@corsair-dev/mailerlite';

export const corsair = createCorsair({
	plugins: [
		mailerlite(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the MailerLite API key before the first call: `pnpm corsair setup --plugin=mailerlite --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
mailerlite()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'mailerlite',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List active subscribers**

```ts
const tenant = corsair.withTenant('acme');
await tenant.mailerlite.api.subscribers.list({ filterStatus: 'active', limit: 50 });
```


**Add or update a subscriber**

```ts
const tenant = corsair.withTenant('acme');
await tenant.mailerlite.api.subscribers.upsert({
	email: 'jordan@acme-logistics.com',
	fields: { name: 'Jordan', last_name: 'Ellis' },
	groups: ['4243829086487936'],
});
```


See the full list on the [API](/plugins/mailerlite/api) page.
