## Account

### planInfo

`account.planInfo`

Read the report credits and discovery calls left in the plan; API subscriptions only

**Risk:** `read`

```ts
await corsair.hypeauditor.api.account.planInfo({});
```

**Input:** _empty object_


**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `result` | `Record<string, JsonValue>` | Yes | — |



---

### unlockedReports

`account.unlockedReports`

List the reports unlocked on the account, with `refunded` marking a credit returned after a failed build

**Risk:** `read`

```ts
await corsair.hypeauditor.api.account.unlockedReports({ limit: 100, date_from: '2024-01-01' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `limit` | `number` | No | Items per page. |
| `offset` | `number` | No | Zero-based index of the first item. |
| `date_from` | `string` | No | Only reports unlocked on or after this date. A date without a time is read as `00:00:00`. |
| `date_to` | `string` | No | Only reports unlocked on or before this date. Omitted, the window runs from account creation to now. |

A date without a time is read as `00:00:00`, and omitting both dates covers the account history.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `result` | `object[] \| Record<string, JsonValue>` | Yes | — |

<AccordionGroup>
<Accordion title="result full type">

```ts
{
  report_id?: number | null,
  username?: string | null,
  type?: string | null,
  unlocked_at?: number | string | null,
  refunded?: boolean | null
}[] | Record<string, JsonValue>
```
</Accordion>
</AccordionGroup>

### search

`discovery.search`

Search creators with the documented filters, 20 per page; each page costs one discovery call, and `sandbox` answers sample data without spending one

**Risk:** `read`

```ts
await corsair.hypeauditor.api.discovery.search({ social_network: 'instagram', filters: { search: ['nasa'], subscribers_count: { from: 10000, to: 100000 } }, page: 1 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `social_network` | `instagram \| youtube \| tiktok \| twitter \| twitch` | Yes | Which network to search. Required. |
| `filters` | `Record<string, JsonValue> \| null` | No | The documented discovery filters, sent as the request body alongside `social_network`: `search`, `search_content`, `search_description`, `niche_search`, `category`, `account_geo`, `subscribers_count`, `er`, `growth`, `sort`, `username_exclude` and the rest. See https://hypeauditor.readme.io/reference/general_discovery. |
| `page` | `number` | No | Page number, 1-indexed, 20 items per page. The result is capped at 10,000 rows, so the highest page is 500. Each page costs one discovery call. |
| `sandbox` | `boolean` | No | Use the sandbox action, which validates the request and returns a sample without spending a call. Defaults to false. |

Each page costs one discovery call and returns 20 rows; the last page is 500. `sandbox: true` spends nothing.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `result` | `Record<string, JsonValue> \| null` | No | — |

## Reports

### instagram

`reports.instagram`

Read the Instagram report by username or user ID; the first request for a creator spends a credit, and a 202 answer carries `retryTtl`

**Risk:** `read`

```ts
await corsair.hypeauditor.api.reports.instagram({ username: 'nasa' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `username` | `string` | No | Instagram username without `@`. Send this or `user_id`, not both. |
| `user_id` | `string` | No | Instagram user ID, which the report returns as `user.id`. Send this or `username`, not both. |
| `type` | `report \| advanced_report` | No | `report` is the mini report and costs one mini-report credit; `advanced_report` is the full report and costs one report credit. Omitted, the provider unlocks the advanced report. |
| `features` | `string[]` | No | Additional report features, such as `ranking` or `mentions`. Omitted returns the default set, and not every feature is in the mini report. |

Send exactly one of `username` or `user_id`; they are two separate actions.



**Output:** `object`

<AccordionGroup>
<Accordion title="Output full type">

```ts
{
  result: {
    retryTtl: number,
    restTokens?: number | null
  }
} | {
  result: {
    report_state?: string | null,
    user?: {
      id?: string | number | null,
      username?: string | null,
      full_name?: string | null,
      is_private?: boolean | null,
      is_verified?: boolean | null,
      is_deleted?: boolean | null,
      about?: string | null,
      photo_url?: string | null
    } | null,
    validUntil?: number | null,
    restTokens?: number | null,
    _report_quality?: string | null
  }
}
```
</Accordion>
</AccordionGroup>
