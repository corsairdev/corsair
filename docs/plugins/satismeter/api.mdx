## Projects

### get

`projects.get`

Read one project by ID

**Risk:** `read`

```ts
await corsair.satismeter.api.projects.get({ projectId: '61fce0adea447e24ec27d606' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | Project ID, from Settings &gt; Integrations &gt; API in the SatisMeter dashboard. |

The project ID comes from Settings > Integrations > API. No endpoint lists projects, so this is the only way to read one.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `project` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="project full type">

```ts
{
  id: string,
  name?: string | null
}
```
</Accordion>
</AccordionGroup>

## Responses

### list

`responses.list`

List responses from every survey in a project, paged by cursor

**Risk:** `read`

```ts
await corsair.satismeter.api.responses.list({ projectId: '61fce0adea447e24ec27d606', pageSize: 100, startDate: '2026-01-01T00:00:00.000Z' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | Project ID, from Settings &gt; Integrations &gt; API in the SatisMeter dashboard. |
| `startDate` | `string` | No | Only include results recorded after this time, in ISO 8601. Defaults to 30 days ago, so older responses need an explicit `startDate`. |
| `endDate` | `string` | No | Only include results recorded before this time, in ISO 8601. Defaults to now. |
| `pageCursor` | `string` | No | The `page.next_page_cursor` of the previous page. Omit it for the first page; when the answer has no cursor, that was the last page. |
| `pageSize` | `number` | No | Results per page, 1 to 100. Defaults to 20. |

Every response in the project across all its surveys. Defaults to the last 30 days and 20 rows per page; pass `startDate` for older data and `pageCursor` to continue.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `responses` | `object[]` | Yes | — |
| `page` | `object` | Yes | — |

### statistics

`surveys.statistics`

Read response counts, display counts and the metric per question for one survey

**Risk:** `read`

```ts
await corsair.satismeter.api.surveys.statistics({ projectId: '61fce0adea447e24ec27d606', surveyId: '61fce0adea447e24ec27d609', startDate: '2026-01-01T00:00:00.000Z' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | Project ID, from Settings &gt; Integrations &gt; API in the SatisMeter dashboard. |
| `surveyId` | `string` | Yes | Survey ID, from Settings &gt; Integrations &gt; API &gt; Survey Keys. |
| `startDate` | `string` | No | Only include results recorded after this time, in ISO 8601. Defaults to 30 days ago, so older responses need an explicit `startDate`. |
| `endDate` | `string` | No | Only include results recorded before this time, in ISO 8601. Defaults to now. |

Counts responses and displays with a response rate, plus a per-question breakdown: an answers count per choice, and the metric (NPS, CSAT, CES or PMF) with its value. A `long-text` question carries a count and no per-value breakdown.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `statistics` | `object` | Yes | Counts for the survey as a whole. |
| `questions` | `object[]` | Yes | Per-question breakdown. |

### remove

`users.remove`

Delete a user’s personal data by internal id; their responses are anonymised, not deleted

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.satismeter.api.users.remove({ userId: '5808e7031a943c7e564cdb17' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `userId` | `string` | Yes | The user's internal `id` from `users.list`, not the `userId` you supplied. Deleting anonymises the user's responses rather than removing them. |

Takes the internal `id` from `users.list`, not your own `userId`. It deletes personal data and anonymises the user\u2019s responses rather than deleting them, and cannot be undone.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `userId` | `string` | Yes | — |
| `removed` | `true` | Yes | — |

### track

`users.track`

Record a user event that survey targeting can match on; each call counts once

**Risk:** `write`

```ts
await corsair.satismeter.api.users.track({ projectId: '61fce0adea447e24ec27d606', userId: '007', event: 'completed-checkout' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | Project ID, from Settings &gt; Integrations &gt; API in the SatisMeter dashboard. |
| `userId` | `string` | Yes | Your own ID for this user, matching the one sent to the browser snippet. |
| `event` | `string` | Yes | A name you choose, such as `completed-checkout`. Survey targeting can match on it. |

Records an event that survey targeting can match on. Each call counts as one event, so it is never retried automatically.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `userId` | `string` | Yes | — |
| `event` | `string` | Yes | — |
| `accepted` | `true` | Yes | — |

### upsert

`users.upsert`

Create or update a user and their traits, and optionally set the date they next see a survey

**Risk:** `write`

```ts
await corsair.satismeter.api.users.upsert({ projectId: '61fce0adea447e24ec27d606', userId: '007', traits: { name: 'James Bond', plan: 'Gold' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | Project ID, from Settings &gt; Integrations &gt; API in the SatisMeter dashboard. |
| `userId` | `string` | Yes | Your own ID for this user, the same one the browser snippet sends. |
| `traits` | `Record<string, unknown>` | No | Custom traits used for survey targeting, such as name, email, createdAt and plan. Sent as given. |
| `surveyDate` | `string` | No | When the user next sees a survey. Use it to survey someone earlier or later than the targeting rules would. |

Creates the user if they do not exist and updates their traits. `surveyDate` sets when the user next sees a survey, which is how you survey someone earlier or later than their targeting rules would.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `userId` | `string` | Yes | — |
| `accepted` | `true` | Yes | — |
