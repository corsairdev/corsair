## Databases

### clear

`databases.clear`

Delete every value in a database while keeping the database itself; the values cannot be restored

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.codereadr.api.databases.clear({ database_id: 120 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `database_id` | `number` | Yes | The database to act on. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `true` | Yes | — |

### create

`databases.create`

Create a database for validating barcode values; case sensitivity is fixed at creation

**Risk:** `write`


**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `database_name` | `string` | Yes | Name for the new database. |
| `case_sensitivity` | `boolean` | No | Case-sensitive validation. Cannot be changed after creation. Defaults to false. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `true` | Yes | — |
| `database_id` | `number` | Yes | The new database. |

### showValues

| Name | Type | Required | Description |

| `database_id` | `number` | Yes | The database to read. |

| `valuelike` | `string` | No | Partial match on the stored value. |

| `responselike` | `string` | No | Partial match on the response text. |

### upsertValue

`databases.upsertValue`

Insert or update one barcode value with its response text and validity, without checking whether it already exists

**Risk:** `write`

```ts
await corsair.codereadr.api.databases.upsertValue({ database_id: 120, value: 'A1B2C3D', response: 'Admitted to Hall 2' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `database_id` | `number` | Yes | The database to write the value to. |
| `value` | `string` | Yes | The barcode value. Longer than 500 characters is truncated without an error. |
| `response` | `string` | No | Text shown when the value is scanned. |
| `validity` | `1 \| 0` | No | `1` valid, `0` invalid. Defaults to 1. |
| `trim_value` | `boolean` | No | Trim surrounding whitespace. Defaults to true. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `true` | Yes | — |

### upsertValues

`databases.upsertValues`

Insert or update up to 100 barcode values in one request, each with its own database, response text, validity and trim setting

**Risk:** `write`

```ts
await corsair.codereadr.api.databases.upsertValues({ database_id: 120, values: [{ value: 'A1', response: 'Hall 2' }, { value: 'B1', response: 'Hall 3' }] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `database_id` | `number` | No | Database for every value that does not name its own. A value with neither is skipped. |
| `trim_value` | `boolean` | No | Trim surrounding whitespace for values that do not set their own. |
| `values` | `object[]` | Yes | Up to 100 values to insert or update in one request. |

</AccordionGroup>

### list

`scans.list`

Search and page through scan records with filters on date, service, device, user, status, barcode value and scan properties, returning each scan with its answers

**Risk:** `read`

```ts
await corsair.codereadr.api.scans.list({ service_id: [927], status: ['1'], start_date: '2026-11-08', limit: 50 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `keyword` | `string` | No | Free-text search across scans. |
| `service_id` | `number[] \| all` | No | Services to search. `all` by default. |
| `device_id` | `number[] \| all` | No | Devices that made the scans. `all` by default. |
| `user_id` | `number[] \| all` | No | Users who made the scans. `all` by default. |
| `scan_id` | `number[] \| all` | No | Only these scans. |
| `status` | `(1 \| 0 \| -1 \| 0 \| 1 \| -1)[]` | No | `1` valid, `0` invalid, `-1` could not be validated offline, as numbers or strings. All statuses by default. |
| `start_date` | `string` | No | YYYY-MM-DD. Scans made on or after this date. |
| `start_time` | `string` | No | HH:mm:ss, 24-hour. Only valid with `start_date`. |
| `end_date` | `string` | No | YYYY-MM-DD. Scans made on or before this date. |
| `end_time` | `string` | No | HH:mm:ss, 24-hour. Only valid with `end_date`. |
| `upload_id` | `number[] \| all` | No | Only scans from these uploads. |
| `limit` | `number` | No | Page size. Defaults to 10000. |
| `offset` | `number` | No | Rows to skip. The API ignores it without `limit`, so the default 10000 is sent when `limit` is omitted. |
| `show_properties` | `boolean` | No | Include each scan's stored properties. Defaults to false. |
| `include_property` | `string[]` | No | Only scans carrying these properties. |
| `exclude_property` | `string[]` | No | Drop scans carrying any of these properties. |
| `with_property` | `Record<string, string>` | No | Exact-match property filters, such as `{ mode: "auto" }`. |
| `without_property` | `Record<string, string>` | No | Exact-match property exclusions, such as `{ mode: "auto" }`. |
| `value` | `string` | No | Exact match on the scanned barcode value. |
| `valuelike` | `string` | No | Partial match on the scanned barcode value. |
| `response` | `string` | No | Exact match on the scan response text. |
| `responselike` | `string` | No | Partial match on the scan response text. |
| `timestamp_received` | `boolean` | No | Include when CodeREADr received each scan; also filters the dates on that timestamp. |
| `timestamp_modified` | `boolean` | No | Include when each scan was last edited; also filters the dates on that timestamp. |
| `modified_diff` | `string` | No | Filter on the gap between creation and last edit, such as `< 2 minute` or `> 1 hour`. |
| `timezone` | `string` | No | IANA name for the returned timestamps, such as `Europe/London`. Defaults to `America/New_York`, not the account timezone; pass `account` to use the one set on the account. |
| `order_by` | `string` | No | Sort keys, comma-separated, such as `timestamp_desc`. Append `_desc` for descending. Keys: barcode, device_name, device_id, response, scan_id, service_id, service_name, status, timestamp, timestamp_received, timestamp_modified, user_id, user_name. |
| `only_recent` | `boolean` | No | Return only the most recent scan per barcode. Defaults to false. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `count` | `number \| null` | No | Rows in this response. |
| `scans` | `object[]` | Yes | — |
| `next_offset` | `number \| null` | No | Pass as `offset` for the next page while this page came back full; absent on the last page. |

## Services

### create

`services.create`

Create a service: how scans are validated (record, database, postback, webview) plus scan behaviour such as symbologies, auto-sync and scanner configuration

**Risk:** `write`

```ts
await corsair.codereadr.api.services.create({ validation_method: 'record', service_name: 'Warehouse intake' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `validation_method` | `record \| ondevicerecord \| database \| ondevicedatabase \| webview \| postback` | Yes | How scans are validated. |
| `database_id` | `number` | No | Required when `validation_method` is `database` or `ondevicedatabase`. |
| `postback_url` | `string` | No | Required when `validation_method` is `postback`. |
| `description` | `string` | No | Web content for `webview` services: HTML, or a URL wrapped as `<curl>https://…</curl>`. |
| `service_name` | `string` | No | Defaults to `Service N` for the next free number. |
| `duplicate_value` | `0 \| 1` | No | Status to give a duplicate scan. Defaults to 1 (valid). |
| `device_duplicate_value` | `0 \| 1` | No | Status to give a duplicate scan found on the device. |
| `period_start_date` | `string` | No | YYYY-MM-DD or MM/DD/YYYY. Defaults to always active. |
| `period_start_time` | `string` | No | hh:mm:ss or hh:mma. Defaults to 12:00AM on the start date. |
| `period_end_date` | `string` | No | YYYY-MM-DD or MM/DD/YYYY. Defaults to always active. |
| `period_end_time` | `string` | No | hh:mm:ss or hh:mma. Defaults to 11:59:59PM on the end date. |
| `upload_email` | `string` | No | Email address that receives a CSV of scans after each upload. |
| `upload_email_format` | `regular \| properties` | No | Whether the emailed CSV carries scan properties. Defaults to `regular`. |
| `view_other_scans` | `boolean` | No | Let an authorized user see every scan on the service. Defaults to true. |
| `direct_history_url` | `string` | No | Page opened by the app's History button. Empty disables it. |
| `direct_lookup_url` | `string` | No | Page opened by the app's Lookup button. Empty disables it. |
| `enable_direct_scan` | `boolean` | No | Postback services only: send scans straight to your server. Defaults to false. |
| `postback_receiver_only` | `boolean` | No | Set when the postback URL cannot answer with the expected XML. Defaults to false. |
| `postback_real_time_scans` | `boolean` | No | Post each online scan to `postback_url` on a non-postback service. |
| `postback_uploaded_scans` | `boolean` | No | Post each uploaded on-device scan to `postback_url` on a non-postback service. |
| `regex_response_pattern` | `string` | No | Regex applied to the response text. Needs `regex_response_replacement`. |
| `regex_response_replacement` | `string` | No | Replacement for `regex_response_pattern`. |
| `regex_scan_pattern` | `string` | No | Regex applied to the scanned value. Needs `regex_scan_replacement`. |
| `regex_scan_replacement` | `string` | No | Replacement for `regex_scan_pattern`. |
| `symbologies` | `number[]` | No | Symbology IDs the app will decode. Omitting this on an update resets the service to the default set. |
| `auto_next_scan` | `0 \| 1 \| 2 \| 3` | No | 0 off, 1 only when valid, 2 always and save on error, 3 always and discard on error. |
| `auto_next_scan_delay` | `number` | No | Seconds before Auto-Next Scan fires. Only with `auto_next_scan`. |
| `enable_gps` | `boolean` | No | Attach the device location to every scan as a property. Defaults to false. |
| `block_camera_scan` | `boolean` | No | Prevent scanning with the device camera. Defaults to false. |
| `block_manual_scan` | `boolean` | No | Prevent typing a value by hand. Defaults to false. |
| `block_db_search` | `boolean` | No | Prevent looking values up in the database. Defaults to false. |
| `auto_sync` | `boolean` | No | Sync on-device scans up and database updates down. On-device databases are capped at 50,000 values. |
| `auto_sync_up_url` | `string` | No | Sync scans straight to your own URL instead of CodeREADr. Only with `auto_sync`. |
| `auto_sync_up_delay` | `number` | No | Seconds between upload attempts. Defaults to 2. Only with `auto_sync`. |
| `auto_sync_down_url` | `boolean` | No | Whether database updates download automatically. Only with `auto_sync`. |
| `auto_sync_down_delay` | `number` | No | Seconds between database update checks. Defaults to 120. Only with `auto_sync`. |
| `decoder_config` | `string` | No | Scanner configuration as a JSON string, produced by the website UI. An empty object `{}` clears it. Setting this locks the scanner settings for the service. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `success` | `true` | Yes | — |
| `service_id` | `number` | Yes | The new service. |
