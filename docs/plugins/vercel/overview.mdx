Use **Vercel** through Corsair: one client, typed API calls, local DB sync, and incoming webhooks.

The plugin calls Vercel's REST API (`https://api.vercel.com`) with a bearer token. Things to know before you call it:

- **Access token.** Create one under [Account Settings → Tokens](https://vercel.com/account/settings/tokens). Pick the team it may reach (or full account) and an expiry. It's the connection's API key; in code you can pass it as `key`.
- **Teams.** Most resources belong to a team. Every operation takes an optional `teamId`, which can be the team id (`team_…`) or its slug. Without it, a call uses the connection's `team_id` field, then the plugin's `teamId` option, then the token's own scope (your default team). `teams.getTeams` lists the teams a token can reach.
- **OAuth.** `authType: 'oauth_2'` and `'managed'` send an OAuth access token. An integration install token (from Vercel's integration flow) never expires; the team the install was made for is saved as the connection's `team_id` automatically. A token that expires (Sign in with Vercel) is refreshed through Corsair.
- **Paging.** List operations take `limit`, `since` and `until` (timestamps in ms). Pass the previous page's `pagination.next` as `until` to get the next page.
- **Rate limits.** Vercel answers 429 with `Retry-After`; Corsair waits and retries up to three times.
- **Secrets.** `envs.getEnvVariable` returns a variable's decrypted value; list operations return most values encrypted. Env values, file contents and webhook secrets are kept out of the event log and the local store.
- **Can't be undone.** Deleting a project, a deployment or an environment variable is permanent. Promotions and rollbacks can be reversed with another promotion.

**What you get:**

- 55 typed API operations
- 6 synced entities (`aliases`, `deployments`, `domains`, `envs`, `projects`, `teams`) for fast `.search()` / `.list()`
- 4 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/vercel better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/vercel better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/vercel better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/vercel better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { vercel } from '@corsair-dev/vercel';

export const corsair = createCorsair({
	plugins: [
		vercel(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Vercel API key before the first call: `pnpm corsair setup --plugin=vercel --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

Provider walkthrough: [Get Credentials](/plugins/vercel/get-credentials).

```ts
vercel()
```

More: [API Key](/concepts/api-key)

</Tab>
<Tab title="Managed OAuth">

No setup required. Corsair hosts the OAuth app for **Vercel** — your tenants connect through Hub when they sign in.

Provider walkthrough: [Get Credentials](/plugins/vercel/get-credentials).

```ts
vercel({
	authType: 'managed',
})
```

More: [Managed OAuth](/concepts/auth#managed)

</Tab>
<Tab title="OAuth 2.0">

Open [hub.corsair.dev](https://hub.corsair.dev/dashboard), navigate to your project, and enter the **client ID** and **client secret** from your Vercel OAuth app.

Provider walkthrough: [Get Credentials](/plugins/vercel/get-credentials).

```ts
vercel({
	authType: 'oauth_2',
})
```

More: [OAuth 2.0](/concepts/oauth)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'vercel',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List projects**

```ts
const tenant = corsair.withTenant('acme');
await tenant.vercel.api.projects.getProjects({ limit: 10 });
```


**Change a project's build command**

```ts
const tenant = corsair.withTenant('acme');
await tenant.vercel.api.projects.updateProject({ idOrName: 'my-site', buildCommand: 'pnpm build' });
```


See the full list on the [API](/plugins/vercel/api) page.

## Query synced data

Projects fetched through the API are stored locally (without their environment variable values).

```ts
const tenant = corsair.withTenant('acme');
const rows = await tenant.vercel.db.projects.search({
	data: { name: 'my-site' },
	limit: 50,
});
```

Synced entities: `aliases`, `deployments`, `domains`, `envs`, `projects`, `teams`. See [Database](/plugins/vercel/database) for filters and operators.

## Webhooks

This plugin registers **4** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/vercel/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
