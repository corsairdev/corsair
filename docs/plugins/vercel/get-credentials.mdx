## Vercel Access Token

To authenticate with the Vercel API, you need a Personal Access Token or a Team Access Token.

<Steps>

<Step title="Open your tokens">
Log in to Vercel and open [Account Settings → Tokens](https://vercel.com/account/settings/tokens).
</Step>

<Step title="Create a token">
Click **Create Token** and give it a name (for example "Corsair").
</Step>

<Step title="Choose its scope and expiry">
Pick the team the token may reach, or **Full Account** for every team you belong to, and an expiration date.
</Step>

<Step title="Copy the token">
Copy it now: Vercel shows it only once.
</Step>

</Steps>

### Storing the token

Store it as the connection's API key with the Corsair CLI:

```bash
pnpm corsair setup --plugin=vercel api_key=your_vercel_token
```

### Choosing the team

Most Vercel resources belong to a team. Each call takes an optional `teamId` (the team id `team_…` or its slug). Without one, calls use the connection's `team_id` field, then the plugin's `teamId` option, then the token's own scope. To set a default team for a connection:

```bash
pnpm corsair setup --plugin=vercel api_key=your_vercel_token team_id=team_abc123
```

`teams.getTeams` lists the teams a token can reach, with their ids and slugs.

## Securing Webhooks (Optional)

If you configure Vercel webhooks to point to your Corsair endpoint, it is highly recommended to set a Webhook Secret to verify incoming payloads.

1. When you create a webhook in Vercel, it will provide a **Secret**.
2. Pass this secret directly when initializing the Vercel plugin:

```ts corsair.ts
import { vercel } from '@corsair-dev/vercel';

export const corsair = createCorsair({
    plugins: [
        vercel({
            webhookSecret: process.env.VERCEL_WEBHOOK_SECRET
        })
    ],
});
```
