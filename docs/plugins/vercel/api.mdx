## Aliases

### assignAlias

`aliases.assignAlias`

Point a hostname at a deployment. If the hostname already serves another deployment it moves, so live traffic switches; the response names the old deployment so it can be moved back.

**Risk:** `write`

```ts
await corsair.vercel.api.aliases.assignAlias({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `teamId` | `string` | No | Team id (team_…) or team slug to run against. Defaults to the connected team. |
| `deploymentId` | `string` | Yes | Deployment to point the alias at: id (dpl_…) or hostname. An alias id or hostname also works and resolves to its current deployment. |
| `alias` | `string` | Yes | Hostname to assign, e.g. www.example.com or my-app.vercel.app. If another deployment holds it, it moves to this one. |
| `redirect` | `string \| null` | No | Hostname to 307-redirect the alias to instead of serving the deployment. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `uid` | `string` | Yes | — |
| `alias` | `string \| null` | No | — |
| `created` | `string \| null` | No | — |
| `oldDeploymentId` | `string \| null` | No | — |

### createDeployment

`deployments.createDeployment`

Start a deployment from a Git ref, from inline files, or as a redeploy of an existing deployment. It builds in the background: follow readyState with getDeployment. target production replaces the live site once ready.

**Risk:** `write`

```ts
await corsair.vercel.api.deployments.createDeployment({});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `teamId` | `string` | No | Team id (team_…) or team slug to run against. Defaults to the connected team. |
| `name` | `string` | Yes | Project name used in the deployment URL. Required even when project is set. |
| `project` | `string` | No | Project id or name to deploy into. Overrides name for the project. |
| `target` | `string` | No | production, staging, or a custom environment. Omit for a preview deployment. production updates the live site. |
| `customEnvironmentSlugOrId` | `string` | No | Custom environment to deploy to, overriding target. |
| `deploymentId` | `string` | No | Redeploy this existing deployment (dpl_…): settings and env are inherited unless overridden here. |
| `withLatestCommit` | `boolean` | No | With deploymentId: build the latest commit instead of the original one. |
| `gitSource` | `object` | No | Git source to build: github by repoId or org+repo, gitlab by projectId, bitbucket by repoUuid or owner+slug. Not with files. |
| `files` | `object[]` | No | Files for a deployment without Git: inline small files (file + data), or reference uploaded ones (file + sha). Not with gitSource. |
| `projectSettings` | `object` | No | Build settings for this deployment. Needed on the first deployment of a new project, then saved. |
| `meta` | `Record<string, string>` | No | Key-value metadata to attach to the deployment. |
| `monorepoManager` | `string \| null` | No | — |
| `forceNew` | `boolean` | No | true: always build, even when an identical deployment exists. |
| `skipAutoDetectionConfirmation` | `boolean` | No | true: proceed when the detected framework differs from the project setting instead of failing with 400. |

### getDeploymentEvents

`deployments.getDeploymentEvents`

**Risk:** `read`

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|

| `idOrUrl` | `string` | Yes | Deployment id (dpl_…) or its hostname, e.g. my-app-abc123.vercel.app. |
| `direction` | `forward \| backward` | No | forward: oldest first (default). backward: newest first. |
| `limit` | `-1 \| number` | No | Maximum number of events; -1 returns all of them. |
| `since` | `number` | No | Only events from this timestamp (ms). |
| `until` | `number` | No | Only events up to this timestamp (ms). |
| `name` | `string` | No | Only events of this build id. |
| `statusCode` | `number \| string` | No | Only request events with this HTTP status or range, e.g. 500 or 5xx. |
| `builds` | `boolean` | No | Include build events. |
| `delimiter` | `boolean` | No | Include delimiter events between steps. |
