## Companies

### delete

`companies.delete`

Delete a company, leaving its users in place; only the relationships go

**Risk:** `destructive`

```ts
await corsair.userlist.api.companies.delete({ identifier: 'company-42' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `identifier` | `string \| number` | Yes | — |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `accepted` | `true` | Yes | — |
| `operation` | `string` | Yes | — |
| `identifier` | `string` | No | — |
| `queuedAt` | `string` | Yes | — |

### upsert

`companies.upsert`

Create or update a company by identifier, with a name and custom properties

**Risk:** `write`

```ts
await corsair.userlist.api.companies.upsert({ identifier: 'company-42', name: 'Acme Inc.', properties: { plan: 'plus' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `identifier` | `string \| number` | Yes | — |
| `name` | `string \| null` | No | null clears it. |
| `signed_up_at` | `string \| null` | No | RFC 3339 / ISO 8601. null clears it. |
| `properties` | `Record<string, any>` | No | Custom properties. Nested objects become dotted keys, and ISO 8601 strings are stored as timestamps. |
| `user` | `string \| number \| Record<string, any>` | No | A single user, as a shortcut for one relationship. |
| `users` | `(string \| number \| Record<string, any>)[]` | No | Several users, as a shortcut for relationships without properties. |
| `relationships` | `object[]` | No | Relationships to users, which can each hold their own properties. |

| `accepted` | `true` | Yes | — |
| `operation` | `string` | Yes | — |

## Events

### create

`events.create`

Record an event against a user, a company or both, with properties and an optional past timestamp

**Risk:** `write`

```ts
await corsair.userlist.api.events.create({ name: 'subscription_activated', user: 'user-123', properties: { plan: 'plus' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | The event name, such as `subscription_activated`. |
| `user` | `string \| number \| Record<string, any>` | No | Required unless a company is given. |
| `company` | `string \| number \| Record<string, any>` | No | Required unless a user is given. |
| `occurred_at` | `string` | No | When it happened, for importing historic events. Defaults to now. |
| `properties` | `Record<string, any>` | No | Custom properties. Nested objects become dotted keys, and ISO 8601 strings are stored as timestamps. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `accepted` | `true` | Yes | — |
| `operation` | `string` | Yes | — |
| `identifier` | `string` | No | — |
| `queuedAt` | `string` | Yes | — |

## Messages

### send

`messages.send`

Queue a transactional email or in-app message, from a template or with an inline subject and body

**Risk:** `write`

```ts
await corsair.userlist.api.messages.send({ template: 'welcome_email', user: 'user-123', properties: { first_name: 'Delaney' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `template` | `string` | No | The template identifier. When set, subject, body and channel come from it. |
| `user` | `string \| number \| Record<string, any>` | No | Required unless `to` is given. Always required for a web message. |
| `company` | `string \| number \| Record<string, any>` | No | A company identifier, or an embedded company object. |
| `properties` | `Record<string, any>` | No | Available in the template as `{{ event.<key> }}`. |
| `channel` | `email \| web` | No | Defaults to email. A web message requires `user` and forbids `to`. |
| `to` | `string` | No | The recipient address. Only for email; required unless `user` is set. |
| `from` | `string` | No | The sender address. Email only. |
| `reply_to` | `string` | No | The reply-to address. Email only. |
| `subject` | `string` | No | Required when not using a template. Supports Liquid. |
| `preheader` | `string` | No | Email preheader text. |
| `body` | `object` | No | Required when not using a template. |
| `sender` | `string` | No | A sender identifier from the account. |
| `theme` | `string \| false` | No | A theme identifier, or false to disable theming. |
| `topic` | `string` | No | A topic identifier from the account. |

```ts
  }[]
}
```
</Accordion>
</AccordionGroup>



**Output**

| `accepted` | `true` | Yes | — |
| `operation` | `string` | Yes | — |
| `identifier` | `string` | No | — |
| `queuedAt` | `string` | Yes | — |

## Relationships

`relationships.delete`

### upsert

`users.upsert`

Create or update a user by identifier or email, with properties, companies, relationships and topic preferences; queued, not applied at once

**Risk:** `write`

```ts
await corsair.userlist.api.users.upsert({ identifier: 'user-123', email: 'user-123@example.com', properties: { first_name: 'Delaney' }, companies: ['company-42'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `identifier` | `string \| number` | No | Your id for the user. Required unless email is given. |
| `email` | `string \| null` | No | The address. Required unless identifier is given. null clears it. |
| `signed_up_at` | `string \| null` | No | RFC 3339 / ISO 8601. null clears it. |
| `properties` | `Record<string, any>` | No | Custom properties. Nested objects become dotted keys, and ISO 8601 strings are stored as timestamps. |
| `company` | `string \| number \| Record<string, any>` | No | A single company, as a shortcut for one relationship. |
| `companies` | `(string \| number \| Record<string, any>)[]` | No | Several companies, as a shortcut for relationships without properties. |
| `relationships` | `object[]` | No | Relationships to companies, which can each hold their own properties. |
| `preferences` | `object[]` | No | Subscription preferences. Only the topics sent are changed; the rest keep their value. |
