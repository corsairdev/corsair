## Account

### subscription

`account.subscription`

Read the plan behind the key: credits used and allowed, period end, per-product usage and the concurrency limit

**Risk:** `read`

```ts
await corsair.zenrows.api.account.subscription({});
```

## Crawl

### get

`crawl.get`

Read a crawl with its coverage and one page of results; poll it with the same cursor to collect new URLs

**Risk:** `read`

```ts
await corsair.zenrows.api.crawl.get({ crawlId: '<crawl_id from crawl.start>' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `crawlId` | `string` | Yes | The `crawl_id` that `crawl.start` returned. |
| `cursor` | `string` | No | The `next_cursor` from the previous read. Each URL is returned once, so poll with the same cursor to get only new ones. It is null once the crawl has ended and its last results were read. |
| `limit` | `number` | No | How many results to return. Zenrows defaults to 1000. |

While the crawl runs `next_cursor` is never null. Poll with the cursor to collect only the URLs you have not read.

### start

`crawl.start`

Start a crawl from one URL: each page it opens is a billed Fetch request, and a crawl runs until its page limits stop it

**Risk:** `write`

```ts
await corsair.zenrows.api.crawl.start({ url: 'https://www.scrapingcourse.com/ecommerce/', maxPages: 10, includePatterns: ['/product/'], outputFormat: 'html' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `url` | `string` | Yes | The start URL. The crawl stays on its domain, subdomains included, and never opens a link that would change something, such as a checkout or unsubscribe. |
| `depth` | `number` | No | How many link steps to follow. At 1, the links on the start page. Omit it to follow links until `maxItems` or `maxPages` stops the crawl. |
| `maxItems` | `number` | No | Stop after keeping this many URLs. Zenrows defaults to 100. |
| `maxPages` | `number` | No | Stop after fetching this many pages. Zenrows defaults to 100. This is the cost cap: each page is one billed Fetch request. |
| `includePatterns` | `string[]` | No | Keep and open only URLs containing at least one of these texts, such as "/product/". The start URL is never returned itself. |
| `excludePatterns` | `string[]` | No | Drop URLs containing any of these texts, even when they match an include pattern. |
| `outputFormat` | `html \| markdown` | No | Also return each kept page: `html` as fetched, `markdown` converted. Omit it to get URLs only. |
| `webhookUrl` | `string` | No | Send crawl events here. The host must resolve publicly, the account needs a webhook signing key, and the URL cannot change once the crawl starts. |
| `webhookEvents` | `(crawl.started \| crawl.completed \| crawl.stopped \| crawl.failed)[]` | No | Events to send. Omit it for all four. |
| `webhookMetadata` | `Record<string, JsonValue>` | No | Up to 20 keys of your own, echoed back in every event so a delivery can be matched to your records. |
| `idempotencyKey` | `string` | No | The same key with the same body returns the original crawl instead of starting a second one. |

The page limit is the cost cap, because each page opened is one billed Fetch request. `webhookUrl` needs a ZenRows webhook signing key on the account and an `https` host that resolves publicly, and the URL cannot change after the start.

| `status` | `string` | Yes | — |

| `depth` | `number \| null` | No | — |
| `max_items` | `number \| null` | No | — |
| `max_pages` | `number \| null` | No | — |
| `include_patterns` | `string[] \| null` | No | — |
| `exclude_patterns` | `string[] \| null` | No | — |
| `output_format` | `string \| null` | No | — |
| `discovery` | `string[] \| null` | No | — |
| `coverage` | `object \| null` | No | — |
| `duplicates_removed` | `number \| null` | No | — |
| `created_at` | `string \| null` | No | — |

### prepareDomain

`extract.prepareDomain`

Ask Zenrows to prepare a domain for Extract, which takes minutes and one slot of the monthly allowance; preparation is free and shared across accounts

**Risk:** `write`

```ts
await corsair.zenrows.api.extract.prepareDomain({ domain: 'example.com', exampleUrls: ['https://example.com/1', 'https://example.com/2', 'https://example.com/3'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `domain` | `string` | Yes | The domain to prepare, without scheme: "example.com". Zenrows drops a leading `www.`, and prepares each subdomain separately. |
| `exampleUrls` | `string[]` | No | 1 to 5 URLs on that domain. Three or more of the same page type work best, because Extract compares them. Zenrows answers 400 without them for a domain that is not already ready. For a ready domain, the call returns its record. |
| `idempotencyKey` | `string` | No | The same key with the same body returns the original submission; a different body answers 409. |

Preparation is free and needs no credits, but it takes one slot of the monthly allowance and minutes to finish. Send `exampleUrls`: a domain that is not already ready is refused without them. A failed attempt that Zenrows could not fetch does not use a slot. Poll `extract.getDomainStatus` rather than blocking.

| `failure` | `object \| null` | No | — |
| `submitted_at` | `string \| null` | No | — |

## Fetch

### browse

`fetch.browse`

Render a page and act on it before capture: fill fields, click, check, scroll or run JavaScript. Reaches the site, so it can change its state

**Risk:** `write`

```ts
await corsair.zenrows.api.fetch.browse({ url: 'https://example.com', jsRender: true, jsInstructions: [{ click: 'a' }] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `url` | `string` | Yes | The page to fetch. |
| `mode` | `auto` | No | Adaptive Stealth Mode: starts from the cheapest configuration and escalates to rendering or residential proxies only when the target needs it. Rejects `jsRender` and `premiumProxy`. |
| `jsRender` | `boolean` | No | Render the page in a headless browser first. Defaults to false. |
| `headers` | `Record<string, string>` | No | Headers to send to the target page, such as &#123; "Referer": "https://www.google.com", "Cookie": "session=..." &#125;. ZenRows forwards every request header when `customHeaders` is on, so the API key moves to the query string for this call. The target sees these exactly as given. |
| `customHeaders` | `boolean` | No | Forward the caller's own request headers to the page. Implied by `headers`, which turn it on even when this is false, and the API key moves to the query string because ZenRows copies every request header onto the target request. |
| `premiumProxy` | `boolean` | No | Route through residential IPs. Most protected sites need it. |
| `proxyCountry` | `string` | No | Two-letter exit country, such as "us". Needs `premiumProxy` or `mode: "auto"`. |
| `sessionId` | `number` | No | Any integer; requests sharing it leave through the same IP for 10 minutes. It pins the IP, not cookies. |
| `originalStatus` | `boolean` | No | Answer with the target's own status code instead of Zenrows' one. A 4xx or 5xx from the target then arrives as an error, and the request is still charged. |
| `allowedStatusCodes` | `number[]` | No | Status codes whose page body is returned instead of raising an error, such as [404]. The answer is then a 200 carrying that page. |
| `waitFor` | `string` | No | CSS selector to wait for before capture. Needs `jsRender`; Zenrows gives up with a 422 after 3 minutes. |
| `wait` | `number` | No | Milliseconds to wait after load before capture. Needs `jsRender` or `mode: "auto"`. Defaults to 0. |
| `blockResources` | `(image \| media \| font \| stylesheet \| script \| xhr \| fetch \| other \| eventsource \| manifest \| websocket \| texttrack)[]` | No | Resource types to block, such as ["image","font"]. Images and stylesheets are already blocked by default, so this customises that rather than adding to nothing. |
| `jsInstructions` | `object[]` | Yes | Browser actions run in order before the page is captured, such as &#123;"fill":["#q","x"]&#125; then &#123;"click":"#submit"&#125;. Each instruction carries one action key, and the sequence has 40 seconds. |
| `responseType` | `markdown \| plaintext` | No | Convert the captured page before returning it. `markdown` and `plaintext` are text; omit it for the HTML as it stands after the actions. |

A write: browser actions reach the site, so this is not available to a read-only caller. Needs `jsRender` or `mode: 'auto'`, and the whole sequence has 40 seconds.

```ts
    string,
```
