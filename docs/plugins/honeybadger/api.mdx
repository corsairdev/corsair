## Check Ins

### create

`checkIns.create`

Create a check-in on a simple period or a cron schedule; a simple schedule needs `report_period` and a cron schedule needs `cron_schedule`

**Risk:** `write`

```ts
await corsair.honeybadger.api.checkIns.create({ project_id: 'Xk9mZp', name: 'Nightly billing', slug: 'nightly-billing', report_period: '1 day', grace_period: '15 minutes' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `project_id` | `string` | Yes | The project ID. |
| `name` | `string \| null` | No | Display name. Null clears it; an unnamed check-in shows its ID. |
| `slug` | `string \| null` | No | Short identifier used in the check-in's reporting URL. Renaming it breaks jobs reporting to `…/check_in/<ingestion key>/<slug>`. |
| `schedule_type` | `simple \| cron` | No | `simple` expects a report every `report_period`; `cron` expects reports on a cron schedule and requires `cron_schedule`. Switching to `simple` clears `cron_schedule`; switching to `cron` clears `report_period`. Defaults to `simple` on create. |
| `report_period` | `string \| null` | No | How often a report is expected, for `simple` schedules. Required unless `schedule_type` is `cron`, and may not be zero. Returned in long form. |
| `grace_period` | `string \| null` | No | How long after the expected time before the check-in counts as missing. Null resets it to zero. |
| `cron_schedule` | `string \| null` | No | Cron expression, required when `schedule_type` is `cron`. |
| `cron_timezone` | `string \| null` | No | Timezone the cron schedule is evaluated in, as the web app lists it (`Central Time (US & Canada)`), not an IANA identifier. Null resets it to `UTC`. |

A `simple` schedule needs `report_period`. A `cron` schedule needs `cron_schedule` and takes the web app timezone name, not an IANA identifier.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |
| `meta` | `object \| null` | No | Request metadata. Quote `request_id` when contacting support. |
