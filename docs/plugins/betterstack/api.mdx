const tenant = corsair.withTenant('acme');

| `period` | `number` | No | How often should we expect this heartbeat? In seconds Minimum value: 30 seconds |
| `grace` | `number` | No | Heartbeats can fluctuate; specify this value to control what is still acceptable Minimum value: 0 seconds We recommend setting this to approx. 20% of period |
| `call` | `boolean` | No | Should we call the on-call person? |

| `heartbeat_group_id` | `number` | No | Set this attribute if you want to add this heartbeat to a heartbeat group |
| `sort_index` | `number` | No | An index controlling the position of a heartbeat in the heartbeat group. |
| `paused` | `boolean` | No | Set to true to pause monitoring — we won't notify you about downtime. Set to false to resume monitoring |
| `server_timezone` | `string` | No | Optional IANA timezone (e.g. Europe/Berlin) used for DST-aware missed-beat detection. Requires period >= 3600 (1 hour) |

| `maintenance_to` | `string` | No | End of the maintenance window each day. Example: '03:00:00' |
| `maintenance_timezone` | `string` | No | The timezone to use for the maintenance window each day. Defaults to UTC. The accepted values can be found in the Rails TimeZone documentation. https://api.rubyonrails.org/classes/ |
| `policy_id` | `number` | No | Set the escalation policy for the monitor. |

| `user_id` | `number` | No | Define which team member to escalate to. \\nEither user_email or user_id required when escalating to User. |

| `team_id` | `number` | No | Define which team to escalate to. \\nEither team_name or team_id required when escalating to Team. |
| `schedule_id` | `number` | No | Define which on-call calendar to escalate to. Required when escalating to Schedule. |
| `policy_id` | `number` | No | Define which escalation policy to escalate to. Required when escalating to Policy. |
| `call` | `boolean` | No | Should we call? \\nCan be used when escalating to User, Team, Schedule, or Organization. |
| `sms` | `boolean` | No | Should we send an SMS? \\nCan be used when escalating to User, Team, Schedule, or Organization. |
| `email` | `boolean` | No | Should we send an email? \\nCan be used when escalating to User, Team, Schedule, or Organization. |
| `push` | `boolean` | No | Should we send a push notification? \\nCan be used when escalating to User, Team, Schedule, or Organization. |
| `critical_alert` | `boolean` | No | Should we send a critical push notification that ignores the mute switch and Do not Disturb mode? \\nCan be used when escalating to User, Team, Schedule, or Organization. |
