## Chat

### history

`chat.history`

Read a chat or group’s messages with time-window and thread filters plus cursor paging

**Risk:** `read`

```ts
await corsair.roam.api.chat.history({ chat_id: '757dfe66-37b4-4772-baa5-8c86ec68c176', limit: 100, ascending: false });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `chat_id` | `string` | No | The chat uuid. |
| `group_id` | `string` | No | The group uuid. |
| `user_ids` | `string[]` | No | Read the direct or multi-person chat with these users instead of a chat or group. |
| `thread_timestamp` | `number` | No | Only the replies in this thread. |
| `after` | `string` | No | Only messages after this timestamp. |
| `before` | `string` | No | Only messages before this timestamp. |
| `ascending` | `boolean` | No | — |
| `cursor` | `string` | No | The `next_cursor` from the previous page, passed through unchanged. |
| `limit` | `number` | No | Records per page, at most 200. Roam applies its own default when omitted. |
| `expand` | `string[]` | No | Relations to inline, as a comma-separated list on the wire. |

Needs exactly one of `chat_id`, `group_id` or `user_ids`. Poll options come back as `{ id, text }` objects.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `messages` | `object[]` | Yes | — |
| `addresses` | `object` | No | Present only with `expand: ['addresses']`: display info for the ids in this page, keyed by id. |
| `next_cursor` | `string \| null` | Yes | Pass as `cursor` to read the next page; null on the last. |
| `has_more` | `boolean` | Yes | — |

### post

`chat.post`

Post a message to a chat, group or direct conversation, or schedule one for later

**Risk:** `write`

```ts
await corsair.roam.api.chat.post({ chat_id: '757dfe66-37b4-4772-baa5-8c86ec68c176', text: 'Standup in five', sync: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `chat_id` | `string` | No | The chat to post into. |
| `group_id` | `string` | No | The group to post into. |
| `user_ids` | `string[]` | No | Open a direct chat with these users. |
| `thread_timestamp` | `number` | No | — |
| `thread_key` | `string` | No | An external id that threads every post sharing it under the first one. |
| `reply_timestamp` | `number` | No | — |
| `text` | `string` | No | — |
| `markdown` | `boolean` | No | — |
| `items` | `string[]` | No | Item ids to attach to the message. |
| `asset_ids` | `string[]` | No | — |
| `blocks` | `object[]` | No | Block Kit blocks, at most ten and 8,000 bytes in total. |
| `color` | `string` | No | — |
| `poll` | `object` | No | — |
| `sender` | `object` | No | — |
| `sync` | `boolean` | No | Wait for the post and return its `timestamp`, which `chat.update`, `reactions.add` and thread replies need. Without it the answer has no timestamp. |
| `send_at` | `string` | No | Schedule the post for this ISO 8601 time instead of sending now: in the future, within 30 days, on a 15-minute UTC boundary. |

Pass `sync: true` to get the `timestamp` back. `text`, `items` and `asset_ids` combine; `blocks` and `poll` stand alone; `send_at` schedules instead of sending.

</Accordion>

```ts
  name?: string,
  imageUrl?: string
}
```
</Accordion>
</AccordionGroup>



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `post` | `object` | Yes | — |
