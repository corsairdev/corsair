Use **Hugging Face** through Corsair: one client, typed API calls, optional local DB sync.

**What you get:**

- 139 typed API operations
- 6 database entities synced for fast `.search()` / `.list()` queries

## Setup

<Steps>

<Step title="Install">
```bash
pnpm install @corsair-dev/huggingface
```

</Step>

<Step title="Add the plugin">
<Tabs>
<Tab title="Solo">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { huggingface } from '@corsair-dev/huggingface';

export const corsair = createCorsair({
	// ... other config options,
	multiTenancy: false,
    plugins: [huggingface()],
});
```
</Tab>
<Tab title="Multi-Tenant">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { huggingface } from '@corsair-dev/huggingface';

export const corsair = createCorsair({
	// ... other config options,
    multiTenancy: true,
    plugins: [huggingface()],
});
```

See [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Tab>
</Tabs>

</Step>

<Step title="Get credentials">
Follow [Get Credentials](/plugins/huggingface/get-credentials) if you need help getting keys.

</Step>

<Step title="Store credentials">
<Tabs>
<Tab title="Solo">
```bash
pnpm corsair setup --plugin=huggingface
```

Use the key names documented in [Get Credentials](/plugins/huggingface/get-credentials) (for example `api_key=`, `bot_token=`, or OAuth client fields).
</Tab>
<Tab title="Multi-Tenant">
```bash
pnpm corsair setup --plugin=huggingface --tenant=<tenantId>
```

Store per-tenant secrets after you create the tenant record. See [Multi-tenancy](/concepts/multi-tenancy).
</Tab>
</Tabs>

</Step>

</Steps>

## Authentication

Each tab shows how to register the plugin for that authentication method. The default `authType` from the plugin does not need to appear in the factory call.

<Tabs>
<Tab title="API Key (Default)">

```ts corsair.ts
huggingface()
```

Store credentials with `pnpm corsair setup --plugin=huggingface` (see [Get Credentials](/plugins/huggingface/get-credentials) for field names). For OAuth, you typically store integration keys at the provider level and tokens per account or tenant.

More: [API Key](/concepts/api-key)

</Tab>
<Tab title="OAuth 2.0">

```ts corsair.ts
huggingface({
    authType: 'oauth_2',
})
```

Store credentials with `pnpm corsair setup --plugin=huggingface` (see [Get Credentials](/plugins/huggingface/get-credentials) for field names). For OAuth, you typically store integration keys at the provider level and tokens per account or tenant.

More: [OAuth 2.0](/concepts/oauth)

</Tab>
</Tabs>


## Query synced data

Synced entities support `corsair.huggingface.db.<entity>.search()` and `.list()`. See [Database](/plugins/huggingface/database) for filters and operators.


## Example API calls

**Read-style (read):** `account.getWhoami`

```ts
await corsair.huggingface.api.account.getWhoami({});
```


**Write-style (destructive):** `account.deleteNotifications`

```ts
await corsair.huggingface.api.account.deleteNotifications({});
```


See the full list on the [API](/plugins/huggingface/api) page. Use `pnpm corsair list --plugin=huggingface` and `pnpm corsair schema <path>` locally to inspect schemas.
