## Boards

### create

`boards.create`

Create a Kanban board or an AI Canvas in a workspace; it starts with a cards workflow and an initiatives workflow

**Risk:** `write`

```ts
await corsair.kanbanize.api.boards.create({ workspace_id: 3, name: 'Product delivery', description: 'Everything the team ships', type: 1 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace to create the board in. |
| `name` | `string` | Yes | — |
| `description` | `string` | No | — |
| `type` | `1 \| 2` | No | `1` for a Kanban board, `2` for an AI Canvas. Defaults to `1`. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  board_id: number,
  workspace_id?: number | null,
  is_archived?: 0 | 1 | null,
  name?: string | null,
  description?: string | null,
  type?: number | null,
  revision?: number | null
}
```
</Accordion>
</AccordionGroup>

### list

`boards.list`

List boards, optionally limited to IDs, workspaces or the boards the key’s user is assigned to, with optional workflows and structure

**Risk:** `read`

```ts
await corsair.kanbanize.api.boards.list({ workspace_ids: [3], is_archived: 0, fields: ['board_id', 'name'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `board_ids` | `number[]` | No | Only these boards. |
| `workspace_ids` | `number[]` | No | Only boards in these workspaces. |
| `is_archived` | `0 \| 1` | No | `0` for live boards, `1` for archived ones. |
| `if_assigned` | `0 \| 1` | No | `1` for only the boards the key’s user is assigned to. |
| `fields` | `(board_id \| workspace_id \| is_archived \| name \| description \| type \| revision)[]` | No | Return only these fields. The record’s ID is always included. |
| `expand` | `(workflows \| settings \| structure \| effective_cycle_time_column_ids \| data_fields)[]` | No | Include these nested objects. |

A list such as `board_ids` goes as one comma-separated value, which is how the API documents it.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object[]` | Yes | — |

<AccordionGroup>
<Accordion title="data full type">

```ts
{
  board_id: number,
  workspace_id?: number | null,
  is_archived?: 0 | 1 | null,
  name?: string | null,
  description?: string | null,
  type?: number | null,
  revision?: number | null
}[]
```
</Accordion>
</AccordionGroup>

## Cards

### create

`cards.create`

Create a card in a column and lane, with an owner, priority, deadline, tags, custom fields and subtasks, or from a template

**Risk:** `write`

```ts
await corsair.kanbanize.api.cards.create({ title: 'Ship the pricing page', column_id: 15876, lane_id: 9838, owner_user_id: 12, priority: 2, tag_ids_to_add: [31] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `column_id` | `number` | Yes | The column the new card goes in, from `columns.list`. |
| `lane_id` | `number` | Yes | The lane the new card goes in, from `lanes.list`. |
| `position` | `number` | No | `0` is the top. |
| `title` | `string` | Yes | The card title. |
| `description` | `string` | No | — |
| `custom_id` | `string` | No | — |
| `owner_user_id` | `number` | No | — |
| `type_id` | `number` | No | — |
| `size` | `number` | No | — |
| `priority` | `1 \| 2 \| 3 \| 4` | No | `1` critical, `2` high, `3` average, `4` low. |
| `color` | `string` | No | Hexadecimal, such as `a1b2c3`. |
| `deadline` | `string` | No | ISO 8601 with a timezone offset. |
| `co_owner_ids_to_add` | `number[]` | No | — |
| `watcher_ids_to_add` | `number[]` | No | — |
| `tag_ids_to_add` | `number[]` | No | — |
| `milestone_ids_to_add` | `number[]` | No | — |
| `template_id` | `number` | No | Create the card from this template. |
| `custom_fields_to_add_or_update` | `object[]` | No | — |
| `subtasks_to_add` | `object[]` | No | — |
| `watch` | `0 \| 1` | No | `1` to have the key’s user watch the new card. |

`title`, `column_id` and `lane_id` are required: Businessmap places every new card in a column and a lane. Businessmap answers with a one-card array; the plugin returns that card as the `data` object, the same shape `cards.get` returns.

## Columns

### create

`columns.create`

Create a main column in a workflow section, or a subcolumn under another column

**Risk:** `write`

```ts
await corsair.kanbanize.api.columns.create({ board_id: 1075, name: 'In progress', position: 1, workflow_id: 1695, section: 3 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `board_id` | `number` | Yes | The board ID, as returned by `boards.list`. |
| `name` | `string` | Yes | — |
| `position` | `number` | Yes | `0` is the leftmost. |
| `workflow_id` | `number` | No | A main column, in a workflow. Needs `section`. Cannot be used with `parent_column_id`. |
| `section` | `1 \| 2 \| 3 \| 4` | No | `1` backlog, `2` requested, `3` progress, `4` done. Required with `workflow_id`. |
| `parent_column_id` | `number` | No | A subcolumn, under this parent. Cannot be used with `workflow_id`. |
| `description` | `string` | No | — |
| `color` | `string` | No | Hexadecimal, such as `a1b2c3`. |

A main column takes `workflow_id` and `section`; a subcolumn takes `parent_column_id` and no section.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `data` | `object` | Yes | — |
