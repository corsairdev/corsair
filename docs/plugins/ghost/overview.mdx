Use **Ghost** through Corsair: one client, typed API calls, and incoming webhooks.

In Ghost Admin, open Settings &gt; Integrations &gt; Add custom integration. Connect its **Admin API key** (`<id>:<secret>`) with the site URL; add its **Content API key** as well to use the `content.*` operations. Things to know before you write:

- **Plans.** Self-hosted Ghost has the whole API. On Ghost(Pro), custom integrations come with the Publisher plan and up, not Starter; the Content API works on every plan.
- **Bodies.** Pass the fields of one object (`title`, `html`, `status`...); the plugin sends them in Ghost's `{ "posts": [ ... ] }` format. Ghost stores content as Lexical: send `html` with `source: "html"` to have Ghost convert it.
- **Edits** need the `updated_at` you last read: a stale value answers 409, so two edits never overwrite each other.
- **Publishing and email.** `status: "published"` puts a post on the live site. Updating a post to published with the `newsletter` query value emails it to members, which can't be taken back. Both are marked `destructive`.
- **Staff.** An integration key can list users and roles and send invites; editing or deleting a staff user needs a staff access token of an Administrator.
- **Webhooks.** Ghost signs each delivery with HMAC-SHA256 of the raw body plus a timestamp, in `X-Ghost-Signature: sha256=<hex>, t=<ms>`, using the webhook's secret. The plugin checks it before handling post, page, tag, member and site events. Ghost 6.45 and later name the event in the body; on older releases add `?event=<name>` (for example `?event=post.published`) to the webhook's target URL so the plugin can route it.

**What you get:**

- 82 typed API operations
- 29 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/ghost better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/ghost better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/ghost better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/ghost better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { ghost } from '@corsair-dev/ghost';

export const corsair = createCorsair({
	plugins: [
		ghost(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the Ghost API key before the first call: `pnpm corsair setup --plugin=ghost --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
ghost()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'ghost',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List posts**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ghost.api.posts.list({});
```


**Create a draft from HTML**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ghost.api.posts.create({
	title: 'Release notes',
	html: '<p>What changed this week.</p>',
	source: 'html',
	status: 'draft',
});
```


See the full list on the [API](/plugins/ghost/api) page.

## Webhooks

This plugin registers **29** webhook event types. Configure the provider to POST to your Corsair HTTP handler, then use `webhookHooks` on the plugin factory.

See [Webhooks](/plugins/ghost/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for routing.
