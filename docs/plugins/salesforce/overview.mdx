Use **Salesforce** through Corsair: one client, typed API calls, optional local DB sync, and incoming webhooks documented below.

**What you get:**

- 225 typed API operations
- 14 database entities synced for fast `.search()` / `.list()` queries
- 7 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
```bash
pnpm install @corsair-dev/salesforce
```

</Step>

<Step title="Add the plugin">
<Tabs>
<Tab title="Solo">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { salesforce } from '@corsair-dev/salesforce';

export const corsair = createCorsair({
	// ... other config options,
	multiTenancy: false,
    plugins: [salesforce()],
});
```
</Tab>
<Tab title="Multi-Tenant">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { salesforce } from '@corsair-dev/salesforce';

export const corsair = createCorsair({
	// ... other config options,
    multiTenancy: true,
    plugins: [salesforce()],
});
```

See [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Tab>
</Tabs>

</Step>

<Step title="Get credentials">
Follow [Get Credentials](/plugins/salesforce/get-credentials) if you need help getting keys.

</Step>

<Step title="Store credentials">
<Tabs>
<Tab title="Solo">
```bash
pnpm corsair setup --plugin=salesforce
```

Use the key names documented in [Get Credentials](/plugins/salesforce/get-credentials) (for example `api_key=`, `bot_token=`, or OAuth client fields).
</Tab>
<Tab title="Multi-Tenant">
```bash
pnpm corsair setup --plugin=salesforce --tenant=<tenantId>
```

Store per-tenant secrets after you create the tenant record. See [Multi-tenancy](/concepts/multi-tenancy).
</Tab>
</Tabs>

</Step>

</Steps>

## Authentication

Each tab shows how to register the plugin for that authentication method. The default `authType` from the plugin does not need to appear in the factory call.

<Tabs>
<Tab title="OAuth 2.0 (Default)">

```ts corsair.ts
salesforce()
```

Store credentials with `pnpm corsair setup --plugin=salesforce` (see [Get Credentials](/plugins/salesforce/get-credentials) for field names). For OAuth, you typically store integration keys at the provider level and tokens per account or tenant.

More: [OAuth 2.0](/concepts/oauth)

</Tab>
<Tab title="API Key">

```ts corsair.ts
salesforce({
    authType: 'api_key',
})
```

Store credentials with `pnpm corsair setup --plugin=salesforce` (see [Get Credentials](/plugins/salesforce/get-credentials) for field names). For OAuth, you typically store integration keys at the provider level and tokens per account or tenant.

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

## Webhooks

This plugin registers **7** webhook handler(s). Configure your provider to POST events to your Corsair HTTP endpoint, then use `webhookHooks` in the plugin factory for custom logic.

See [Webhooks](/plugins/salesforce/webhooks) for every event path and payload shape, and [Webhooks concept](/concepts/webhooks) for how to set up routing.


## Query synced data

Synced entities support `corsair.salesforce.db.<entity>.search()` and `.list()`. See [Database](/plugins/salesforce/database) for filters and operators.


## Example API calls

**Read-style (read):** `accounts.fetchAccountByIdWithQuery`

```ts
await corsair.salesforce.api.accounts.fetchAccountByIdWithQuery({});
```


**Write-style (write):** `accounts.accountCreationWithContentTypeOption`

```ts
await corsair.salesforce.api.accounts.accountCreationWithContentTypeOption({});
```


See the full list on the [API](/plugins/salesforce/api) page. Use `pnpm corsair list --plugin=salesforce` and `pnpm corsair schema <path>` locally to inspect schemas.
