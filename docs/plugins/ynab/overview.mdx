Use **YNAB** through Corsair: one client, typed API calls.

This plugin supports personal use of your own YNAB account only. Never collect another person's personal access token. YNAB requires OAuth for access to other users' accounts, and this plugin does not implement OAuth. The shared tenant-connect examples below do not apply to this plugin. Pass your own token with `ynab({ key: process.env.YNAB_API_KEY! })`.

Create a personal access token in YNAB under **Account Settings → Developer Settings → New Token**. It goes in `Authorization: Bearer` against `https://api.ynab.com/v1`.

- **Amounts are milliunits, not currency.** Every amount is the currency value times 1,000, so $12.34 is `12340` and $1,234.56 is `1234560`. An amount is a whole number of milliunits, so a fractional value is rejected before the request rather than rounded. Reading a milliunit as a decimal is the most common mistake with this API.
- **Outflows are negative.** A $12.34 purchase is `-12340`, and an inflow is positive. The sign carries the direction; there is no separate field.
- **A category assignment replaces, it does not add.** `categories.update` sets the month's budgeted amount to exactly the value given, so sending `50000` makes the month $50 — it does not add $50. Sending `0` clears it.
- **Dates are `yyyy-MM-dd`.** No time and no zone. A month is addressed by its first day, so `2024-06-01` is June.
- **Everything is wrapped in `data`.** Every response is `{ data: … }`, and list endpoints add `server_knowledge` — a counter you can pass back as `last_knowledge_of_server` to receive only what changed since. That is worth using, because a full budget is very large.
- **`budgets.get` returns the whole budget.** Every account, category, payee, month and transaction in one answer, which is huge for a real budget. `last-used` reaches the most recently opened one without listing first.
- **Transactions can be created 500 at a time.** The batch is validated together rather than one call each, and an `import_id` on each makes a repeat safe: a transaction whose import_id already exists on the same account is skipped, not updated, and is reported in `duplicate_import_ids`. Use `transactions.update` for corrections.
- **A split transaction has a null parent category.** When `subtransactions` is non-empty, the parent's `category_id` and `category_name` are null and the amounts live on the splits.
- **Check the error name on a 403.** `subscription_lapsed` requires renewal, `trial_expired` requires a subscription, `unauthorized_scope` requires write permission, `data_limit_reached` means the request exceeds an API data limit, and `email_unconfirmed` requires email confirmation. A 401 indicates a missing, invalid or revoked token.
- **A malformed delta request is rejected whole.** Nothing is partly applied, which is why a 400 is never retried.
- **Memo and payee names are personal.** A memo can name a merchant and a payee can name an employer, so the plugin logs ids, amounts and cleared state rather than text.

**What you get:**

- 24 typed API operations

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/ynab better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/ynab better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/ynab better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/ynab better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { ynab } from '@corsair-dev/ynab';

export const corsair = createCorsair({
	plugins: [
		ynab(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the YNAB API key before the first call: `pnpm corsair setup --plugin=ynab --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

```ts
ynab()
```

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

```ts
const { connectUrl } = await corsair.manage.connect.createLink({
	plugin: 'ynab',
	tenantId: 'acme',
});
// redirect the user's browser to connectUrl
```

</Step>

</Steps>

## Example API calls

**List the accounts in a budget**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ynab.api.accounts.list({ budgetId: 'last-used' });
```


**Record a purchase**

```ts
const tenant = corsair.withTenant('acme');
await tenant.ynab.api.transactions.create({
	budgetId: 'last-used',
	transactions: [{ account_id: 'acc00000-0000-0000-0000-000000000001', date: '2024-06-01', amount: -123450 }],
});
```


See the full list on the [API](/plugins/ynab/api) page.
