## Breakdown Items

### create

`breakdownItems.create`

Create a breakdown item, such as a person, team, product or region; its id is what an entry sends as source_id

**Risk:** `write`

```ts
await corsair.simplekpi.api.breakdownItems.create({ name: 'EMEA', breakdown_id: 12 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | — |
| `breakdown_id` | `number` | No | Omit it for an item that combines several breakdowns. |
| `is_archived` | `boolean` | No | Archive the item. An update replaces the item, so send it again. |
| `sort_order` | `number` | No | Display position. An update replaces the item, so send it again. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `number` | Yes | — |
| `name` | `string \| null` | No | — |
| `breakdown_id` | `number \| null` | No | Null when the item combines more than one breakdown. |
| `user_id` | `number \| null` | No | Set for a People breakdown item, null for every other kind. |
| `is_system` | `boolean \| null` | No | — |
| `is_archived` | `boolean \| null` | No | — |
| `sort_order` | `number \| null` | No | — |
| `created_at` | `string \| null` | No | ISO 8601. |
| `updated_at` | `string \| null` | No | ISO 8601. |

### delete

`breakdownItems.delete`

Delete a breakdown item, which removes that slice from the KPIs that use it; this cannot be undone

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.simplekpi.api.breakdownItems.delete({ id: 77 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `number` | Yes | A positive integer assigned by SimpleKPI. |

SimpleKPI answers 204 but keeps the item, archived (`is_archived: true`), rather than removing it (live, 11-16).



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `number` | Yes | — |
| `deleted` | `true` | Yes | — |

## Kpi Entries

### create

`kpiEntries.create`

Write or update one KPI entry. kpi_id, source_id and entry_date identify it, so the same trio again updates rather than duplicating. A write with every value empty answers stored: false

**Risk:** `write`

```ts
await corsair.simplekpi.api.kpiEntries.create({ kpi_id: 1234, entry_date: '2026-08-03', actual: 42, target: 50, setActual: true, setTarget: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `user_id` | `number \| null` | No | The user the entry is against. |
| `email` | `string \| null` | No | Identifies the user by email instead of user_id. Send one, not both. |
| `kpi_id` | `number` | Yes | — |
| `source_id` | `number \| null` | No | The breakdown source. Omit it for the KPI's default source. |
| `entry_date` | `string` | Yes | A date the KPI's frequency allows. A weekly KPI rejects a mid-week date. |
| `actual` | `number \| null` | No | — |
| `target` | `number \| null` | No | — |
| `notes` | `string \| null` | No | — |
| `setActual` | `boolean` | No | True writes actual, false leaves the stored value untouched. |
| `setTarget` | `boolean` | No | True writes target, false leaves the stored value untouched. |
| `setNotes` | `boolean` | No | True writes notes, false leaves the stored text untouched. |
| `addToActual` | `boolean` | No | True adds actual to the stored value instead of replacing it. |

An upsert on kpi_id, source_id and entry_date. A write with every value empty answers 200 with `{ stored: false }`, which the output models alongside the entry shape.



**Output:** `object`

<AccordionGroup>
<Accordion title="Output full type">

```ts
{
  id: number,
  user_id?: number | null,
  source_id?: number | null,
  kpi_id?: number | null,
  entry_date?: string | null,
  actual?: number | null,
  target?: number | null,
  notes?: string | null,
  created_at?: string | null,
  updated_at?: string | null
} | {
  stored: false,
  source_id?: number | null,
  kpi_id?: number | null,
  entry_date?: string | null,
  detail?: string | null
}
```
</Accordion>
</AccordionGroup>

### list

`kpiEntries.list`

List KPI entries, filtered by user, KPI, breakdown source and date range; narrow by KPI and dates or the response gets large

**Risk:** `read`

```ts
await corsair.simplekpi.api.kpiEntries.list({ kpiId: 1234, dateFrom: '2026-08-01', dateTo: '2026-08-31', rows: 100 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `userId` | `number` | No | Only entries for this user. |
| `kpiId` | `number` | No | Only entries for this KPI. |
| `sourceId` | `number` | No | Only entries for this breakdown source. |
| `dateFrom` | `string` | No | Earliest entry date, inclusive. |
| `dateTo` | `string` | No | Latest entry date, inclusive. |
| `page` | `number` | No | Which page to return, counting from 1. |
| `rows` | `number` | No | How many rows per page, 500 by default. Page until one comes back short, because there is no total. |

All filters are optional, but narrow by kpiId and a date range or the response gets large. Filters are camelCase on this route, unlike the bodies.
