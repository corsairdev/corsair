## Clicks

### export

`clicks.export`

Export raw click rows (time, browser, country, destination, platform, referer, bot, ISP, params) for a workspace or one link. Not in Linkly's OpenAPI spec; Linkly's analytics docs and MCP server use it. Counts against the workspace's analytics allowance (free plans: 100 a month; when a paid plan runs out, Linkly adds a billed API pack).

**Risk:** `read`

```ts
await corsair.linkly.api.clicks.export({ workspace_id: 42, start: '2026-06-01', end: '2026-06-30' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace that owns the links. Find IDs with workspaces.listWorkspaces. |
| `link_id` | `string` | No | A link ID, e.g. "30". One ID also works in link_ids. |
| `start` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `end` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `country` | `string` | No | ISO 3166-1 alpha-2 code, e.g. US. |
| `platform` | `string` | No | — |
| `bots` | `boolean` | No | Include bot clicks. Defaults to false. |



**Output:** `Record<string, any>[] \| object`

<AccordionGroup>
<Accordion title="Output full type">

```ts
Record<string, any>[] | {
  clicks: Record<string, any>[]
}
```
</Accordion>
</AccordionGroup>

### getCounters

`clicks.getCounters`

Group a workspace's clicks by one dimension, such as country or UTM campaign, ordered by count (top 10,000 values). Counts against the workspace's analytics allowance (free plans: 100 a month; when a paid plan runs out, Linkly adds a billed API pack).

**Risk:** `read`

```ts
await corsair.linkly.api.clicks.getCounters({ workspace_id: 42, counter: 'country', start: '2026-06-01', end: '2026-06-30' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace that owns the links. Find IDs with workspaces.listWorkspaces. |
| `counter` | `country \| city \| region \| platform \| destination \| referer \| bot_name \| isp \| link_id \| remote_ip \| top_params \| ad_network \| utm_source \| utm_medium \| utm_campaign \| utm_content \| utm_term` | Yes | The dimension to group clicks by. |
| `link_id` | `string` | No | A link ID, e.g. "30". One ID also works in link_ids. |
| `link_ids` | `string` | No | Hyphen-separated link IDs, e.g. "24-25-26". |
| `start` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `end` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `country` | `string` | No | ISO 3166-1 alpha-2 code, e.g. US. |
| `bots` | `boolean` | No | Include bot clicks. Defaults to false. |
| `unique` | `boolean` | No | Count unique visitors only. |
| `format` | `json` | No | Only 'json', the default. Linkly also serves csv and tsv, which this plugin does not parse. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `total` | `number` | Yes | Clicks across all groups, including any beyond the top 10,000 returned. |
| `values` | `object[]` | Yes | Ordered by count, highest first. |

### getTimeSeries

`clicks.getTimeSeries`

Read click counts over time for a workspace, filtered by link, date range, country and device, optionally pivoted into a links-by-date matrix. Counts against the workspace's analytics allowance (free plans: 100 a month; when a paid plan runs out, Linkly adds a billed API pack).

**Risk:** `read`

```ts
await corsair.linkly.api.clicks.getTimeSeries({ workspace_id: 42, start: '2026-06-01', end: '2026-06-30' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace that owns the links. Find IDs with workspaces.listWorkspaces. |
| `link_id` | `string` | No | A link ID, e.g. "30". One ID also works in link_ids. |
| `link_ids` | `string` | No | Hyphen-separated link IDs, e.g. "24-25-26". |
| `start` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `end` | `string` | No | YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ. |
| `country` | `string` | No | ISO 3166-1 alpha-2 code, e.g. US. |
| `browser` | `string` | No | — |
| `platform` | `string` | No | — |
| `referer` | `string` | No | — |
| `isp` | `string` | No | — |
| `bots` | `boolean` | No | Include bot clicks. Defaults to false. |
| `unique` | `boolean` | No | Count unique visitors only. |
| `format` | `json` | No | Only 'json', the default. Linkly also serves csv and tsv, which this plugin does not parse. |
| `pivot` | `link_id` | No | Return a matrix instead of a time series: dates as rows, links as columns. |
| `timezone` | `string` | No | IANA name for bucket boundaries, e.g. America/New_York. Data is stored in UTC. |
| `frequency` | `day \| hour` | No | Bucket size. Defaults to 'day'. |



**Output:** `object`

## Conversions

### create

`conversions.create`

Report a lead, sale or custom event and attribute it to the link that drove it through its linkly_cid. Unattributable events are discarded and answer attributed: false. Pass event_id so a repeat does not count twice

**Risk:** `write`

```ts
await corsair.linkly.api.conversions.create({ workspace_id: 42, event_name: 'purchase', event_type: 'sale', linkly_cid: '01KYPGEEPJSPR3S564QRBDGA1W', event_id: 'order-1234', amount_cents: 4999, currency: 'USD' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace that owns the links. Find IDs with workspaces.listWorkspaces. |
| `event_name` | `string` | Yes | e.g. purchase or signup. |
| `event_type` | `lead \| sale \| custom` | No | lead for signups and trials, sale when money changes hands. |
| `linkly_cid` | `string` | No | The token Linkly appended to the destination URL. Without it (and no earlier attributed event for external_id) the conversion is discarded. |
| `event_id` | `string` | No | Your id for this event. Repeating it returns the original conversion instead of counting twice, which also makes the call safe to retry. |
| `external_id` | `string` | No | Your customer id; links later events to an earlier attributed one. |
| `amount_cents` | `number` | No | — |
| `currency` | `string` | No | ISO 4217, e.g. USD. |
| `country` | `string` | No | — |
| `occurred_at` | `string` | No | ISO 8601 date-time. Defaults to now. |
| `visitor_ip` | `string` | No | The visitor's IP, for geography. Never returned. |
| `metadata` | `Record<string, any>` | No | — |



**Output:** `object`

<AccordionGroup>
<Accordion title="Output full type">

```ts
{
  id: string,
  link_id?: number | null,
  click_id?: string | null,
  event_type?: string | null,
  event_name?: string | null,
  source?: string | null,
  occurred_at?: string | null,
  inserted_at?: string | null,
  amount_cents?: number | null,
  currency?: string | null,
  country?: string | null,
  event_id?: string | null,
  external_id?: string | null,
  ip_source?: string | null,
  metadata?: Record<string, any> | null
} | {
  attributed: false,
  message?: string | null
}
```
</Accordion>
</AccordionGroup>

### update

`workspaces.update`

Rename a workspace or replace its whole webhook list. Sending webhooks overwrites every registered URL, so a missing one stops receiving events. Not in Linkly's OpenAPI spec; Linkly's own MCP server uses it

**Risk:** `destructive`

```ts
await corsair.linkly.api.workspaces.update({ workspace_id: 42, name: 'Marketing EU' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `workspace_id` | `number` | Yes | The workspace that owns the links. Find IDs with workspaces.listWorkspaces. |
| `name` | `string` | No | A new workspace name. |
| `webhooks` | `string[]` | No | REPLACES the workspace's whole webhook list. Omit to leave it alone; use webhooks.subscribe or webhooks.unsubscribe for one URL. |



**Output:** `Record<string, any>`
