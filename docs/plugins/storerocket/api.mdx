## Locations

### create

`locations.create`

Create a location; name and city are required

**Risk:** `write`

```ts
await corsair.storerocket.api.locations.create({
	projectId: 'PROJECT_ID',
	name: 'Downtown Store',
	city: 'Seattle',
	phone: '555-0101',
	lat: 47.6062,
	lng: -122.3321,
});
```

**Input**

|------|------|----------|-------------|
| `projectId` | `string` | Yes | — |
| `name` | `string` | Yes | — |
| `city` | `string` | Yes | — |
| `slug` | `string` | No | Location slug. |
| `address` | `string \| null` | No | — |
| `address_line_1` | `string \| null` | No | — |
| `address_line_2` | `string \| null` | No | — |

| `facebook` | `string \| null` | No | — |
| `instagram` | `string \| null` | No | — |
| `twitter` | `string \| null` | No | — |
| `yelp` | `string \| null` | No | — |
| `youtube` | `string \| null` | No | — |

Name and city are required. Omit hours or send hours: &#123;&#125; for a coming-soon location; a nonempty hours object must include all seven days. Sending both coordinates avoids depending on the geocoder; check the geocoding object in the response, whose status says whether the address was found, only roughly matched, not found, or queued.

## Special Hours

### create

`specialHours.create`

Create a special-hours rule, with an optional idempotency key

**Risk:** `write`

```ts
await corsair.storerocket.api.specialHours.create({ projectId: "PROJECT_ID", name: "Thanksgiving", holiday_key: "US:thanksgiving-day", start_date: "2026-11-26", hours: "closed", repeats_yearly: true, applies_to: { type: "countries", values: ["US"] }, idempotencyKey: "thanksgiving-2026-us" });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `projectId` | `string` | Yes | — |
| `name` | `string` | Yes | — |
| `start_date` | `string` | Yes | — |
| `end_date` | `string` | No | — |
| `until_further_notice` | `boolean` | No | — |
| `hours` | `closed \| regular \| open_24_hours \| object[]` | Yes | — |
| `repeats_yearly` | `boolean` | No | — |
| `holiday_key` | `string` | No | Stable holiday identifier such as US:thanksgiving-day; needed for repeats_yearly. |
| `holiday_region` | `string` | No | Where a repeating holiday date is read, e.g. AU-QLD. |
| `note` | `string \| null` | No | — |
| `applies_to` | `object` | Yes | — |
| `idempotencyKey` | `string` | No | Sent as the Idempotency-Key header; the same key with the same body replays the first answer. |

Requires name, start_date, hours and applies_to; a missing end_date means the same day, and until_further_notice takes no end_date. The hours value is "closed", "regular", "open_24_hours", or up to six &#123;opens, closes&#125; ranges. repeats_yearly needs a yearly holiday_key on a single day. The same Idempotency-Key with the same body replays the first answer; with a different body it answers 409.
