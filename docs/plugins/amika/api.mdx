### send

`agentSessions.send`

Sends one message to a coding agent (Claude Code or Codex) in a rig and waits for its reply. Without sandbox_id/sandbox_name/sandbox_ref it creates a new rig from repo_url; pass session_id to continue a chat. A failed turn still answers 200 with is_error: true and the agent CLI's own message. Runs on the rig's stored agent credential and can take minutes.

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.amika.api.agentSessions.send({
	message: 'Run the test suite and fix any failing test, then open a pull request.',
	agent: 'claude',
	model: 'opus',
	repo_url: 'https://github.com/acme/web-app',
	new_branch_name: 'fix/failing-tests',
});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `message` | `string` | Yes | — |
| `agent` | `claude \| codex` | No | — |
| `session_id` | `string` | No | — |
| `sandbox_id` | `string` | No | Route into the sandbox with this id instead of a fresh one. Matches by id only; send `sandbox_name` or `sandbox_ref` to name the sandbox. At most one of `sandbox_id`, `sandbox_name`, `sandbox_ref`. |
| `sandbox_name` | `string` | No | Route into the sandbox with this name instead of a fresh one. At most one of `sandbox_id`, `sandbox_name`, `sandbox_ref`. |
| `sandbox_ref` | `string` | No | Route into the sandbox with this id or name instead of a fresh one; 409 `resource_ref_ambiguous` if the value is one sandbox's id and another's name. At most one of `sandbox_id`, `sandbox_name`, `sandbox_ref`. |
| `new_session` | `boolean` | No | — |
| `model` | `fable \| opus \| sonnet \| haiku \| gpt-5.6-sol \| gpt-5.6-terra \| gpt-5.6-luna \| gpt-5.5 \| gpt-5.2 \| null` | No | — |
| `effort` | `low \| medium \| high \| xhigh \| max \| null` | No | — |
| `repo_url` | `string` | No | — |
| `branch` | `string` | No | — |
| `new_branch_name` | `string` | No | — |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `session_id` | `string \| null` | No | — |
| `sandbox_id` | `string \| null` | No | — |
| `agent` | `string \| null` | No | — |
| `response` | `string \| null` | No | — |
| `is_error` | `boolean \| null` | No | True when the turn failed. The failure is still a 200: `response` carries the agent CLI's own message (e.g. "Not logged in · Please run /login"). |
| `is_new_session` | `boolean \| null` | No | — |
| `created_sandbox` | `boolean \| null` | No | — |
| `usage` | `object \| null` | No | — |

<AccordionGroup>


**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string` | Yes | Command run id (`cr_…`). |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `id` | `string \| null` | No | Command run id (`cr_…`). |
| `rig_id` | `string \| null \| null` | No | Rig the run runs on. Null after the rig is deleted. |
| `rig_name` | `string \| null \| null` | No | Name of the rig. Null after the rig is deleted. |

### create

`commandRuns.create`

Queues one shell command on a rig (run with bash -e -o pipefail) and answers at once. Name an existing rig (rig_id, rig_name or rig_ref) or create one with rig_create; a stopped rig is started. **Risk:** `destructive` · **Irreversible**

## Jobs

### create

`jobs.create`

Creates a job: a cron trigger and 1 to 20 shell steps. Each time the trigger fires, a job run runs the steps in order on one rig. Step 0 names the rig with exactly one of rig_id, rig_name, rig_ref or rig_create; later steps name none and run on step 0's rig. Set enabled false to create it paused. An idempotencyKey is made for you when you leave it out.

**Risk:** `destructive`

```ts
await corsair.amika.api.jobs.create({
	name: 'nightly-tests',
	description: 'Install and run the suite every night',
	trigger: { kind: 'cron', schedule: '0 3 * * *', timezone: 'America/New_York' },
	steps: [{ rig_ref: 'dev-rig', command: 'pnpm install --frozen-lockfile', timeout_ms: 600000 }, { command: 'pnpm test', timeout_ms: 1800000 }],
	rig_status_on_finish: 'stopped',
	enabled: true,
});
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `idempotencyKey` | `string` | No | Idempotency-Key header: a retry with the same key and body returns the run or job this key already made. Leave it out and the plugin sends a new random key. |
| `name` | `string` | Yes | Unique name in the organization. |
| `description` | `string` | No | Free text for people. |
| `trigger` | `object` | Yes | — |
| `steps` | `object[]` | Yes | 1 to 20 commands. A job run runs them in order, one command run each. A step starts only after the previous step succeeds. |
| `rig_status_on_finish` | `active \| stopped \| deleted` | No | Status to give the rig when the job run ends, after success or failure. When set, the rig stays up between steps. Omit to restore the rig's status from before the job run. |
| `overlap_policy` | `skip \| allow` | No | `skip` (default): do not start a scheduled job run while an earlier run of this job is `pending` or `running`; record it as `skipped`. `allow`: start it. |
