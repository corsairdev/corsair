The fal plugin handles incoming webhooks. Point your provider’s subscription URL at your Corsair HTTP handler (see [Overview](/plugins/fal/overview) for setup context and the exact URL shape).

<Info>
**New to Corsair?** See [webhooks](/concepts/webhooks) and [hooks](/concepts/hooks).
</Info>

## Webhook map

- `requests`
  - `completed` (`requests.completed`)

## HTTP handler setup

```ts app/api/webhook/route.ts
import { processWebhook } from "corsair";
import { corsair } from "@/server/corsair";

export async function POST(request: Request) {
    const headers = Object.fromEntries(request.headers);
    const body = await request.json();
    const result = await processWebhook(corsair, headers, body);
    return result.response;
}
```

## Requests

### Completed

`requests.completed`

A queued request finished: status OK with the model output, or ERROR with the error. Signed by fal (Ed25519).

**Payload**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `request_id` | `string` | Yes | — |
| `gateway_request_id` | `string \| null` | No | The last attempt’s id; differs from request_id when fal retried. |
| `status` | `OK \| ERROR` | Yes | OK: payload is the model output. ERROR: payload is the error body. |
| `payload` | `Record<string, any> \| null` | Yes | — |
| `error` | `string \| null` | No | — |
| `payload_error` | `string \| null` | No | Set when fal could not include the output; read it with queue.result. |

**`webhookHooks` example**

```ts
fal({
    webhookHooks: {
        requests: {
            completed: {
                before(ctx, args) {
                    return { ctx, args };
                },
                after(ctx, response) {
                },
            },
        },
    },
})
```
