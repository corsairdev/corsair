### run

`models.run`

Run a model and wait up to waitSeconds (default 10) for its output; spends fal credits. SUCCEEDED and FAILED are final. IN_QUEUE or IN_PROGRESS is a job to follow with queue.status; video, audio and training usually take longer than the wait.

**Risk:** `write`

```ts
await corsair.fal.api.models.run({ endpointId: 'fal-ai/flux/schnell', input: { prompt: 'A paper boat on a pond', image_size: 'square' }, waitSeconds: 10 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `endpointId` | `string` | Yes | fal model endpoint id, for example fal-ai/flux/schnell or fal-ai/kling-video/v2.1/master/text-to-video. Find ids with models.search. |
| `input` | `Record<string, any>` | Yes | The model's input fields, for example &#123; prompt: 'a lighthouse at dawn' &#125;. Each model has its own; read them with models.search(&#123; endpointIds: [id], includeOpenApi: true &#125;). |
| `webhookUrl` | `string` | No | An https URL fal POSTs the result to when the request completes (signed; see the requests.completed webhook). |
| `priority` | `normal \| low` | No | low puts it behind your other requests to this endpoint. |
| `startTimeout` | `number` | No | Seconds fal may wait for a runner before giving up (504). Does not limit run time. |
| `hint` | `string` | No | Routing hint: requests with the same hint go to the same runner. |
| `noRetry` | `boolean` | No | true turns off fal’s automatic retries for this request. |
| `maxQueueLength` | `number` | No | Reject with 429 if this many requests are already queued. |
| `waitSeconds` | `number` | No | How long models.run waits after submitting, default 10 and at most 15 seconds. |

Goes through fal's queue, so a run that outlasts `waitSeconds` is not lost. It answers with the same fields as `queue.status`. SUCCEEDED and FAILED are final; only IN_QUEUE or IN_PROGRESS need following, with `queue.status({ responseUrl })`.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `status` | `string` | Yes | fal's raw queue status: IN_QUEUE, IN_PROGRESS or COMPLETED. A failed or cancelled request is COMPLETED too, so read `state` for the outcome. |
| `request_id` | `string` | Yes | — |
| `response_url` | `string` | Yes | Pass to queue.status as responseUrl to follow a run still going. |
| `status_url` | `string \| null` | No | — |
| `cancel_url` | `string \| null` | No | — |
| `queue_position` | `number \| null` | No | — |
| `logs` | `object[] \| null` | No | — |
| `metrics` | `object \| null` | No | — |
| `error` | `string \| null` | No | — |
| `error_type` | `string \| null` | No | — |
| `state` | `IN_QUEUE \| IN_PROGRESS \| SUCCEEDED \| FAILED` | Yes | IN_QUEUE or IN_PROGRESS while it runs; SUCCEEDED with output, or FAILED with error, once it is done. |
| `output` | `Record<string, any>` | No | The model output. Its shape is model-specific: image models return images[].url, video models video.url, audio models audio.url. fal media URLs expire, so save files you want to keep. |

```ts
}[] | null
```

## Queue

### cancel

`queue.cancel`

Cancel a queued request: removed if still waiting, asked to stop if running

**Risk:** `write`

```ts
await corsair.fal.api.queue.cancel({ endpointId: 'fal-ai/flux/schnell', requestId: '<request id>' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `endpointId` | `string` | No | The endpoint id the request was submitted to. Pass it with requestId. |
| `requestId` | `string` | No | The request_id queue.submit returned. Pass it with endpointId. |
| `responseUrl` | `string` | No | Instead of endpointId + requestId: the response_url queue.submit returned. |

Pass `endpointId` and `requestId`, or the `responseUrl` that `queue.submit` returned. A request that already finished answers ALREADY_COMPLETED instead of an error.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `status` | `OK \| CANCELLATION_REQUESTED \| ALREADY_COMPLETED \| NOT_FOUND` | Yes | OK: removed from the queue, never runs. CANCELLATION_REQUESTED: running, fal asked the runner to stop (it may still finish). ALREADY_COMPLETED or NOT_FOUND: nothing to cancel. |

### status

| `responseUrl` | `string` | No | Instead of endpointId + requestId: the response_url queue.submit returned. |

Pass `endpointId` and `requestId`, or the `responseUrl` that `queue.submit` returned. fal marks failed requests COMPLETED as well, so once it does this reads the result and answers `state` SUCCEEDED with `output`, or FAILED with `error`.

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.fal.api.requests.deletePayloads({ requestId: '<request id>' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `requestId` | `string` | Yes | — |

Needs a full-access fal key; inference-only keys get 403. Deletes the request's stored input and output payloads and the files it generated, for good. **Output**
