Use **fal** through Corsair: one client, typed API calls, and incoming webhooks.

Every model on fal takes its own input fields. Look them up with `models.search({ endpointIds: ['<endpoint id>'], includeOpenApi: true })`, then pass them as `input`.

Video, audio and training runs usually take minutes. After submitting, `models.run` waits up to 10 seconds (at most 15). When it sees the run end within the wait, it answers a final `state`: SUCCEEDED with `output`, or FAILED with `error` (bad input or a model error), and there is nothing to follow. Any other answer carries the run's `response_url` and IN_PROGRESS or IN_QUEUE. IN_QUEUE also covers a read that failed or ran out of time, so the run may already have started or even finished at fal. Follow every IN_QUEUE or IN_PROGRESS answer with `queue.status({ responseUrl })` until it says SUCCEEDED or FAILED, or pass `webhookUrl` and let fal post the result. On Corsair's cloud, `get_job` and the job card do the following for you.

**What you get:**

- 14 typed API operations
- 1 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/fal better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/fal better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/fal better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/fal better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { fal } from '@corsair-dev/fal';

export const corsair = createCorsair({
	plugins: [
		fal(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Tabs>

Store the fal API key before the first call: `pnpm corsair setup --plugin=fal --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

## Example API calls

**Find text-to-video models**

```ts
const tenant = corsair.withTenant('acme');
await tenant.fal.api.models.search({ category: 'text-to-video', limit: 5 });
```


**Generate an image**

```ts
const tenant = corsair.withTenant('acme');
await tenant.fal.api.queue.submit({
	endpointId: 'fal-ai/flux/schnell',
	input: { prompt: 'A watercolor lighthouse on a cliff at dawn', image_size: 'square_hd' },
});
```


See the full list on the [API](/plugins/fal/api) page.

## Webhooks

Pass `webhookUrl` to `queue.submit` and fal POSTs the result there when the request finishes. Hand `processWebhook` the raw body text (`await request.text()`), not parsed JSON. fal signs the exact bytes it sent; a parsed body is rebuilt as a best effort, which fails for outputs with whole-number floats or integers past 2^53. To hold deliveries to one fal account, store its fal user id (the `x-fal-webhook-user-id` header) as the account's `user_id`.

```ts
fal({
    webhookHooks: {
        requests: {
            completed: {
                after: async (ctx, result) => {
                    if (result.data?.status === 'OK') console.log(result.data.request_id, result.data.payload);
                }
            },
        },
    },
})
```

Mount your framework handler once (see [Frameworks](/frameworks/next)), then point the provider at that URL. Full event list: [Webhooks](/plugins/fal/webhooks). Concepts: [Webhooks](/concepts/webhooks), [Hooks](/concepts/hooks).
