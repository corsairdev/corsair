## Credentials

### delete

`credentials.delete`

Delete a credential metadata record; this does not revoke the credential

**Risk:** `destructive` · **Irreversible**

```ts
await corsair.truvera.api.credentials.delete({ credential_id: 'https://creds.truvera.io/1234' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `credential_id` | `string` | Yes | — |
| `password` | `string` | No | Deprecated: only for retrieving a persisted credential body |

Deletes the metadata record only. The credential itself stays valid, so use `credentials.revoke` first.



**Output:** `object \| undefined`

```ts

} | undefined
```

### issue

`credentials.issue`

Issue and sign a verifiable credential, optionally distributing it to a holder, persisting it, or making it revocable

**Risk:** `destructive`

```ts
await corsair.truvera.api.credentials.issue({ credential: { issuer: 'did:cheqd:mainnet:ac2b9027-ec1a-4ee2-aad1-1e316e7d6f59', type: ['BasicCredential'], subject: { id: 'did:key:z6Mkq...', name: 'A. Holder' } }, revocable: true });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `credential` | `object` | Yes | The credential to sign |
| `persist` | `boolean` | No | Store an encrypted copy; requires `password` |
| `password` | `string` | No | Encrypts a persisted credential; never stored by the plugin |
| `recipient_did` | `string` | No | The holder's DID for DID distribution |
| `recipient_email` | `string` | No | The holder's email for email distribution |
| `algorithm` | `string` | No | Signing algorithm; dockbbs enables zero-knowledge proofs |
| `distribute` | `boolean` | No | — |
| `format` | `jsonld \| jwt \| sdjwt` | No | Default jsonld |
| `revocable` | `boolean` | No | Provision a revocation registry automatically |

The issuer must be a DID the account controls. `persist` needs `password`, and `distribute` needs a recipient; both are checked before the request.

### revoke

`credentials.revoke`

Revoke a credential, which makes every verification of it fail

**Risk:** `destructive`

```ts
await corsair.truvera.api.credentials.revoke({ credential_id: 'https://creds.truvera.io/1234' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `credential_id` | `string` | Yes | The credential URI, as the issue or list route returned it |

Makes every verification of the credential fail. It can be undone with `credentials.unrevoke` only when the registry was created with `add_only: false`; in an add-only registry (the default) the revocation is permanent.



**Output:** _empty object_

## Dids

### create

`dids.create`

Create a DID with its keys, optionally with a DIDComm service endpoint

**Risk:** `destructive`

```ts
await corsair.truvera.api.dids.create({ type: 'cheqd', key_type: 'ed25519' });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `type` | `string` | No | DID method, such as cheqd, key, or dock |
| `key_type` | `string` | No | Signing key type, such as ed25519 or secp256k1 |
| `controller` | `string` | No | Controller DID, when it is not the DID itself |
| `didcomm_service_url` | `string` | No | DIDComm endpoint to add to the document |
| `include_didcomm_service` | `boolean` | No | — |

A DID with a DIDComm service endpoint needs `didcomm_service_url`. Deleting a DID leaves credentials signed with it unverifiable against that DID.

| `did` | `string \| null` | No | — |
| `controller` | `string \| null` | No | — |
