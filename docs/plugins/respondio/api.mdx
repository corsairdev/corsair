### addTags

**Risk:** `write`

```ts
await corsair.respondio.api.contacts.addTags({ identifier: 'id:1', tags: ['vip', 'renewal'] });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `identifier` | `string` | Yes | — |
| `tags` | `string[]` | Yes | The tags to add or remove, 1 to 10. |



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `contactId` | `number \| null` | No | The ID of the contact the action was performed on. |

### list

`contacts.list`

List contacts with an $and or $or filter over fields, tags and lifecycle, a free-text search, and cursor paging

**Risk:** `read`

```ts
await corsair.respondio.api.contacts.list({ filter: { $and: [{ category: 'contactTag', field: 'vip', operator: 'hasAnyOf', value: ['vip'] }] }, timezone: 'Asia/Kuala_Lumpur', limit: 50 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `filter` | `object` | No | Every condition in $and must hold; any one in $or must. Defaults to no conditions. |
| `search` | `string` | No | A free-text search across the contacts. Defaults to empty, which matches every contact. |
| `timezone` | `string` | No | An IANA timezone used to interpret any timestamp condition, such as Asia/Kuala_Lumpur. Defaults to UTC. |
| `limit` | `number` | No | Page size, 1 to 99. respond.io defaults to 10. |
| `cursorId` | `string \| number` | No | Where the page starts: the previous pagination.next URL as it is, or the cursorId value from it. |

<AccordionGroup>
<Accordion title="filter full type">

```ts
{
  $and?: {
    category: contactField | contactTag | lifecycle,
    field: string,
    operator: isEqualTo | isNotEqualTo | isTimestampAfter | isTimestampBefore | isTimestampBetween | exists | doesNotExist | isGreaterThan | isLessThan | isBetween | hasAnyOf | hasAllOf | hasNoneOf,
    value?: string | string[] | {
      from: string,
      to: string
    }
  }[],
  $or?: {
    category: contactField | contactTag | lifecycle,
```

| `includeComments` | `boolean` | No | True mixes the contact's comments into the list, each item then carrying a type of message or comment. A page can be empty while pagination.next is still set, so keep paging until next is null. |

| `items` | `Record<string, JsonValue>[] \| null` | No | A message or, with includeComments, a comment. Each carries `type` only when includeComments was true. |
