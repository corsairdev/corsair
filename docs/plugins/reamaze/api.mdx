## Articles

### create

`articles.create`

Create a help center article under a topic

**Risk:** `write`

```ts
await corsair.reamaze.api.articles.create({ topic: 'the-federalist-papers', title: 'Returns policy', body: 'Send it back within 30 days.', status: 1 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `topic` | `string` | Yes | Topic slug the article is filed under |
| `title` | `string` | Yes | — |
| `body` | `string` | Yes | — |
| `status` | `0 \| 1 \| 4` | No | 0 published, 1 draft, 4 internal |
| `topic_id` | `string` | No | Topic slug carried in the body |

Posts to the topic named by `topic`, with the payload wrapped in `article`. The numeric `status` is 0 published, 1 draft or 4 internal.

## Contacts

### create

`contacts.create`

Create a contact for the account

**Risk:** `write`

```ts
await corsair.reamaze.api.contacts.create({ name: 'bob', email: 'bob@example.com', data: { plan: 'pro' } });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | — |
| `email` | `string` | No | Either this or mobile is required |
| `mobile` | `string` | No | E.164 without spaces, e.g. +12223334444. Either this or email is required |
| `id` | `string` | No | Your own id for this contact |
| `external_avatar_url` | `string` | No | — |
| `notes` | `string[]` | No | Plain note bodies attached at creation |
| `data` | `Record<string, any>` | No | Customer data attributes, one level deep |

Wraps the payload in `contact` and answers `{ contact }`. Pass an `email` or a `mobile` number in E.164 form; other contact types cannot be created. `notes` is an array of note bodies attached at creation, and `data` becomes the customer data attributes.



**Output**

### list

`conversations.list`

List conversations, filtered by status, assignee, tag, channel, origin or date

**Risk:** `read`

```ts
await corsair.reamaze.api.conversations.list({ filter: 'open', sort: 'updated', page: 1 });
```

**Input**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `filter` | `archived \| open \| unassigned \| all` | No | Defaults to unarchived conversations only |
| `for` | `string` | No | User email; returns conversations visible to that customer |
| `for_id` | `string` | No | SSO user id; the same filter as `for` |
| `sort` | `updated \| changed` | No | updated orders by last customer message, changed by any update. Default is created_at |
| `tag` | `string` | No | Comma-separated tags, all must match |
| `category` | `string` | No | Channel slug |
| `page` | `number` | No | Page number, 1-based. The response carries page_size and page_count |
| `start_date` | `string` | No | ISO 8601; filters on the latest customer message time |
| `end_date` | `string` | No | ISO 8601; filters on the latest customer message time |
| `origin` | `number \| string` | No | Origin number (1 email) or name (email) |
| `data` | `Record<string, any>` | No | Sent as one `data[key]=value` query entry per key, ANDed by the API |

Answers `{ conversations, page_size, page_count, total_count }`. `filter` takes `archived`, `open`, `unassigned` or `all`; omitting it returns unarchived conversations only. `data` is sent as one `data[key]=value` entry per key, so `data: { plan: 'pro' }` becomes `data[plan]=pro`.



**Output**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `conversations` | `object[]` | Yes | — |
| `page_size` | `number \| null` | No | — |
| `page_count` | `number \| null` | No | — |
| `total_count` | `number \| null` | No | — |
