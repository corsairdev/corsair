---

Use **ERPNext** through Corsair: one client, typed API calls, optional local DB sync.

Authenticate with a Frappe token pair: `Authorization: token <api_key>:<api_secret>`, created per user under Settings > My Settings > API Access. Every ERPNext deployment is its own tenant, so the plugin takes a `baseUrl` option (the site origin, for example `https://yourcompany.frappe.cloud`).

This plugin implements the requested 51 operations over the generic Frappe REST surface. Inbound webhooks are not included.

**What you get:**

- 51 typed API operations
- 1 database entity synced for fast `.search()` / `.list()` queries

## Setup

<Steps>

<Step title="Install">
```bash
pnpm install @corsair-dev/erpnext
```

</Step>

<Step title="Add the plugin">
<Tabs>
<Tab title="Solo">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { erpnext } from '@corsair-dev/erpnext';

export const corsair = createCorsair({
	// ... other config options,
	multiTenancy: false,
    plugins: [erpnext()],
});
```
</Tab>
<Tab title="Multi-Tenant">
```ts corsair.ts
import { createCorsair } from 'corsair';
import { erpnext } from '@corsair-dev/erpnext';

export const corsair = createCorsair({
	// ... other config options,
    multiTenancy: true,
    plugins: [erpnext()],
});
```

See [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Tab>
</Tabs>

</Step>

<Step title="Get credentials">
Follow [Get Credentials](/plugins/erpnext/get-credentials) if you need help getting keys.

</Step>

<Step title="Store credentials">
<Tabs>
<Tab title="Solo">
```bash
pnpm corsair setup --plugin=erpnext
```

Use the key names documented in [Get Credentials](/plugins/erpnext/get-credentials) (for example `api_key=`, `bot_token=`, or OAuth client fields).
</Tab>
<Tab title="Multi-Tenant">
```bash
pnpm corsair setup --plugin=erpnext --tenant=<tenantId>
```

Store per-tenant secrets after you create the tenant record. See [Multi-tenancy](/concepts/multi-tenancy).
</Tab>
</Tabs>

</Step>

</Steps>

## Authentication

Each tab shows how to register the plugin for that authentication method. The default `authType` from the plugin does not need to appear in the factory call.

<Tabs>
<Tab title="API Key (Default)">

```ts corsair.ts
erpnext()
```

Store credentials with `pnpm corsair setup --plugin=erpnext` (see [Get Credentials](/plugins/erpnext/get-credentials) for field names). For OAuth, you typically store integration keys at the provider level and tokens per account or tenant.

More: [API Key](/concepts/api-key)

</Tab>
</Tabs>


## Query synced data

Synced entities support `corsair.erpnext.db.<entity>.search()` and `.list()`. See [Database](/plugins/erpnext/database) for filters and operators.


## Example API calls

**Read-style (read):** `desk.searchGlobal`

```ts
await corsair.erpnext.api.desk.searchGlobal({});
```


**Write-style (write):** `desk.addComment`

```ts
await corsair.erpnext.api.desk.addComment({});
```


See the full list on the [API](/plugins/erpnext/api) page. Use `pnpm corsair list --plugin=erpnext` and `pnpm corsair schema <path>` locally to inspect schemas.
