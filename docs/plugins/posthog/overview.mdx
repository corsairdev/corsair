Use **PostHog** through Corsair: one client, typed API calls, local DB sync, and incoming webhooks.

The key you connect decides what the plugin can do:

- **Personal API key (`phx_...`)**: every action. Read actions call PostHog's private API (`/api/projects/{project_id}/...`), and capture looks up the project token (needs `project:read`). Create one under Settings → Personal API keys and tick the read scopes you need (see [Get Credentials](/plugins/posthog/get-credentials)).
- **Project token (`phc_...`)**: the five capture actions only (`events.eventCreate`, `aliasCreate`, `identityCreate`, `trackPage`, `trackScreen`). Read actions throw an error asking for a personal key.

Things to know before you call:

- **`project_id` comes from the connection, and any call can override it.** It is the number in your PostHog URL (`/project/12345`). Every private-API action takes an optional `project_id` (capture always uses the connected project), so a key scoped to all projects (or all organizations) works across them; `organizations.list` and `projects.list` show what the key reaches.
- **Writes match the PostHog MCP.** Insights, dashboards, flags, cohorts, experiments, surveys, annotations, actions, notebooks and person properties. Experiments and surveys are created and edited as drafts; launching stays in PostHog. Deleting an insight, dashboard, flag or annotation flags it `deleted` (restorable in PostHog); deleting a survey is permanent.
- **Some reads run as queries.** `events.list` (EventsQuery, PostHog's replacement for the deprecated events endpoint), `webAnalytics.overview` / `webAnalytics.stats`, `llmAnalytics.traces` (TracesQuery) and `llmAnalytics.costs` (HogQL over `$ai_generation` events) all need only the `query` read scope.
- **Region is detected for personal keys.** Without `host`, the first call goes to the US cloud and a 401 retries once on the EU cloud. A `phc_` token uses the US host unless `host` is set. Set `host` for self-hosted PostHog (https, or http on localhost).
- **`query.run` is the general tool.** Pass a HogQL string (`select event, count() from events group by event`) or any PostHog query object with a `kind` (`TrendsQuery`, `FunnelsQuery`, `RetentionQuery`...). List event and property names first with `eventDefinitions.list` and `propertyDefinitions.list`.
- **`logs.query` searches PostHog Logs** by service, severity, text or attribute; keep the window short (default last hour).
- **Error tracking issues come from an `ErrorTrackingQuery`**, so each issue carries occurrence, user and session counts for the date range (last 7 days by default).
- **`featureFlags.update` replaces `filters` whole.** Read the flag with `featureFlags.get` first and send back the full release conditions with your change.

**What you get:**

- 71 typed API operations
- 1 synced entity (`events`) for fast `.search()` / `.list()`
- 1 incoming webhook event types

## Setup

<Steps>

<Step title="Install">
<CodeGroup>
```bash npm
npm install corsair @corsair-dev/posthog better-sqlite3
npm install --save-dev @types/better-sqlite3
```
```bash yarn
yarn add corsair @corsair-dev/posthog better-sqlite3
yarn add --dev @types/better-sqlite3
```
```bash pnpm
pnpm install corsair @corsair-dev/posthog better-sqlite3
pnpm install --save-dev @types/better-sqlite3
```
```bash bun
bun add corsair @corsair-dev/posthog better-sqlite3
bun add --dev @types/better-sqlite3
```
</CodeGroup>

</Step>

<Step title="Add the plugin">
```ts corsair.ts
import Database from 'better-sqlite3';
import { createCorsair } from 'corsair';
import { posthog } from '@corsair-dev/posthog';

export const corsair = createCorsair({
	plugins: [
		posthog(),
	],
	database: new Database('corsair.db'),
	kek: process.env.CORSAIR_KEK!,
	multiTenancy: true,
	hub: {
		projectApiKey: process.env.CORSAIR_API_KEY!,
		signingSecret: process.env.CORSAIR_SIGNING_SECRET!,
	},
});
```

With `multiTenancy: true`, scope calls with `corsair.withTenant(id)`. See [Quick start](/quick-start) for KEK + Hub keys, and [Multi-tenancy](/concepts/multi-tenancy) for account isolation.

</Step>

<Step title="Choose authentication">
<Tabs>
<Tab title="API Key (Recommended)">

Store the PostHog API key before the first call: `pnpm corsair setup --plugin=posthog --tenant=acme api_key=<your-key>` (leave out `--tenant` without `multiTenancy`), or pass it as `key` in the plugin options. With Hub, each tenant enters their own key on the connect page. See [API key auth](/concepts/api-key).

Provider walkthrough: [Get Credentials](/plugins/posthog/get-credentials).

posthog()

</Tab>

</Step>

<Step title="Connect a tenant">
Mint a connect link and send the tenant to it. Hub hosts the page and delivers the result to your app — see [Connect / OAuth](/management/connect).

const { connectUrl } = await corsair.manage.connect.createLink({

## Example API calls

**Count yesterday's events with HogQL**

```ts
const tenant = corsair.withTenant('acme');
await tenant.posthog.api.query.run({ query: 'select event, count() from events where timestamp > now() - interval 1 day group by event order by count() desc limit 10' });
```


**Capture an event**

```ts
const tenant = corsair.withTenant('acme');
await tenant.posthog.api.events.eventCreate({ distinct_id: 'abc123', event: 'corsair_example' });
```


See the full list on the [API](/plugins/posthog/api) page.

## Query synced data

Search synced events without hitting PostHog.

```ts
const tenant = corsair.withTenant('acme');
const rows = await tenant.posthog.db.events.search({
	data: {},
	limit: 50,
});
```

Synced entities: `events`. See [Database](/plugins/posthog/database) for filters and operators.

## Webhooks

Fires when a PostHog event is captured.

```ts
posthog({
    webhookHooks: {
        events: {
            captured: {
                after: async (ctx, result) => {
                    console.log('PostHog event captured:', result.data);
                }
            },
        },
    },
})
```

Mount your framework handler once (see [Frameworks](/frameworks/next)), then point the provider at that URL. Full event list: [Webhooks](/plugins/posthog/webhooks). Concepts: [Webhooks](/concepts/webhooks), [Hooks](/concepts/hooks).
