This guide walks you through obtaining all required credentials for the PostHog plugin.

## Authentication Method

The PostHog plugin uses API key authentication (`api_key`) plus your project id (`project_id`). Which key you store decides what works:

| Key | Prefix | Works for |
|-----|--------|-----------|
| Personal API key (recommended) | `phx_` | Every action: HogQL queries, insights, dashboards, persons, feature flags, recordings, error tracking, experiments, surveys, cohorts, actions, annotations, definitions, and capture |
| Project token | `phc_` | Capture only (`events.*`) |

With a personal key, capture still works: the plugin reads the project token from your project once and uses it.

## Personal API Key Setup

### Step 1: Create the key

1. In PostHog, open **Settings** → **Personal API keys** (`/settings/user-api-keys`)
2. Click **Create personal API key** and give it a label such as "Corsair"
3. Under **Scopes**, choose **Specific scopes** and give **Read** on:
   `query`, `insight`, `dashboard`, `person`, `feature_flag`, `session_recording`, `error_tracking`, `experiment`, `survey`, `cohort`, `action`, `annotation`, `event_definition`, `property_definition`, `project`
4. Give **Write** on `feature_flag` and `annotation` only if you want `featureFlags.update` and `annotations.create`
5. Limit the key to the project you will connect, then copy it (it is shown once)

A call whose scope is missing returns 403; the rest keep working.

### Step 2: Find your project id

Open any page of your project: the number after `/project/` in the URL is the project id (for example `https://us.posthog.com/project/12345`). It is also under **Settings** → **Project** → **Project ID**.

### Step 3: Store the credentials

```bash
pnpm corsair setup --plugin=posthog api_key=phx_your-personal-key project_id=12345
```

Verify it was saved:

```bash
pnpm corsair auth --plugin=posthog --credentials
```

US and EU cloud are detected on the first call. For self-hosted PostHog, pass the host when you create the plugin:

```ts
posthog({ host: 'https://posthog.example.com' })
```

## Project Token (capture only)

If you only send events, a project token is enough: **Settings** → **Project** → **Project token** (starts with `phc_`). Store it as `api_key` the same way. Read actions will ask for a personal key.

## Webhook Secret

### Step 1: Create Webhook Destination

1. Go to your PostHog project settings
2. Navigate to **Data Pipelines** → **Destinations**
3. Click **New destination**
4. Select **Webhook** as the destination type
5. Configure:
   - **Webhook URL**: Your webhook endpoint (e.g., `https://yourapp.com/api/webhook`)
   - **Events**: Select `event_captured` or all events
6. Click **Save**
7. If a webhook secret is provided, copy it and store securely

**Storing Credentials:**

Store the webhook secret with the CLI:

```bash
pnpm corsair setup --plugin=posthog webhook_signature=your-webhook-secret
```

## Required Credentials Summary

| Credential | Required For | Where to Find |
|-----------|--------------|---------------|
| Personal API Key (`phx_`) | Every action | Settings → Personal API keys |
| Project id | Read actions | The number after `/project/` in the PostHog URL |
| Project token (`phc_`) | Capture only, if you don't use a personal key | Settings → Project → Project token |
| Webhook Secret | Webhooks | Data Pipelines → Destinations → Webhook |

For general information about how Corsair handles authentication, see [Authentication](/concepts/auth).
