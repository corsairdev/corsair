```
Base URL  https://auth.corsair.dev/v1/projects/{slug}
Auth      Authorization: Bearer ck_cloud_<slug>.<secret>
```

This API reads and writes project configuration: instances, integrations,
tenants, access rows, MCP links, and connect sessions. Anything the Corsair
console does by hand, you can do here over HTTP.

It does not run tool calls. An operation for a tenant executes on the
instance's own URL through the [Corsair SDK](/introduction), and nothing on that
path can change the project.

## Two planes, two hosts

| Host | Serves |
|---|---|
| `auth.corsair.dev/v1/projects/{slug}/…` | management, this API, on the hub |
| the instance's `url`, on `api.corsair.cloud` | tool calls, on your project's runtime |

A management write returns as soon as the hub commits it. It does not call your
runtime and does not wait on one, so a write succeeds whether or not the
instance is deployed.

## One key, one project

Every request carries one bearer token, your project key:

```
Authorization: Bearer ck_cloud_<slug>.<secret>
```

The `{slug}` in the path must match the slug the key carries. Naming another
project's slug returns `404`. One key has full authority over one project, with
no tenant scope and no read-only mode. Keep it server-side, never in a browser
or a mobile app. See [Authentication](/v1-guides/authentication).

## Resources

- **Instances** are your runtime boundary. One might be `prod`, another
  `staging`. Each is credential-isolated, so a call scoped to `staging` cannot
  write on `prod`. An instance's `url` is where its tool calls execute, and is
  `null` until it is deployed.
- **Integrations** are the providers enabled on one instance, addressed as
  `instance:integration` (`prod:slack`). Each has an `auth_type`: Corsair's own
  OAuth app (`managed`) or your own credentials. `GET /integrations/catalog`
  lists every provider Corsair ships and which support `managed`.
- **Tenants** are the people you serve. You pick the id (`usr_8841`, a user row
  id, whatever you map to). Corsair holds their tokens; you never see them.
- **Access** is one row per `instance:tenant`, at a permission of `readonly`,
  `readwrite`, or `admin`. Minting a link requires the row to exist already.
- **Connections** are one tenant's auth for one integration on one instance,
  addressed as `instance:integration:tenant`. Fix the axes you care about and
  list the rest: `GET /connections?instance=prod&tenant=usr_8841`.
- **MCP links** are URLs scoped to a set of `(instance, tenant, permission)`
  rows. Paste one into any MCP client as a custom connector.

<Callout title="No endpoint accepts a token">
There is no write path for credentials. To connect a tenant, create a connect
session and redirect them to the URL it returns, so they authorize the
integration themselves. `GET /connections` reads back the result and its status.
</Callout>

## Conventions

Fields are `snake_case`. Lists come back in one envelope, always:

```json
{ "object": "list", "data": [ ... ], "has_more": false, "next_cursor": null }
```

Page with `limit` and `starting_after`, passing the previous response's
`next_cursor`. `limit` accepts 1 to 100 and defaults to 100; a higher value is
clamped to 100 and a non-integer is a `400`. Single objects carry their own
`object` and `id`. Every response carries a `Request-Id`; quote it in support.

Writes that mint something (`POST /instances`, `POST /mcp/links`,
`POST /mcp/links/{id}/rotate`, `POST /connect/sessions`) accept an
`Idempotency-Key` header, so a retried call returns the original result instead
of minting a second credential.

Errors use a single shape on every endpoint. See [Errors](/v1-guides/errors).
