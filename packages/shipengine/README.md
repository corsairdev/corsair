# ShipEngine for Corsair

> ShipEngine was rebranded as ShipStation API in February 2025. The official provider documentation says ShipEngine customers do not need to change existing integrations and that ShipEngine endpoints remain unchanged. The package and Corsair slug stay `shipengine`; this plugin targets the former ShipEngine API contract, now documented under the ShipStation API brand.

This package exposes **92 documented ShipEngine REST operations** from the provider's [official OpenAPI 3.0 definition](https://github.com/ShipEngine/shipengine-openapi/blob/master/openapi.json) (spec version `1.1.202604070904`). It uses strict Zod request and response schemas derived from that contract. The official [ShipEngine → ShipStation API notice](https://docs.shipstation.com/apis/shipengine/docs/getting-started/new-shipstation-api.md) confirms the rebrand and unchanged routes.

## Authentication and regions

Use a production or sandbox API key in the documented `API-Key` HTTP header (not a Bearer token). The default service base URL is `https://api.shipengine.com`; set `apiRegion: 'eu'` for the official EU host `https://api.eu.shipengine.com`. All calls use HTTPS. Obtain and protect keys in the provider dashboard; a production key can incur charges.

`shipengine({ apiRegion: 'eu' })` is optional; the default region is `us`. Credentials are resolved from Corsair's tenant key store, or an explicit server-side `key` option.

## Limits, pagination, retries, and costs

The official [usage and rate limits](https://docs.shipstation.com/apis/shipengine/docs/guides/rate-limits.md) document a default **200 requests/minute** production limit and **20 requests/minute** sandbox limit. A 429 response includes `Retry-After` seconds; Corsair's HTTP transport honors that header and retries rate-limited requests up to three times. Pagination is supported on the list endpoints that expose it: forward the documented `page`, `page_size` (or the endpoint-specific `pagesize`), `sort_dir`, and `sort_by` values. Per-endpoint defaults and bounds declared in OpenAPI are summarized in the operation table; no undocumented maximum is inferred.

The provider documents no per-request credit schedule for this API. **Buying labels is billable**: ShipStation wallet-carrier label costs are deducted from the account balance; connected merchant carrier accounts bill under their carrier terms. Return-label purchase, batch label processing, and `POST /v1/batches` with `process_labels.create_batch_and_process_labels` can also buy labels. Funding carrier or Shipsurance balances spends money, and carrier pickup scheduling may carry carrier fees. These operations are marked `destructive` in Corsair metadata. Rate quotes and address validation are read-only and do not purchase labels. Check current provider pricing and carrier terms before production use.

## Binary files and upload flows

`GET /v1/downloads/{dir}/{subdir}/{filename}` returns PDF, PNG, or ZPL bytes. Corsair's shared JSON transport decodes non-JSON responses as text, so this operation uses a plugin-local fetch path that preserves bytes, validates the media type, honors `Retry-After`, and returns `{ kind: 'binary', contentType, base64, byteLength }`. Downloads larger than **50 MiB** are rejected by a safety limit.

The documented account image upload is **JSON**, not multipart: `POST /v1/account/settings/images` accepts `image_data` as a Base64-encoded string and `image_content_type` as `image/png` or `image/jpeg`. There is no arbitrary binary upload route in the current official OpenAPI definition. Combined-label generation accepts label IDs and can return a URL or inline JSON-encoded label content.

## Webhook routes excluded

Issue #2406 excludes webhook receiving and management. The five documented management routes below are intentionally not registered. Tracking start/stop operations remain available, but this package does not receive provider callbacks.

| Excluded route | Operation | Reason |
|---|---|---|
| `GET /v1/environment/webhooks` | List Webhooks | Webhook management is excluded by issue #2406 scope. |
| `POST /v1/environment/webhooks` | Create a Webhook | Webhook management is excluded by issue #2406 scope. |
| `GET /v1/environment/webhooks/{webhook_id}` | Get Webhook By ID | Webhook management is excluded by issue #2406 scope. |
| `PUT /v1/environment/webhooks/{webhook_id}` | Update a Webhook | Webhook management is excluded by issue #2406 scope. |
| `DELETE /v1/environment/webhooks/{webhook_id}` | Delete Webhook By ID | Webhook management is excluded by issue #2406 scope. |

## Live test

The default test suite uses mocked transport. To run the read-only live carrier-list smoke test, set `SHIPENGINE_API_KEY` (a sandbox key is recommended) and run `pnpm --dir packages/shipengine test:live`. The live test skips with a warning when no key is set.
