# @corsair-dev/zohobooks

Zoho Books API v3 integration for Corsair. The package implements 884 of the 885 REST operations documented across all 45 resource documents in Zoho's official OpenAPI bundle. Every included operation has Zod input/output validation based on its operation contract.

## Installation and authentication

Install with pnpm add @corsair-dev/zohobooks. Zoho Books uses OAuth 2.0. The plugin requests all 81 distinct OAuth scopes referenced by the included operation contracts, with offline consent so Corsair can refresh access tokens. This is a broad grant covering the catalog; Zoho administrators may constrain the granted scopes. API calls send Authorization: Zoho-oauthtoken <access_token>.

Set region to the data center where the organization is hosted. Supported values are us (default), eu, in, au, jp, ca, sa, and ae. China is not currently supported: Zoho's first-party Finance API-domain announcement documents the China Books API at `www.zohoapis.com.cn/books/v3`, but the Books OAuth guide's China multi-DC entry lists a Billing API base URI, not a Books Accounts OAuth URL. The Books guide and official Books OpenAPI bundle do not identify a China Accounts OAuth host. This plugin therefore does not infer or use `accounts.zoho.com.cn`; support can be added when Zoho documents the Books-specific OAuth host. Each Corsair plugin instance uses one supported region; configure the Zoho OAuth client for that data center, or use shared client credentials if you enabled Zoho multi-DC support.

## Request shape

Operations accept documented pathParams, query, headers, and body groups using Zoho's parameter and field names. Path IDs are URL-encoded. Most organization-scoped calls require query.organization_id; use organizations.listOrganizations to discover the ID. Operations that define {organization_id} in the route take it through pathParams. Organization list/create and user organization lookup routes are unscoped.

Pass page and per_page to paginated operations. The plugin makes one request and does not automatically traverse pages; Zoho's general pagination page documents 200 records by default, while operation-specific parameter defaults in the OpenAPI contract may differ. The plugin forwards caller-provided pagination values and does not apply a default.

Zoho's OpenAPI documents region availability annotations on some fields. These fields are retained in the operation contract, but the plugin does not enforce edition/region-specific field availability locally; Zoho may reject a field that is unavailable for the connected organization.

The three multipart upload routes accept binary file values as { filename, contentType, base64 }. Binary download results use { kind: binary, contentType, base64, byteLength }. The plugin rejects binary responses larger than 10 MiB.

## Limits and errors

Zoho documents 100 API calls per minute per organization, along with plan-specific daily request quotas and concurrent-call limits. Recoverable HTTP 429 responses are retried once by the plugin error handler and honor Retry-After; the documented daily-quota code 45 is not retried. Failed writes are not retried on server or network errors. Propagated ApiErrors preserve HTTP and retry metadata but redact request/response payloads that may contain customer or financial data.

## Scope and exclusions

The official v3 OpenAPI bundle documents 885 REST operations across 45 resource documents; 884 are implemented. The all_tag_options route is excluded because its path has a numeric regex segment but the contract declares tag_id only as a query parameter and has no path parameter for the segment. Resolving that mismatch would require guessing the route. OAuth authorization, refresh, and revoke are handled by Corsair rather than exposed as Books resource endpoints. Webhooks are out of scope and no handlers are registered.
