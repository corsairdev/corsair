# @corsair-dev/twitter

X (Twitter) plugin for Corsair: the full X API v2 on api.x.com (posts, users, DMs, Chat, lists, Spaces, communities, trends, media, usage, compliance, webhooks) with OAuth 2.0 PKCE or app-only Bearer auth.

## Install

```bash
pnpm add @corsair-dev/twitter
```

## Connect

Two ways in, set with `authType`:

- **`oauth_2` (default): act as an X user.** OAuth 2.0 Authorization Code with PKCE (S256). Sign-in goes to `https://x.com/i/oauth2/authorize`, tokens come from `https://api.x.com/2/oauth2/token` with the client ID and secret as HTTP Basic (a confidential client). The default scopes are `X_DEFAULT_SCOPES` (posts, users, follows, likes, lists, blocks, mutes, bookmarks, Spaces, DMs, media upload, `offline.access`). Broadcasts, calls, the developer account and the media library need `X_EXTRA_SCOPES` too: `twitter({ scopes: [...X_DEFAULT_SCOPES, ...X_EXTRA_SCOPES] })`, with those scopes enabled on the X app.
- **`api_key`: the app's Bearer token (app-only auth).** For the routes X only takes app-only (compliance jobs, `usage.get`, filtered-stream rules and links, full-archive counts, Account Activity subscription lists) and for public reads. It can't act as a user.

Each operation's description says which one it needs, and the plugin reports a token of the wrong kind before it calls X.

Access tokens last 2 hours. X rotates the refresh token on every refresh and the old one stops working at once; the key builder refreshes through core's `getOAuthAccessToken`, which stores the new access token, expiry and refresh token together.

## Pricing (pay-per-use)

X bills each call against the developer account's credits:

| Call | Price |
| --- | --- |
| Post (`posts.create`, `tweets.create`, replies, reposts) | $0.015 |
| Post that contains a URL | $0.20 |
| Direct Message sent | $0.015 |
| Post read (per post returned) | $0.005 |
| User read (per user returned) | $0.010 |
| DM event read (per event returned) | $0.010 |

Keep `max_results` low on searches and timelines. `usage.credits` shows the balance.

Following, liking and quote-posting were removed from the self-serve tiers on 2026-04-20: `users.following.follow`, `users.likes.like` and a post with `quote_tweet_id` can answer 403 on a pay-per-use app.

Posts, DMs, Chat messages, reposts, going live, calls and every delete are `destructive`, so the permission guard asks before they run.

## Left out

The streaming routes hold one HTTP connection open and send newline-delimited JSON for as long as it lasts, which a request-response operation can't carry: `GET /2/tweets/search/stream` (filtered stream), `/2/tweets/sample/stream`, `/2/tweets/sample10/stream`, the firehoses (`/2/tweets/firehose/stream` and its `lang/en|ja|ko|pt` variants, `/2/likes/firehose/stream`, `/2/likes/sample10/stream`), the compliance and label streams (`/2/tweets/compliance/stream`, `/2/users/compliance/stream`, `/2/likes/compliance/stream`, `/2/tweets/label/stream`) and `/2/activity/stream`. Their rules, links and connections are included (`posts.streamRules.*`, `posts.streamLinks.*`, `connections.*`). `GET /2/openapi.json` (the spec itself) is left out too.

## Regenerating

The operations come from X's OpenAPI spec (https://api.x.com/2/openapi.json, 273 operations, fetched 2026-11-25). `twitter-manifest.json`, `endpoints/operation-types.ts`, `endpoints/catalog.ts` and `plugin-docs.yaml` are generated; `endpoints/tweets.ts` (the two original endpoints, kept for existing callers) and the rest are hand-written.
